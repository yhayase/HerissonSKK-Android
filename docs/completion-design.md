# 見出し語補完・動的補完の設計契約

画面キーボードの候補予測は、本書の見出し語補完・動的補完とは別の機能です。前方一致に完全一致も含め、読みではなく変換候補を使用順に表示する仕様は[入力 UI 設計](input-ui-design.md)を参照します。本書の補完設定を予測の設定として流用しません。

K14、K15、F11、S07 の契約です。根拠は
`docs/requirements.md`、`docs/compatibility.md` と、DDSKK 固定参照版
`e8bf68b27021c29781dbfa6a8ef7b770565bdb5b` の `skk-comp.el`、
`skk-dcomp.el`、`skk-vars.el` です。GPL の実装や試験データは複製せず、観察した
操作契約から本アプリ向けの境界を定めます。

## 確認できた互換動作

DDSKK の通常補完は読み入力中の TAB で始まり、現在の読みより長い見出し語を前方一致
で探します。同じ見出し語そのものは補完結果にしません。続けて補完すると次候補へ進み、
既定では末尾で停止します。参照版には `.` で次候補、`,` で前候補という文字キーもあり、
Shift+TAB による前候補も既定で有効です。

DDSKK の動的補完は既定で無効です。有効時は送りなしの読みを個人辞書から検索し、入力
済み部分と補完部分を分けて表示します。TAB で補完部分を読みへ取り込みます。受諾前に
SPC を押すと補完部分を捨て、元の読みだけを変換します。通常文字、確定、カタカナ化も
未受諾部分を入力済みとは扱いません。送りあり変換では動的補完しません。参照版の
個人辞書内の順序は学習状態に依存します。

参照版は補完元を Lisp で差し替え、履歴、外部辞書、辞書サーバーなどへ拡張できます。
本アプリは任意 Lisp とネットワーク補完を対象にせず、公開済みのローカル辞書
スナップショットだけを検索します。

## 本アプリのキーと表示

通常補完は TAB で最初または次の候補へ進み、Shift+TAB で前へ戻します。補完巡回中は `.` でも次へ、`,` でも前へ移るようにしました。末尾と先頭では
循環せず、現在値を保って短い案内を表示します。巡回前・終了後は通常の句読点入力です。
明示的なキー設定がある場合はそれを優先し、補完開始・前候補・動的受諾の再割当は維持します。

動的補完の受諾は Right とします。通常補完の TAB と分けるという S07 の要求を満たし、
読みカーソルが末尾にあり、動的補完が表示中の場合だけ Right を受諾として扱います。
動的補完がなければ Right は従来どおりカーソル移動です。動的補完は初期状態で無効とし、
設定画面にオン／オフを提供します。新しい入力セッションから適用します。

入力済みの読みを `に`、提案を `にほん` とすると、コアの読みと入力先 composition は
`に` のままです。候補表示領域に入力済み部分 `に` と未受諾部分 `ほん` を別属性で表示
します。未受諾部分を `setComposingText`、確定文字、登録本文、学習要求へ含めません。
色だけに依存せず、「補完候補」などのラベルも付けます。

## 通常補完の状態遷移

TAB 時点の読みを原文、同じ辞書スナップショットから得た結果列を巡回対象として固定
します。最初の TAB は先頭結果を読みへ取り込みます。この取り込みは動的補完と違って
受諾済みであり、続く SPC は補完後の読みを変換します。反復 TAB・Shift+TAB と巡回中の `.`・`,` は固定した
列だけを移動するため、途中の学習や辞書再読込で候補が入れ替わりません。

候補が一件もない場合、読み、カーソル、ローマ字保留、入力先を変更しません。補完巡回中
の C-g または Escape は原文と元のカーソルへ戻して巡回を終了します。通常文字、SPC、
Enter、BS、モード切替、カーソル移動は現在表示中の補完を読みとして確定してから、元の
操作を一度だけ処理します。新しい編集後は旧結果列を再利用しません。

通常補完と動的補完は、読みカーソルが末尾にある時だけ開始します。途中カーソルで TAB
を押しても読みを変えず案内し、動的提案は表示しません。途中編集へ安全な補完範囲を定義
するまでは、既存の前後文字を重複・消失させないことを優先します。

## 動的補完の状態遷移

動的補完が有効なら、送りなしの安定した読みを編集するたびに先頭結果を提案します。
Right は提案全体を読みへ取り込み、カーソルを末尾へ移し、その打鍵では次の提案を出し
ません。次の実入力から再計算します。SPC は提案を捨て、元の読みで通常変換します。
たとえば `Ni` で読みが `に`、提案が `にほん` の時、SPC の検索キーは `に` です。

通常文字は提案を捨てて元の読みへ一度だけ入力し、その結果から新しい提案を計算します。
BS も元の読みを一文字戻して再計算します。Left、Home、外部カーソル移動は提案を捨て、
従来のカーソル移動を行います。Enter、C-j、かな・カタカナ・半角切替、C-g、Escape は
提案を捨てて元の読みだけへ既存の操作を適用します。セッション終了、入力先切替、接続
失敗でも提案を破棄し、遅い処理から復元しません。

動的提案がある状態で TAB を押した場合は提案の受諾に使いません。元の読みを原文として
通常補完を開始します。これにより TAB と Right の意味が混ざりません。

## 検索対象、順序、重複

通常補完の検索範囲 `ALL` は、現在公開済みの一つの辞書スナップショットに対し、次の順で
行います。

1. 個人辞書
2. 有効な取り込み済みシステム辞書の設定順
3. アプリ同梱辞書

各辞書内はUnicodeコードポイント順です。SQLiteの前方一致索引から必要な範囲だけを読み、全見出しをメモリーに展開して並べ替えません。同じ見出しは最初の辞書だけを残し、注釈や候補
本文は補完順に影響させません。候補抑止後に表示可能な候補が一件もないシステム見出しは
補完結果にしません。無効辞書と取り外した辞書は検索しません。

動的補完の検索範囲 `PERSONAL_ONLY` は DDSKK の既定動作に合わせ、同じスナップショット
の個人辞書だけを使います。システム辞書と同梱辞書から未受諾提案を出しません。通常補完
と動的補完は同じ辞書ポートを使いますが、呼出側が範囲を明示します。

通常読みは Unicode の完全一致で前方比較し、入力済みの見出しより長い結果だけを返し
ます。ひらがな・カタカナの変換や大文字小文字の同一視を検索層で暗黙に行いません。
カタカナ入力モードは既存の読み正規化でひらがなの辞書キーを検索し、表示・受諾後の
読みを入力モードに合わせます。

通常読みと動的補完では、末尾が ASCII 小文字の送りあり辞書キーを結果から除きます。
たとえば prefix `か` に対する `かき` は結果にできますが、変換用キー `かk` は結果に
しません。abbrev は ASCII 識別子末尾の小文字を送り記号と解釈せず、元の見出しを保ちます。

abbrev では入力した ASCII の大小文字を保ったまま前方一致検索します。非 ASCII を途中に
含む見出しへ勝手に切り替えません。空の読みから履歴を補完する DDSKK 機能は初期実装の
対象外で、空読みの TAB は無変更です。

## 送り、ローマ字保留、数値読み

送り境界、送り子音、送り仮名のいずれかがある時は通常補完も動的補完も行いません。
DDSKK と同じく初期実装は送りなし見出しだけを対象にします。補完済み読みから新たに送り
入力へ進む通常操作は妨げません。

ローマ字保留が空の安定した読みだけを検索します。末尾の `n` のように既存ローマ字規則
が単独で終端確定できる場合、手動 TAB はまず既存規則で `ん` に確定してから検索します。
終端確定前の読み、保留、カーソルをスナップショットとして残し、補完結果がない場合と
補完検索が失敗した場合は全てを TAB 前へ戻します。それ以外の不完全な保留では TAB は
入力を変えず、動的補完も表示しません。動的補完のためだけに保留文字を確定しません。

数値を含む読みも文字列として前方一致できますが、補完検索では数値正規化や `#0` などの
候補本文展開を行いません。補完後に SPC を押した通常変換で K16 の数値正規化を適用します。

## 登録、保護入力、学習との関係

再帰登録中は最も内側の読みへ同じ補完規則を適用します。通常補完で受諾した読み、または
Right で受諾した動的補完だけが内側の変換キーになります。未受諾提案は親の登録本文、
カーソル、入力先 composition に入りません。登録保存待ちと候補削除確認・保存待ちでは
補完を開始せず、その状態のキー規則を優先します。

パスワード欄と `TYPE_NULL` はコアを迂回するため、補完検索、提案表示、受諾を行いません。
通常欄の「個人データを保存しない」指定は書込だけを禁止するため、読み取り専用の補完は
利用できます。補完しただけでは候補学習、登録、履歴保存を発行しません。受諾後の変換・
確定は従来の学習方針に従います。読みや提案を診断、例外、一般ログへ含めません。

## コアと辞書の最小境界

辞書ポートは次の形です。

```kotlin
data class CompletionQuery(
    val prefix: String,
    val abbrev: Boolean = false,
    val limit: Int = 64,
    val scope: CompletionScope = CompletionScope.ALL,
)

enum class CompletionScope { ALL, PERSONAL_ONLY }

fun interface BasicSkkDictionary {
    fun lookup(query: DictionaryQuery): List<DictionaryCandidate>
    fun complete(query: CompletionQuery): List<String> = emptyList()
}

data class CompletionConfig(
    val manualEnabled: Boolean = true,
    val dynamicEnabled: Boolean = false,
)
```

コアには `CompleteForward`、`CompleteBackward`、`AcceptDynamicCompletion` の独立アクション
を追加します。表示モデルは入力済み読みと未受諾 suffix を別フィールドで返します。
`BasicSkkEngine` は `CompletionConfig` を任意引数で受け、設定がない既存呼出しでも通常入力
を変えません。Android は新しい入力セッションの開始時に設定とキー割り当てを固定します。
設定変更は次のセッションから適用し、進行中の読みの意味を変えません。

辞書ポートの呼出し形式は同期ですが、未キャッシュ時は読込要求を返し、接続層がワーカーで読み込んで同じ操作を再実行します。入力スレッドでディスク完了を待ちません。複合辞書がソース優先順・抑止・重複を解決し、一回の巡回列・動的提案は一貫した検索結果から作ります。部分結果を公開せず、既存巡回列は維持し、新規検索で新しい世代を利用します。詳細は [ストレージとキャッシュ](dictionary-storage-cache-design.md) を参照します。

## 資源上限と失敗境界

初期上限は、入力 prefix 1,024 UTF-16 文字、返却結果 64 件、結果一件 4,096 文字、結果
本文合計 65,536 文字、一検索の作業量 50,000 単位とします。前方一致見出し一件と、候補
抑止の可視性判定で実際に調べる候補一件をそれぞれ一単位として複合辞書全体で数え、
重複除去前の検査数も作業量へ含めます。実装は辞書ごとの前方一致範囲を索引で求め、全件
走査を通常経路にしません。これらは現在の入力・表示上限内で候補巡回を十分に行いつつ、
巨大な取り込み辞書による一打鍵の処理量を制限する初期値です。

64 件は正常な返却上限です。優先順で重複を除いた結果が 64 件に達したら検索を終了し、
65 件目が存在しても失敗にしません。入力長、結果一件長、結果本文合計、検索作業量の
上限超過は部分結果を返さず、検索全体を失敗にします。

不正 Unicode、上限超過、辞書利用不能、作業量超過では結果全体を失敗とします。通常補完
は読みを変えず一般化した案内を表示し、動的補完は提案を表示しません。直前の別 prefix の
結果を流用しません。例外に prefix や見出しを含めません。実機で 1,000 回検索の時間と
メモリーを計測し、上限を変更する場合は試験値と低性能端末への影響を記録します。

## 受入試験表

| 区分 | 操作 | 期待結果 |
|---|---|---|
| K14 基本 | 個人辞書に `にほん`、読み `に` で TAB | 読みが `にほん` になり、入力先へ確定しません |
| K14 なし | 一致なしで TAB | 読み、カーソル、保留、入力先が不変です |
| 巡回 | `にほん`、`にほんご` が候補で TAB、TAB、Shift+TAB | 固定順で前進・後退し、端で循環しません |
| 優先順 | 同じ見出しが個人、複数システムに存在 | 個人、設定順、同梱の順で重複を一件にします |
| 抑止 | システム見出しの全候補を抑止 | その見出しを補完結果に出しません |
| 取消 | 巡回中に C-g または Escape | TAB 前の読みとカーソルへ戻ります |
| K15 表示 | 動的補完を有効にし `Ni` | 入力済み `に` と未受諾部分 `ほん` を分離表示します |
| K15 未受諾 | 提案中に SPC | `に` だけを検索し、`にほん` を確定・学習しません |
| K15 受諾 | 提案中に Right | 読みが `にほん` になり、その打鍵では変換・確定しません |
| 操作分離 | 提案中に TAB | Right 受諾ではなく、元の `に` から通常補完を開始します |
| 通常編集 | 提案中に文字、BS、Left、Enter、モード切替 | 未受諾部分を捨て、元の読みに既存操作を一度だけ適用します |
| 送り | 送り境界または送り仮名のある読みで TAB・動的補完 | 補完せず既存の送り入力を保持します |
| abbrev | `API` prefix と大小文字違いの見出し | 大小文字を保つ前方一致だけを返します |
| ローマ字 | 終端可能な `n` と、それ以外の不完全保留で TAB | `n` だけ既存規則で確定し、不完全保留は無変更です |
| カーソル | 読み途中へ移動して TAB・動的補完 | 読みを変更せず提案を出しません |
| 数値 | `だい1` を補完後に SPC | 補完は文字列検索、変換時だけ K16 を適用します |
| 再帰登録 | 子読みで通常補完・動的補完の未受諾・受諾 | 親本文と入力先を変えず、受諾済み読みだけ子変換に使います |
| 保護入力 | password、`TYPE_NULL` | 辞書を呼ばず、表示せず、キーを入力先へ渡します |
| 学習禁止 | 通常欄の no-personalized-learning | 補完は使えますが、補完だけでは書込を発行しません |
| スナップショット | 巡回中に辞書公開・設定を変更 | 巡回は固定し、新辞書は次の検索、設定は次セッションから使います |
| 件数上限 | 65 件以上の一致 | 優先順の先頭 64 件を正常に返し、65 件目以降を調べ続けません |
| 資源上限 | 65,536 文字・50,000 作業単位の境界と超過 | 多数見出しと一見出しの多数抑止候補を検査し、超過は部分表示せず元の読みを保持します |
| 接続失敗 | 表示更新を入力先が拒否 | 再送・確定せずセッションを失敗化し、未受諾部分を残しません |
