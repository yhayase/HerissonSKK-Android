# Emacs 編集キーの設計

アプリ別の適用範囲と移行は[アプリ別 Emacs 設定](app-emacs-design.md)を参照します。

## 範囲と現状

F05・F13・S02 の内部編集と条件付きの入力先編集を設計します。要件の正本は [requirements.md](requirements.md)、既存キーは [compatibility.md](compatibility.md)、試験との対応は [試験対応表](test-coverage.md) を参照します。Emacs 全体、kill ring、マーク設定、矩形選択、表示行移動は対象外です。

現行の `EditableBuffer` は UTF-16 オフセットと ICU4J 77.1 / Unicode 16 の拡張書記素クラスタを使い、左右・論理行端・前後削除を提供します。`BasicSkkEngine` は見出し語・登録本文の編集を所有し、送り境界を更新します。`EditorSession` は固定した `InputConnection` と世代を所有しますが、期待選択通知の照合は外部文書の版を保証しません。`HardwareKeyMapper` は AltGr の文字生成を Ctrl コマンドより先に判別します。これらを拡張し、外部文書をコアの未確定バッファへ取り込まない構成にします。

## 設定と配送

初期値はオフ、Meta の初期割り当ては Alt とします。既存アプリのショートカットを変更しないためです。Escape 前置 Meta は初期対象外です。設定オフでも C-j・C-g・C-q と、内部編集の矢印・Home・End・BS・Delete は残します。Emacs 専用キーはオフなら元イベントを入力先へ渡します。

配送は次の順です。

1. パスワード欄と `TYPE_NULL` は全処理を迂回します。設定オンでも C-j を含めて渡し、周辺文字を取得しません。
2. OS 配列による文字生成・AltGr・デッドキーを判定します。右 Alt で文字を生成する場合、および Alt で非 Alt 時と異なる文字を生成する場合は Meta にしません。Ctrl+Alt による文字生成も同様です。判別不能な修飾キーを Meta と推測しません。
3. 状態固有の SKK コマンド、候補選択、確認・保存待ちの制約を適用します。
4. オンなら内部編集対象、内部対象がなければ入力先編集へ送ります。
5. 未割り当てのキーは渡します。

Meta は文字生成ではない Alt+b/f にだけ適用します。Super/Command に相当する Android の Meta 修飾、Ctrl+Alt の非文字ショートカット、Shift 付きの編集拡張は初期割り当てに含めません。キー割り当て変更では同じ状態の SKK コマンドとの衝突を適用前に拒否します。

オンで認識した編集コマンドは、端での無変化・非対応・失敗も含めて消費します。別のアプリ操作として再配送しません。キー押下で決まった配送先をリピートとキーアップにも保持し、キーアップだけを渡しません。内部対象の消失やフォーカス変更後のリピートは新しい入力欄へ編集を送らず、キーを離すまで消費します。

## 状態別の対象

| 状態 | 編集対象と競合処理 |
| --- | --- |
| 未確定なしの「あ」・直接入力・他の通常モード | 入力先編集ポートです。かなモードであることを内部対象の存在と混同しません |
| 見出し語・abbrev | 読みバッファです。入力先の確定済み文字へ越境しません |
| 登録本文、内側の未確定なし | 現在の登録フレームの本文です。親・入力先へ越境しません |
| 登録内に読み・候補あり | 最内側の状態を優先します |
| 候補・候補一覧 | C-n は次候補、C-p は前候補です。物理キーのインライン変換では C-h / BS は候補を確定して末尾の一クラスタを削除します。候補メニューでは従来の戻り操作を維持します。他の編集キーは消費して候補を保持します。候補を暗黙確定して入力先を編集しません |
| 削除確認・登録保存待ち | 既存の確認・取消規則を優先し、編集キーは消費して保持します |
| 未受諾の動的補完 | 編集により提案を破棄し、元の読みだけを編集します。C-f は Right による受諾と区別します |
| 通常補完中 | 編集前に現在受諾している読みを確定し、補完セッションを終了して内部編集します。未受諾の提案文字は挿入しません |

読み中の未消化ローマ字では C-h は BS と同じく未消化列を先に削除します。他の移動・削除は既存の終端規則で `n` → `ん`、`ky` → `ky` のように同じ内部対象へ解決してから操作します。通常状態の未消化列だけがある場合は、移動・C-d・C-k の最初の一打でその列を既存規則どおり確定し、そこで消費します。同じ一打で確定文字や隣接する入力先文字を編集しません。登録内なら確定先は登録本文です。送り境界をまたぐ削除では境界を残った文字位置へ移し、送りが空になった場合も既存のコア設計に従って検索条件を再計算します。

## 文字・行・単語と選択の意味

オフセットは全層で UTF-16 とし、文字移動・削除は拡張書記素クラスタ単位にします。不正サロゲートやクラスタ途中の選択を切り上げて削除せず拒否します。内部対象には現在選択範囲がありません。将来選択を加える場合と外部ポートでは、両端がクラスタ境界の選択だけを受理します。

| 操作 | 採用する意味 |
| --- | --- |
| C-b / C-f | 一クラスタ前／後へ移動します。選択があれば前方向は小さい端、後方向は大きい端へ畳み、この一打でさらに移動しません |
| C-a / C-e | 論理行の先頭／改行直前へ移動します。選択があれば選択の active end（selectionEnd）を起点にします |
| C-p / C-n | 前／次の論理行の同じクラスタ列へ移動します。選択は active end を起点に解消します。候補中は上記の候補操作が優先します |
| C-h / C-d | 選択があればその範囲だけ、なければ前／後の一クラスタを削除します。内部 C-h の未消化列と空読みの取消は既存 BS 規則を保ちます |
| C-k | 選択があればその範囲だけを削除します。なければ現在位置から論理行末までを削除します。行末にいる場合だけ、直後の改行一つを削除します。文書末尾では本文とクリップボードを保持し、End of buffer を表示します |
| M-b / M-f | 下記の単語定義で前の語頭／次の語末へ移動します。選択があれば C-b/f と同じ方向端へ畳むだけです |

改行は CRLF を一つ、単独 CR と LF をそれぞれ一つとして扱います。CR と LF の間には停止しません。U+2028・U+2029 も論理行区切りにします。末尾改行の後には空行があります。折り返しは行に数えません。タブ・全角文字・絵文字も一クラスタ一列です。ピクセル幅やタブ幅を使いません。

連続する縦移動の最初に目標列を記録し、短い行では行末に止めても目標列を保持します。最初／最後の行でさらに移動する場合は位置を変えません。縦移動以外のコマンド、挿入・削除、外部選択通知、対象や世代の変更で目標列を破棄します。単一行で C-p/n は無変化です。

単語は ICU4J の Unicode プロパティで定義する独自の決定的な区切りとします。基底文字が Letter または Number、もしくは `_` のクラスタが連続する範囲を一語とし、付随する結合文字はクラスタと一緒に扱います。単独の結合文字、空白、句読点、ハイフン、絵文字は区切りです。漢字・ひらがな・カタカナ・英数字の連続も一語とし、形態素解析や言語辞書には依存しません。M-f は区切りを飛ばして次の語末へ、語中ならその語末へ移動します。M-b は逆方向に区切りを飛ばして直前の語頭へ、語中ならその語頭へ移動します。語がなければ対象の端です。例として `日本語 abc_def-12` は `日本語`、`abc_def`、`12` の三語です。

入力先に対するC-kの削除文字はAndroidのクリップボードへ保存します。クリップボードへの保存が失敗した場合は削除しません。連続 C-k では削除文字を順に連結します。C-k 以外の操作、外部からのカーソル変更、入力先や IME の切替、クリップボードの置換で連続を終了します。自分の削除に伴う選択通知とマウスポインターの移動は連続を終了しません。kill ring、学習辞書、ログへは送りません。内部では文字列・カーソル・送り境界を一つの状態更新で反映します。

## コアと Android のポート

コアには Android 非依存の編集コマンド、読み取り専用スナップショット、編集計画を置きます。計画は対象 ID・版・元の選択・移動先または削除区間を持ち、範囲は半開区間です。バッファの変更ごとに版を増やし、対象と版が一致したときだけ適用します。内部編集は `EditableBuffer` を拡張し、`BasicSkkEngine` が送り境界・残余・登録フレームとの整合性を保ちます。

Android 側の `EditorEditPort` は取得・検証・適用を所有します。結果は `Applied`、`NoChange`、`Unsupported`、`Stale`、`FailedOrUnknown` を区別し、最後の三つを成功表示しません。コアが外部の絶対位置を推測したり、`InputConnection` を直接呼んだりしません。読み用の内部カーソル同期と入力先編集の選択要求は別の種別として追跡します。

### 標準 InputConnection の限界と採用範囲

API 26〜35 の標準 InputConnection では、取得した本文と同じ版への原子的な削除を保証できません。本設計は取得時の対象を確認し、検知した古い状態への要求を拒否します。取得後に入力先自身が変更する競合は残ります。この制約を明示し、検証済みの入力先で条件付きの削除を提供します。F13 の入力先削除を将来の独自プロトコルだけに限定しません。

初期の受入試験は `test-editor` の通常の EditText と偽接続で行い、実際の試験に合格するまでは対応済みと記載しません。パッケージ名の許可リストには依存せず、計画に基づく編集は毎回の取得結果と境界の検証によって対応可否を決めます。

外部編集では、取得した本文の境界が十分な場合は計画を照合して適用します。取得窓の端にかかって計画できない左右・上下・行端移動と前後削除では、変更をまだ送っていない場合に限り、標準移動キー・Backspace・Delete を一度送ります。ページ・文書端移動も標準キーを使います。この経路の文字・行境界は入力先の標準動作に依存し、論理行や ICU の分節規則との一致は保証しません。内部編集の規則は変わりません。

標準キーによる移動と前後削除は最大 64 件の待機列から順に送ります。前後削除も同じ操作列に残し、選択通知が遅れても次のキーを古い絶対位置の計画へ変換しません。C-m は物理 Enter と同じ SKK の確定処理を通し、入力先へ渡す場合は修飾なしの Enter キーを送ります。受付は適用完了とは区別します。[sendKeyEvent の仕様](https://developer.android.com/reference/android/view/inputmethod/InputConnection#sendKeyEvent(android.view.KeyEvent)) では配送が非同期で、配送前にフォーカスが変わる可能性もあります。送信前の世代確認は送信済みイベントの配送先を保証しません。後続の本文取得・破壊的編集との原子的な順序保証もありません。変更要求後に不一致を検出しても、同じ変更の再送や別 API による代替削除は行いません。

M-</> では、標準キーの送信前に `clearMetaKeyStates` で Shift のラッチを解除し、文字 `<` / `>` 用の Shift が範囲選択へ残ることを防ぎます。選択通知から自分の操作を推測して後から範囲を解除する処理は行いません。入力先による同 API の対応状況には依存します。

取得できない入力欄でも C-m は同じ Enter 経路を使います。検索や送信を含め、入力先が Enter に定義した動作に従います。送信受付を本文反映の保証にはしません。以下の取得・事後確認は、本文を確認して計画する経路に適用します。

- 選択なしの C-h/d/k は、確認したクラスタまたは行末までの半開区間から前後の UTF-16 長を計算し、`deleteSurroundingText(before, after)` を一度だけ要求します。C-k の行末改行削除も CRLF 全体を取得できる場合だけです。
- 選択ありの C-h/d/k は、既存の選択範囲全体と両端境界を確認したうえで `commitText("", 1)` を一度だけ要求します。削除のために新しい選択を作りません。`setSelection` で削除範囲を作ってから `commitText` を行う二段操作は使いません。
- 削除で前後の文字が結合し、内部計画のカーソルが削除開始位置より後ろの新しいクラスタ境界へ移る場合は、外部では削除前に拒否します。削除後に追加のカーソル補正を推測して要求しません。

未対応・不明の場合はキーを消費し、「この入力欄ではこの編集操作を利用できません」と一度通知します。変更要求後の不一致と API の拒否は、その要求を終了します。同じ入力セッションの版が変わっていない場合だけ、既に待機している別の明示的なキーを新しく取得・照合して実行します。失敗した要求そのものは再送しません。版が変わった場合は待機列を破棄します。例外・タイムアウトでは、そのポートを停止します。試験欄での合格を他アプリの合格へ一般化しません。

周辺取得が二度一致しても、最後の取得と変更の間にアプリが編集できます。`beginBatchEdit` は通知・描画をまとめる仕組みであり文書ロックではありません。API 33 の `takeSnapshot` は IME から直接呼ぶ取得経路に使えません。API 34 の範囲置換も期待版の照合とは扱いません。[InputConnection の公式仕様](https://developer.android.com/reference/android/view/inputmethod/InputConnection) に基づく制約です。取得後の入力先独自変更を含めて誤削除が絶対にないとは約束しません。

標準ポートの移動にも同じ競合限界があります。フォーカス変更を検知した場合は旧要求を送信せず、作成時の接続だけを使用します。OS や入力先にまだ通知されていない変更を IME が完全に識別できるとは表記しません。コードポイント版の削除をクラスタ削除の代替にせず、拒否後の別 API による再試行や、元文字の再挿入による修復を行いません。

### スナップショット取得と不変条件

| API | 取得方針 |
| --- | --- |
| 26〜30 | `getExtractedText` を監視フラグなしで一回ずつ取得します。差分更新を合成しません。`partialStartOffset == -1` の応答だけを受理します |
| 31〜35 | `getSurroundingText` を優先します。初回の取得が利用できない場合は `getExtractedText` を試します。計画の再取得・事後確認では取得方式を変えません |

`ExtractedText` の `startOffset + selectionStart/End`、`SurroundingText` の `offset + selectionStart/End` が絶対選択位置です。後者の offset が -1 の場合は絶対位置不明として抽出方式を試し、それも取得不能なら、相対選択範囲が正しい二回の周辺応答を照合して標準操作へ委ねます。相対位置から絶対位置を推測しません。加算は広い整数で検証してから Int へ変換します。計画経路では、取得テキストに相対選択が両方含まれ、絶対選択が最後に確認したセッションの選択と一致することを必須とします。相対位置しか分からない標準操作経路は絶対選択を照合できず、実際の操作位置は入力先が所有します。同じ相対応答が二回返っても、入力先内部で既に古くなった状態を検出できる保証はありません。既知の絶対位置が最新の通知と一致しない場合も、妥当な本文・選択を同じ方式で二回照合した上で、対応する標準操作だけを入力先へ委ねます。通知の古い位置から変更範囲を作りません。逆向き選択の順序は保持します。[ExtractedText](https://developer.android.com/reference/android/view/inputmethod/ExtractedText) と [SurroundingText](https://developer.android.com/reference/android/view/inputmethod/SurroundingText) の公式仕様を参照します。

`partialStartOffset == -1` は差分でないことを示しますが、外部文書の全体取得を独自に保証する印としては使いません。要求より短い応答、空応答、取得窓の末尾を文書末尾と推測しません。`getTextBeforeCursor` と `getTextAfterCursor` と `getSelectedText` の別々の結果を連結して一つの版として扱いません。EditorInfo の初期周辺文字も操作時点の本文として使いません。

標準ポートの分節開始位置は、既知の文書開始（offset 0）、または取得窓内で完全に観測した改行の直後にします。窓端の CRLF の片側は境界証拠にしません。任意に切られた窓の先頭で ICU を開始すると、長い Regional Indicator 列などの境界を誤判定し得るためです。

操作に必要な境界だけを確認します。C-a は既知の行頭へ移動できれば、後続行末の取得を要求しません。C-b/f も現在位置と移動先のクラスタ境界を窓内で確認できれば後続行全体は不要です。C-eは移動先となる改行開始を実際に取得できる場合に限ります。C-kは改行開始を取得できる場合に加え、カーソル後方の追加取得と、offset=0の非部分ExtractedTextが同じ末尾・選択位置を示す場合に最終行末までを削除できます。単語移動や縦移動も、走査が不明な窓末尾へ達した場合は拒否します。先頭側の文脈が不足したまま前行へ越境しません。

取得窓末尾は文書末尾と推測しないため、C-a 以外で選択端・移動先・削除終端が不明な窓末尾と一致する編集計画は拒否します。C-a は削除を伴わず、既知の行頭という移動先を独立して証明できる例外です。C-kは、上記の追加取得で文書末尾を確認できた場合だけ例外とします。完全なExtractedTextが取得できない入力欄、8192 UTF-16単位を超える抽出、後方の確認範囲を超える行では、推測して削除せず未対応とします。行端・上下・左右・前後削除は、上記の標準キー経路に委ねます。アプリが返した窓末尾を偽の行末にして変更しません。

計画に基づく移動・削除では各操作で次を検証します。

- 対象世代・固定した接続が現在も active で、保護入力ではなく、内部未確定・登録・未処理の選択要求がありません。
- 本文は上限内かつ正しい UTF-16 で、対象区間・選択両端・移動先のクラスタ境界を完全な文脈で確認できます。
- 同じ取得方法で再取得し、offset・本文・選択が一致します。途中に選択更新、入力開始／終了、再起動、接続再作成、キー入力による別操作があれば破棄します。同じ座標の通知でも編集中なら計画を無効にします。
- 送信直前にも世代と接続の状態を確認し、作成時の接続だけに、一度の移動または上記の削除要求を送ります。現在の接続を取り直して旧計画を適用しません。
- 戻り値 false、例外、応答不明なら消費して終了し、代替操作をしません。true でも適用完了の証拠とはせず、要求後の通知・再取得で選択と本文が期待結果に一致するか確認します。別の API への切替や同じ変更の再送はしません。不一致なら目標列を捨てます。同じ版なら後続の明示的な要求を取得し直し、版が変わっていれば待機列も破棄します。本文を修復しません。

期待選択通知のキューは版番号ではありません。古い通知・同じ座標への往復・アプリの本文変更をすべて識別できるとは扱いません。このため、上記確認に合格した削除も入力先自身の同時編集に対する原子的保証は持ちません。本文が予期せず変わった要求は成功扱いせず、同じ要求を再送しません。

### 将来の協調ポートで強化する条件

標準ポートの競合限界を解消する将来拡張として、入力先アプリが明示的に対応する場合に、文書インスタンス ID・単調増加する版・選択・必要区間とその境界証拠を返す協調ポートを検討します。削除要求には操作 ID、文書 ID、期待版、期待選択、削除区間を含めます。入力先が同じ実行区間で照合して削除し、競合なら一切変更しないことを契約にします。フォーカスと接続の有効性も入力先側で同時に確認します。結果再取得は操作 ID で重複を防ぎ、タイムアウト時の盲目的再送はしません。

パッケージ名の許可リストや一度成功したアプリを原子操作対応の証拠にはしません。標準の `InputConnection` にこの契約を付加したと仮定しません。協調プロトコルは別の実装・認証・試験が必要な拡張であり、本書で実装済みにはしません。

## 上限・プライバシー・失敗

周辺文字の要求は前後各 2,048 UTF-16 単位、選択を含む応答の受理上限は 8,192 単位とします。抽出要求にも 8,192 のヒントを指定します。ヒントが強制上限ではないため、返却長を見て超過応答を解析・複製せず拒否します。受信時の IPC メモリ割り当てまで IME が制限できるとは扱いません。上限を超える選択や行を分割取得して追跡しません。

操作は同時に一つ、セッション内の待機コマンドは FIFO で最大 64 個とします。待機中はコマンド種別だけを保持し、本文・選択・削除区間は保持しません。各コマンドは直前の成功または無変化の確認後に、新しい周辺文字から計画します。超過キーは消費しますが、受理済みの順序は保持します。独立した入力、外部選択変更、回復できない失敗、タイムアウト、フォーカス終了では待機列を破棄します。API の拒否・事後不一致でも同じ版が維持されている場合は、後続の別コマンドを新しく取得・照合します。ポートの正常完了通知は実行権の解放後に行い、次の要求を安全に受け付けます。計画に使う取得は変更前に二回、送信後確認は一回です。初回の周辺取得が利用できない場合に限り、抽出取得を追加で試します。アプリ応答を待つ処理を UI スレッドでループしません。ネイティブ移動直後の C-k は選択通知を最大 500 ms 待ち、その後に同じ版の状態から取得を始めます。通知待ちが終わっても座標が一致しなければ削除しません。取得開始後、500 ms を超えた計画は失効させ、遅延結果で適用しません。同期 API の呼び出し自体をこの時間で強制中断できるとは約束せず、専用の直列実行経路を一つに限定し、停止した呼び出しを避けるためのスレッド増殖をしません。

取得本文・選択文字は要求中のメモリだけに保持します。連続 C-k の削除文字は、連結のため同じ入力セッションのメモリに保持し、連続の終了・取消・セッション変更で参照を捨てます。ログ、クラッシュ添付、学習、永続キャッシュ、ネットワークへ出しません。明示的なC-kで削除する範囲だけをAndroidのクリップボードへ保存します。メモリの即時ゼロ化を JVM で保証するとは表記しません。ログは内容を含まない結果コードと処理時間だけにします。学習禁止の通常欄でも編集は可能ですが、本文の保存はしません。非対応通知はセッション内で抑制し、キーリピートで連打しません。

## Undo・Pasteとクリップボード

Emacs編集オンの通常入力先ではC-/をAndroidのUndo、C-yをPasteアクションへ対応させます。対象アプリが対応しなければ実行できません。内部の読み・登録本文や候補中から入力先を勝手に編集しません。クリップボード保存後にも入力セッションと期限を確認し、失効していれば削除しません。クリップボード保存と入力先の削除は原子的ではないため、削除が拒否された場合もコピーした文字がクリップボードに残る場合があります。

Paste・Undoの通知が完了コールバックより先に届いた場合は、発行中の操作に限って選択通知を保留し、同じ接続から取得した操作後の位置と照合します。一致する場合だけ次の受理済みコマンドへ進み、不一致・取得不能・範囲選択では待機列を破棄します。操作そのものを再送しません。無変化の操作には残留する通知待ちを作らず、操作後の別のカーソル移動は通常どおり古い編集を無効化します。この照合も入力先の並行操作に対して原子的ではありません。

Android 8ではClipboardManagerの初期化に呼出し元のLooperが必要なため、IME生成時にメインスレッドで取得します。実際のコピーは検証済みのCtrl+k要求から行い、コピー失敗時には削除しません。
