# Android SKK IME 機能要件・非機能要件・設定要件

作成日: 2026-09-16

## 本書の位置付け

物理キーボードを中心に日常利用できる Android SKK IME の製品要件をまとめます。実装済み機能の一覧ではありません。既存の合意は「確定」、今回整理した未合意の具体案は「提案」、判断が必要な事項は「未決」と明記します。必須は安定版までの対象であり、すべてを初期版に実装する意味ではありません。

本書は機能・品質・設定画面の要求を管理します。操作列と状態遷移の詳細は [互換性と受入仕様](compatibility.md)、時期は [ロードマップ](roadmap.md)、端末・アプリ別の試験は [検証計画](validation-plan.md)、実装状況は [フェーズ 1 の記録](phase1.md) を参照します。既存文書と異なる提案は、採用までは既存仕様を変更しません。

## 目的・対象範囲

- ローマ字による SKK 入力、変換、登録を物理キーボードだけで完結させます。
- 変換、辞書検索、学習はオフラインで利用できます。
- 郵便番号・人名などの追加辞書と、入力規則・キー・表示のカスタマイズに対応します。
- 見出し語内の編集と、入力先に対する任意の Emacs 編集キーを提供します。
- ソフトウェアキーボードは将来拡張です。物理キーボード使用時に文字キー画面が入力領域を占有しないようにします。
- DDSKK 17.2 リリース（`ddskk-17.2_Mena`、`e8bf68b27021c29781dbfa6a8ef7b770565bdb5b`）を互換性基準とします。Emacs 全体や任意の Emacs Lisp の実行は対象外です。

追加の DDSKK 機能（送りの厳密照合、ヒント、交ぜ書き等）は互換性仕様 R01〜R04 で分類します。未調査の機能を対応済みとは表示しません。

## 設定画面の要件

以下は設定画面の情報構成です。レイアウトの確定案ではありません。「確定」の設定も現時点で実装済みとは限りません。

### S01: 入力・キーボード表示

| 項目 | 選択内容・動作 | 初期値・状態 |
| --- | --- | --- |
| 入力開始モード | 新しい通常入力セッションはひらがなにします。パスワード欄と `TYPE_NULL` は直接入力に限定し、通常のモード切替より優先します | 確定。変更設定やアプリ別記憶は初期対象外です |
| 物理キーボード接続時の文字キー画面 | 隠せます。候補・注釈・モード表示は別に扱います | 非表示を初期値とする提案。文字キー画面の実装は将来です |
| 物理キーボード未接続時の文字キー画面 | 表示の可否と切断時の扱いを定義します | 将来・未決。切断だけで変換を確定する仕様にはしません |
| 物理キーボード配列 | OS で設定した配列を利用し、設定画面から OS 側の設定場所を案内します | 確定。IME 独自の US／JIS 再マッピングは初期対象外です |

### S02: キーバインド・Emacs 編集

パスワード欄と `TYPE_NULL` では通常の SKK・Emacs 編集処理を迂回します。候補・登録・学習を行わず、C-j も入力先へ渡します。この製品上の例外を通常キーより優先します。学習禁止要求だけの通常欄では変換・候補表示を許し、保存のみ抑止します。

Emacs 編集のオン／オフは必須です。オフでも SKK の C-j・C-g などは残します。Emacs 編集だけに使うキーは、オフなら入力先へ渡します。見出し語・登録内の編集機能自体はオフでも物理キーで利用できる必要があります。

| 項目 | 要求 | 初期値・状態 |
| --- | --- | --- |
| Emacs 編集キーを使う | 内部の見出し語・登録文字と、未確定がない場合の入力先編集を対象にします | 機能は確定。初期値オフを提案します |
| Meta の割り当て | `M-f`、`M-b` を操作できる割り当てを提供します | Alt を初期値とする提案。Escape 前置方式の採否は未決です |
| SKK コマンドのキー変更 | モード切替、変換、確定、取消、前候補、補完、登録、削除確認などを変更できます | 必須。標準キーは互換性仕様に従います |
| Emacs 編集キーの変更 | 標準の編集操作に別のキーを割り当てられます | 提案。候補選択キーは S05 で管理します |
| 競合表示・復旧 | 同じ状態で競合する割り当てを検出し、適用前に知らせます。標準設定へ戻せます | 必須。復旧は壊れたキー割り当てに依存しません |

対象とする標準 Emacs 編集キーは次のとおりです。前後の文字移動・削除は文字列を破壊しない単位で扱います。

| キー | 操作 | 内部バッファ／入力先で決める事項 |
| --- | --- | --- |
| C-a / C-e | 行頭／行末へ移動 | 論理行か表示行かは未決です |
| C-b / C-f | 前／次の文字へ移動 | 結合文字・絵文字も含めて試験します |
| C-p / C-n | 前／次の行へ移動 | 単一行・複数行、縦移動時の列保持を定義します |
| C-h / C-d | 前／次の文字を削除 | 選択範囲がある場合の扱いを定義します |
| C-k | 行末まで削除 | 行末位置での改行削除、削除文字の保持は未決です。C-y は現時点の必須対象に含めません |
| M-b / M-f | 前／次の単語へ移動 | 日本語・英数字・記号の単語境界を定義します |

**優先順位の提案:** 文字生成を判別したうえで、その状態の SKK コマンド・候補選択、内部バッファの編集、未確定がない場合の入力先編集、入力先への引き渡しの順とします。AltGr の文字生成を Meta と誤認しません。候補表示中の C-n／C-p、未消化ローマ字がある場合の移動、選択範囲に対する編集の詳細は、実装前に状態別キー表へ追記します。

内部バッファの編集で入力先の確定済み文字を変更しません。入力先編集は取得可能な文字列・選択範囲に制約され、全アプリでの同一動作は保証しません。編集対象を確認できない場合は推測で削除しません。その場合にキーを渡すか消費するかは、操作ごとに定義・検証します。アプリ別の有効化・除外設定は未決で、初期要件としては確定していません。

### S03: ローマ字テーブル・派生入力方式

| 項目 | 要求 | 初期値・状態 |
| --- | --- | --- |
| テーブル選択 | 標準とカスタムのローマ字規則を選べます | 標準を初期値とします。確定です |
| 規則のカスタマイズ | 入力列、出力文字列、必要な未消化文字の扱いを変更できます | 必須。編集 UI とファイル形式は未決です |
| 取り込み・書き出し | カスタム規則をファイルから導入し、保存できます | 提案。形式・版番号・文字コードを定義します |
| AZIK | ローマ字派生方式を利用できます | 対応要求は確定。同梱する版・出典・標準キーとの競合は未決です |
| 検証・復旧 | 不正な規則を適用せず理由を表示し、標準へ戻せます | 必須。重複規則と正当な接頭辞共有を区別します |
| 入力試行 | 保存前に入力列と変換結果を確認できます | 提案です |

AZIK などを単なるテーブル置換で実現できるとは仮定しません。SKK コマンドとの競合や状態遷移を含む受入例を方式ごとに用意します。ACT・かな入力・親指シフト・TUT-code は別途調査対象です。

### S04: 「あ／ア」モードの句読点・記号

| 項目 | 要求・選択例 | 状態 |
| --- | --- | --- |
| ピリオド | `。`／`．` を選択できます | 必須。半角 `.` も選択肢に含めることを提案します |
| カンマ | `、`／`，`／`,` を選択できます | 具体的な選択肢は提案です |
| 括弧などの記号 | 全角／半角を選べます。例: `（ ）`／`( )` | 必須。対象記号の全リストは未決です |
| 記号別の上書き | 一括設定に加え、記号ごとに出力を指定できます | 提案です |
| 「あ／ア」の共通設定 | 両モードに同じ記号設定を適用します | 提案。モード別の上書きは未決です |

初期値は標準ローマ字テーブルに従う提案とし、具体的な出力一覧を実装前に固定します。直接入力・全角英数・半角カナ・abbrev への適用範囲も明記します。「全角」の一語だけで、句読点や括弧の種類まで暗黙に決めません。

**競合時の提案:** 選択したテーブルに句読点・記号設定を適用し、その結果を画面に表示します。カスタムテーブルをそのまま使う「テーブルに従う」選択も用意します。SKK コマンドとして解釈する `>` や `/` などは、コマンド処理後の文字入力にだけ記号設定を適用します。設定によって変換開始などが失われないことを検証します。

### S05: 候補表示・選択

| 項目 | 要求 | 初期値・状態 |
| --- | --- | --- |
| 候補選択キー | `asdfjkl`／`1234567` などを選択できます | `asdfjkl` が確定初期値です。任意列の編集 UI は提案です |
| 単独表示の候補数 | 一覧に移るまでの候補数を指定します | 最初の3候補を単独表示することは確定。変更可能にすることは提案です |
| 一覧の候補数 | 固定数と画面幅に応じた自動調整を選べます | 必須。標準は7ラベルです。自動調整の初期採否は未決です |
| 注釈 | 候補本文と区別して表示し、確定文字には含めません | 表示は必須。表示オン／オフ設定は提案です |

すべての表示候補を物理キーで選択できるようにし、候補数と選択キー数の不整合を検出します。同一ページの重複ラベルは許可しません。幅変更で選択対象が意図せず入れ替わらないよう、ページ・ラベルの更新時点を実装前に固定します。長い候補・注釈を省略する場合も内容を確認する手段を用意します。

### S06: 辞書・学習

| 項目 | 要求 | 初期値・状態 |
| --- | --- | --- |
| システム辞書一覧 | 名前、有効状態、優先順位、利用可能／処理中／失敗を確認できます | 必須。出典・件数・更新日時の表示は提案です |
| 辞書追加 | ファイルから郵便番号・人名などの辞書を追加します | 必須。個人辞書への取り込みとは別操作にします |
| 有効・無効／並べ替え | 個別に切り替え、検索優先順位を変更します | 必須。個人辞書が先、システム辞書は設定順です |
| 更新・取り外し | 指定辞書を更新・利用対象から削除します | 必須。個人辞書や元の選択ファイルを巻き込まない操作にします |
| 個人辞書の取り込み・書き出し | 対応形式と文字コードを明示します | 必須。マージ／置換と重複時の扱いは未決です |
| 学習 | 候補順位・登録の永続化を制御します | 通常学習オンは確定。無効時は F10 に従います |
| 個人データを記録しない利用 | 学習・登録保存を抑止できます | 必須。通常の学習設定との UI 上の統合方法は未決です |
| 個人辞書の消去 | 対象と影響を示し、明示的な確認後に消去します | 提案。一般設定の初期化とは分離します |

システム辞書間の重複候補、注釈の統合、学習順位、削除した候補の再表示条件は実装前に確定します。不正行や非対応表現を黙って読み飛ばして「成功」と表示しません。部分取り込みを許す場合は件数・理由を表示し、適用判断ができる必要があります。更新失敗・中断時も旧辞書を利用できます。

### S07: 補完・高度機能

動的補完のオン／オフを設け、初期値はオフとします。通常の見出し語補完と動的補完の受諾操作を区別します。数値変換は初期値オンです。オン／オフ設定を公開するかは提案段階です。日付入力、送り条件の厳密照合、再変換、ネットワーク機能の設定は、機能仕様の確定後に追加します。未実装の設定を利用可能として表示しません。

### S08: 設定全体の操作・保存・復旧

- 各設定に現在値・標準値・適用範囲を示します。関連する設定への移動を可能にします。
- キーボードで項目移動・変更・保存・取消ができます。タッチ操作でも設定を復旧できます。
- 保存失敗を成功扱いせず、再起動後に最後に正常保存した設定を利用できます。
- 不正なキー・テーブル・辞書設定は適用前に検証します。復旧で個人辞書を消しません。
- 設定の取り込み・書き出し、カテゴリごとの初期化は提案です。設定ファイルに個人辞書を暗黙に含めません。
- 適用時点の提案として、入力規則・キー・候補設定は次の未確定入力開始から反映します。変更だけで入力中の文字を確定・消去しません。学習抑止は有効化後の保存処理に直ちに適用し、進行中の保存との境界を定義します。

## 非機能要件

| ID | 要件 | 検証・合格条件 |
| --- | --- | --- |
| N01 | コアを Android・画面・実 DB なしで検証できます | ローマ字、状態遷移、内部編集、候補選択、再帰登録を通常の JVM 単体テストで実行できます。辞書と出力先を差し替えられます |
| N02 | 要求ごとの回帰テストを維持します | 標準・カスタム設定、取消、失敗、境界条件の期待結果を記述します。不具合修正には再現テストを追加します。ブラウザ版の挙動を無条件に正解とせず DDSKK と採用仕様に照合します |
| N03 | Android 接続の品質を別に検証します | Enter の確定／送信分離、キー配送、入力欄変更、古い非同期結果、選択範囲変更を結合・実機試験します。コアのテストだけで全アプリ対応とは判定しません |
| N04 | 入力・辞書データを失わないようにします | 書き込み失敗・中断・再起動で既存辞書を保持します。別入力欄への誤挿入・二重確定を起こしません。保存失敗を通知し再試行できます |
| N05 | プライバシーを保護します | 入力本文を診断ログへ残さず、パスワード・学習禁止入力を学習しません。設定のオン操作で入力先の学習禁止を上書きしません。ネットワークは任意機能です |
| N06 | 応答性能・資源使用を測定します | 起動、打鍵反映、辞書検索の p50／p95／最大値、PSS を条件付きで記録します。辞書処理によって入力を長時間停止させません。数値目標は実機測定後に固定します |
| N07 | 対応環境・制約を明示します | 最低 API 26、主実機は Xiaomi Pad 8 とします。検証した OS・アプリ・配列・接続方法を記録します。Pixel 7 の確認は要求しません |
| N08 | Unicode の編集を安全に扱います | UTF-16 の片側だけを残しません。内部編集では結合文字・絵文字を含むユーザーが認識する文字単位を検証します。入力先で不可能な操作は制約として記録します |
| N09 | 表示・操作を読み取りやすくします | 文字サイズ変更、横幅変化、長い候補・注釈でも確定・取消できます。フォーカスと選択を識別できます。読み上げ対応の範囲は未決です |
| N10 | 拡張・保守を可能にします | コア、辞書・保存、Android 接続、表示・設定の責務を分け、テーブルやキー変更で全体を書き換えずに済む構造にします。ブラウザ版の分離とテスト資産を設計の参考にします |
| N11 | ビルド・変更を再検証できます | ツールの版と実行手順を管理し、変更に対応するテスト・Lint・ビルドを実行します。CI の整備と実行範囲は実装計画で具体化します |
| N12 | 配布・更新後も継続利用できます | 出典・ライセンスを確認し、辞書バックアップと更新手順を用意します。一般公開の条件は公開前に確認します。APK 更新時のデータ保持を検証します |

性能の測定境界と回数は [検証計画](validation-plan.md)、予備測定の代理指標は [性能測定手順](performance.md) に従います。数値目標が未確定の間は性能要件達成とは判定しません。

2026-09-12 の実機確認環境は Xiaomi Pad 8、Android 16、HyperOS 3.0.303.0、任天堂 Bluetooth キーボード（DS ポケモンタイピング付属）です。物理キーは日本語配列で、OS では英語配列へ切り替えて確認しました。これは全組み合わせの互換性保証ではありません。
