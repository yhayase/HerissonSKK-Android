# Android SKK IME 機能要件・非機能要件・設定要件

作成日: 2026-09-16。計画更新日: 2026-09-19

## 本書の位置付け

物理キーボードを中心に日常利用できる Android SKK IME の製品要件をまとめます。実装済み機能の一覧ではありません。既存の合意は「確定」、今回整理した未合意の具体案は「提案」、判断が必要な事項は「未決」と明記します。初回・後続の範囲は [ロードマップ](roadmap.md) を正本とします。分類・時期は公開計画と対応させ、実装済みかどうかは試験対応表で区別します。

本書は機能・品質・設定画面の要求を管理します。操作列と状態遷移の詳細は [互換性と受入仕様](compatibility.md)、時期は [ロードマップ](roadmap.md)、端末・アプリ別の試験は [検証計画](validation-plan.md)、実装状況は [要件と試験の対応](test-coverage.md) と [継続記録](work-status.md) を参照します。既存文書と異なる提案は、採用までは既存仕様を変更しません。

## 目的・対象範囲

- ローマ字による SKK 入力、変換、登録を物理キーボードだけで完結させます。
- 変換、辞書検索、学習はオフラインで利用できます。
- 郵便番号・人名などの追加辞書と、入力規則・キー・表示のカスタマイズに対応します。
- 見出し語内の編集と、入力先に対する任意の Emacs 編集キーを提供します。
- QWERTYソフトウェアキーボードは初回必須です。物理キーボード使用時に文字キー画面が入力領域を占有しないようにします。
- DDSKK 17.2 リリース（`ddskk-17.2_Mena`、`e8bf68b27021c29781dbfa6a8ef7b770565bdb5b`）を互換性基準とします。Emacs 全体や任意の Emacs Lisp の実行は対象外です。

## 設定画面の要件

以下は設定画面の情報構成です。レイアウトの確定案ではありません。「確定」の設定も現時点で実装済みとは限りません。

### S01: 入力・キーボード表示

| 項目 | 選択内容・動作 | 初期値・状態 |
| --- | --- | --- |
| 入力開始モード | 新しい通常入力セッションはひらがなにします。パスワード欄と `TYPE_NULL` は直接入力に限定し、通常のモード切替より優先します | 確定。変更設定やアプリ別記憶は初期対象外です |
| 物理キーボード接続時の文字キー画面 | 隠せます。候補・注釈・モード表示は別に扱います | 初回必須。具体的な表示・切替の設計は未決です |
| 物理キーボード未接続時の文字キー画面 | 表示の可否と切断時の扱いを定義します | 初回の設計事項です。切断時の表示方針と、後続の変換状態保持は区別します |
| 物理キーボード配列 | OS で設定した配列を利用し、設定画面から OS 側の設定場所を案内します | 確定。IME 独自の US／JIS 再マッピングは初期対象外です |

### S02: キーバインド・Emacs 編集

パスワード欄と `TYPE_NULL` では通常の SKK・Emacs 編集処理を迂回します。候補・登録・学習を行わず、C-j も入力先へ渡します。この製品上の例外を通常キーより優先します。学習禁止要求だけの通常欄では変換・候補表示を許し、保存のみ抑止します。

Emacs 編集のオン／オフは必須です。オフでも SKK の C-j・C-g などは残します。Emacs 編集だけに使うキーは、オフなら入力先へ渡します。見出し語・登録内の編集機能自体はオフでも物理キーで利用できる必要があります。

| 項目 | 要求 | 初期値・状態 |
| --- | --- | --- |
| Emacs 編集キーを使う | 内部の見出し語・登録文字と、未確定がない場合の入力先編集を対象にします | 既存の初期値はオフです。アプリ別の適用詳細は初回の設計事項です |
| Meta の割り当て | `M-f`、`M-b` を操作できる割り当てを提供します | 既存のMetaはAltです。Escape前置方式は初回必須ではありません |
| SKK コマンドのキー変更 | モード切替、変換、確定、取消、前候補、補完、登録、削除確認などを変更できます | 必須。標準キーは互換性仕様に従います |
| Emacs 編集キーの変更 | 標準の編集操作に別のキーを割り当てられます | 提案。候補選択キーは S05 で管理します |
| 競合表示・復旧 | 同じ状態で競合する割り当てを検出し、適用前に知らせます。標準設定へ戻せます | 必須。復旧は壊れたキー割り当てに依存しません |

対象とする標準 Emacs 編集キーは次のとおりです。前後の文字移動・削除は文字列を破壊しない単位で扱います。

| キー | 操作 | 内部バッファ／入力先で決める事項 |
| --- | --- | --- |
| C-a / C-e | 行頭／行末へ移動 | 採用済みの境界は [編集設計](emacs-editing-design.md) を参照します |
| C-b / C-f | 前／次の文字へ移動 | 結合文字・絵文字も含めて試験します |
| C-p / C-n | 前／次の行へ移動 | 単一行・複数行、縦移動時の列保持を定義します |
| C-h / C-d | 前／次の文字を削除 | 選択範囲がある場合の扱いを定義します |
| C-k | 行末まで削除 | 行末では直後の改行を削除します。詳細は編集設計に従います。C-y は現時点の必須対象に含めません |
| M-b / M-f | 前／次の単語へ移動 | 日本語・英数字・記号の単語境界を定義します |
| C-v / M-v | 次／前の画面へ移動 | 入力先では PageDown／PageUp 相当、候補選択では一覧ページを移動します |
| M-< / M-> | 文書先頭／末尾へ移動 | 入力先では Ctrl+Home／Ctrl+End 相当です |
| C-w / M-w | 選択範囲の切り取り／コピー | 入力先の選択範囲を操作し、未選択時は変更しません |
| C-m | 改行 | 未確定入力では Enter と同じく確定を優先し、確定と改行を二重に実行しません |

2026-09-17 改訂: かな入力の `-` は長音、`[` と `]` は鉤括弧にします。その他の記号の全角・半角を設定できます。変更のない入力規則設定画面は破棄確認なしで閉じます。再帰登録を C-g で抜けた場合は、登録前の最後の候補・一覧へ戻ります。辞書設定の追加・更新・有効化・並び替えは下書きにまとめ、確定して閉じるときに一括保存・再構築します。


**既存の配送契約:** 文字生成を判別したうえで、その状態の SKK コマンド・候補選択、内部バッファの編集、未確定がない場合の入力先編集、入力先への引き渡しの順とします。AltGr の文字生成を Meta と誤認しません。状態別の配送・編集境界は [カスタマイズ設計](customization-design.md) と [編集設計](emacs-editing-design.md) に従います。

内部バッファの編集で入力先の確定済み文字を変更しません。入力先編集は取得可能な文字列・選択範囲に制約され、全アプリでの同一動作は保証しません。編集対象を確認できない場合は推測で削除しません。その場合にキーを渡すか消費するかは、操作ごとに定義・検証します。アプリ別のEmacs編集オン／オフは初回必須です。アプリ別の個別キー割り当ては後続2です。

### S03: ローマ字テーブル・派生入力方式

| 項目 | 要求 | 初期値・状態 |
| --- | --- | --- |
| テーブル選択 | 標準とカスタムのローマ字規則を選べます | 標準を初期値とします。確定です |
| 規則のカスタマイズ | 入力列、出力文字列、必要な未消化文字の扱いを変更できます | 既存の保存形式はカスタマイズ設計に定義済みです。UIは初回に再設計します |
| 取り込み・書き出し | カスタム規則をファイルから導入し、保存できます | その他の後続。外部交換形式・版番号・文字コードを設計します |
| AZIK | ローマ字派生方式を利用できます | 採用済みの版・出典・競合は [AZIK仕様](azik-profile.md) を参照します |
| 検証・復旧 | 不正な規則を適用せず理由を表示し、標準へ戻せます | 必須。重複規則と正当な接頭辞共有を区別します |
| 入力試行 | 保存前に入力列と変換結果を確認できます | 初回UIの利用目的に必要なら含めます |

AZIK などを単なるテーブル置換で実現できるとは仮定しません。SKK コマンドとの競合や状態遷移を含む受入例を方式ごとに用意します。ACT・かな入力・親指シフト・TUT-code は別途調査対象です。

### S04: 「あ／ア」モードの句読点・記号

| 項目 | 要求・選択例 | 状態 |
| --- | --- | --- |
| ピリオド | `。`／`．` を選択できます | 半角 `.` を含めて実装済みです |
| カンマ | `、`／`，`／`,` を選択できます | この3種類を実装済みです |
| 括弧などの記号 | 全角／半角を選べます。例: `（ ）`／`( )` | 既存の対象記号はカスタマイズ設計に定義済みです。対象拡張は別途判断します |
| 記号別の上書き | 一括設定に加え、記号ごとに出力を指定できます | 提案です |
| 「あ／ア」の共通設定 | 両モードに同じ記号設定を適用します | 共通設定を採用済みです。モード別の上書きは提案です |

既存の初期値と適用範囲は [カスタマイズ設計](customization-design.md) に定義しています。対象記号の拡張範囲は設計時に判断します。「全角」の一語だけで、句読点や括弧の種類まで暗黙に決めません。

**競合時の契約:** 選択したテーブルに句読点・記号設定を適用し、その結果を画面に表示します。カスタムテーブルをそのまま使う「テーブルに従う」選択も用意します。SKK コマンドとして解釈する `>` や `/` などは、コマンド処理後の文字入力にだけ記号設定を適用します。設定によって変換開始などが失われないことを検証します。

### S05: 候補表示・選択

| 項目 | 要求 | 初期値・状態 |
| --- | --- | --- |
| 候補選択キー | `asdfjkl`／`1234567` などを選択できます | `asdfjkl` が確定初期値です。任意列の編集UIは後続3です |
| 単独表示の候補数 | 一覧に移るまでの候補数を指定します | 2026-09-17 改訂: 初期値は3候補目から一覧です。開始位置を1〜10候補目で設定できます |
| 一覧の候補数 | 固定数と画面幅に応じた自動調整を選べます | 必須。初期値は固定7件です。固定／自動とも画面高と文字サイズで件数を制限します |
| 注釈 | 候補本文と区別して表示し、確定文字には含めません | 表示は必須。表示オン／オフ設定は提案です |
| 未確定の表示記号 | 読みに `▽`、候補に `▼` を付けられます | 既定はオフです。入力先の本文を読み戻せる場合に限り、表示記号を確定本文・学習へ含めず扱います |

すべての表示候補を物理キーで選択できるようにし、候補数と選択キー数の不整合を検出します。同一ページの重複ラベルは許可しません。幅変更時のページ・ラベル固定は候補表示設計に従います。長い候補・注釈を省略する場合も内容を確認する手段を用意します。

### S06: 辞書・学習

| 項目 | 要求 | 初期値・状態 |
| --- | --- | --- |
| システム辞書一覧 | 名前、有効状態、優先順位、利用可能／処理中／失敗を確認できます | 必須。出典・件数・更新日時の表示は提案です |
| 辞書追加 | ファイルから郵便番号・人名などの辞書を追加します | 必須。個人辞書への取り込みとは別操作にします |
| 有効・無効／並べ替え | 個別に切り替え、検索優先順位を変更します | 必須。個人辞書が先、システム辞書は設定順です |
| 更新・取り外し | 指定辞書を更新・利用対象から削除します | 必須。個人辞書や元の選択ファイルを巻き込まない操作にします |
| 個人辞書の取り込み・書き出し | 対応形式と文字コードを明示します | マージ／置換と重複処理は辞書設計に定義・実装済みです |
| 学習 | 候補順位・登録の永続化を制御します | 通常学習オンは確定。無効時は F10 に従います |
| 個人データを記録しない利用 | 学習・登録保存を抑止できます | 必須。通常の学習設定との UI 上の統合方法は未決です |
| 個人辞書の消去 | 対象と影響を示し、明示的な確認後に消去します | 提案。一般設定の初期化とは分離します |

システム辞書間の重複・注釈統合・学習順位は辞書設計、削除候補の再表示条件は候補削除設計に定義します。不正行や非対応表現を黙って読み飛ばして「成功」と表示しません。部分取り込みを許す場合は件数・理由を表示し、適用判断ができる必要があります。更新失敗・中断時も旧辞書を利用できます。

### S07: 補完・高度機能

動的補完のオン／オフを設け、初期値はオフとします。通常の見出し語補完と動的補完の受諾操作を区別します。数値変換は初期値オンです。オン／オフ設定を公開するかは提案段階です。数値・日付の整備は後続1、厳密送り照合・再変換はその他の後続です。ネットワーク辞書導入・手動更新の設定は初回に設計します。未実装の設定を利用可能として表示しません。

### S08: 設定全体の操作・保存・復旧

- 各設定に現在値・標準値・適用範囲を示します。関連する設定への移動を可能にします。
- キーボードで項目移動・変更・保存・取消ができます。タッチ操作でも設定を復旧できます。
- 保存失敗を成功扱いせず、再起動後に最後に正常保存した設定を利用できます。
- 不正なキー・テーブル・辞書設定は適用前に検証します。復旧で個人辞書を消しません。
- 設定の取り込み・書き出しはその他の後続、カテゴリごとの初期化は提案です。設定ファイルに個人辞書を暗黙に含めません。
- 既存の適用時点として、入力規則・キー・候補設定は次の入力セッション開始から反映します。変更だけで入力中の文字を確定・消去しません。学習抑止は有効化後の保存処理に直ちに適用し、進行中の保存との境界を定義します。

## 設定UIの設計方針（初回必須）

各機能がユーザーにとって何であり、何をしたくて設定するのかを起点にします。その意味と利用目的に沿って画面の分け方、情報の順序、操作の流れ、用語、操作部品を設計します。内部設定項目をテキスト入力欄へ写した構成や、ウィジェットの選択だけで要件を満たしたとは扱いません。

ローマ字テーブルは、自分の打ち方で意図した文字を入力するためのものです。方式選択、一部の打ち方の変更、結果の確認という利用目的から画面を設計します。Emacs編集は、慣れた操作の利用とアプリとの衝突回避を目的とし、どこで何が有効か、SKK操作との関係を理解できる構成にします。

情報の強弱と画面ごとの目的を明確にし、一画面に異なる目的の項目を詰め込みません。保存・取消・復旧の扱いを揃え、タッチと物理キーの双方で操作できます。入力試行・プレビューはこの目的に必要なら初回に含めます。具体的な画面構成は設計時に相談します。
