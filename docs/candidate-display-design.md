# 候補・注釈・登録表示の設計

本書は入力UI再設計前の実装契約です。再設計で承認された本文非省略・注釈長押し・表示方式は[合意事項](input-ui-redesign.md)、移行順序は[実装計画](input-ui-implementation-plan.md)を優先します。

本書は現行の表示契約を管理します。初回のUI改善とQWERTY統合の範囲は [ロードマップ](roadmap.md)、実機受入は [検証計画](validation-plan.md) に従います。本契約と既存試験だけで再帰登録の見切れや全面改善を完了としません。

## 領域と表示内容

候補領域は縦方向にスクロールできる一つのビューです。通常帯は最大96dpかつ画面高の25%を目安とし、一覧・登録・全文は画面高の40%まで使います。実装は最小48dpと親の利用可能高も考慮します。状態・候補・ボタン・全文を合わせて領域を制限し、表示操作で入力先のフォーカスを移しません。

一覧を状態説明より上に、登録の見出し・本文・操作案内を辞書状態より先に配置します。固定の「ローカル辞書・限定試験辞書」は表示せず、入力モードや読込中・失敗などの実状態を示します。`input_status` は状態本文のIDです。

## 横並び一覧とページ

一覧は左から右へ並べます。文字倍率1で140dpを列幅の目安とし、ビューの実測幅から余白を引いた幅と文字倍率で列数を求めます。レイアウト前だけConfigurationの幅を代替値にします。自動設定は1段、上限指定は最大2段を使い、設定件数・ラベル数・幅・高さでページ件数を制限します。

候補選択開始時にページ件数とラベル対応を固定し、選択中のサイズ変更で選択対象を入れ替えません。表示タイルの配置は変わり得ますが、件数の再計算は次の選択開始時です。候補の長さだけで件数を変えません。初期値・一覧への移行とキー操作は [互換性仕様](compatibility.md) に従います。

本文とラベルは18sp、注釈は別行の13sp・淡い灰色で区別します。タイルの読み上げはラベル・本文・注釈のプレビューであり、巨大な全文をアクセシビリティノードへ渡しません。

## 有界プレビュー

| 対象 | 書記素数の上限 |
| --- | ---: |
| 一覧の候補本文 | 32 |
| 一覧の注釈 | 24 |
| 単独候補の注釈ウィンドウ | 32 |
| 一般状態の既定プレビュー | 96 |

各欄は実際の横幅でも省略します。書記素境界の探索はUTF-16で4096文字までとし、サロゲートを分割しません。探索上限を超える一書記素は通常表示で複製せず、その旨を表示します。全文への導線は下記の表示条件を満たす一覧候補で提供します。

## 単独候補の注釈

入力先が返すCursorAnchorInfoから座標を求め、候補本文を覆わない近傍のIME所有ウィンドウへ表示します。座標が得られない、または現在の候補と一致しない場合は省略します。この制約を全入力先で注釈が読める保証へ読み替えません。

注釈を入力先の未確定テキストへ挿入しません。確定・取消・一覧移行・入力欄変更・IME終了時には閉じます。単独候補の本文・注釈と全文ボタンは下部へ重複表示しません。

## 全文ボタンの条件

一覧の現在選択中の候補本文または注釈が省略されている場合だけ「候補の全文」を表示します。書記素数上限だけでなく実レイアウトの省略も検査します。他候補だけの省略では表示しません。候補・幅・文字サイズ変更時に再判定し、省略がなくなればボタンと全文表示を閉じます。単独候補では下部の全文ボタンを提供しません。

## 全文表示

選択中候補の「候補の全文」を押すと、候補領域内に候補本文と注釈を順に表示します。別 Activity、
Dialog、Intent は使わず、IME と入力先の接続を維持します。各ページは UTF-16 で 2048 文字を目標、
8192 文字を探索上限とし、全文の参照と現在位置だけを保持します。前へ、次へ、閉じるをタッチでき、
未修飾の Left、Right でもページを移動できます。

一つの書記素が 8192 文字を超える場合だけ、進行を保証するためコードポイント境界で分割し、その
事実をページ内に表示します。この例外でも欠落や重複はなく、全ページを連結すると元の UTF-16
文字列になります。候補が変わるか入力欄が終了すると全文表示を閉じます。

全文表示中も Space、候補ラベル、Enter、`x`、Ctrl-g などは従来の入力操作へ一度だけ配送します。
その際は全文表示を閉じてから同じキーを処理します。修飾キー単独と既存ショートカットの意味は
変更しません。キー押下の所有権は既存の `KeyPressLedger` に記録し、キーアップの漏出を防ぎます。

## 未確定表示記号

入力先へ `▽`／`▼` を表示する設定は既定でオフです。有効でも、本文を読み戻せて既知の選択位置がある場合だけ付けます。表示記号はコアの読み、候補本文、登録本文、学習対象には含めません。内部カーソルだけ表示記号の一文字分を補正します。

確定時はコアの本文で置き換えます。外部カーソル移動、引用前の保持、入力終了では、以前の表示全文と元の位置を読戻し結果で照合してから表示記号だけを除去します。入力先が先に composing span を終了しても本文を再挿入せず、現在の選択範囲を除去した文字数だけ補正します。本文の外部変更や読戻し失敗で照合できない場合は推測で削除せず、除去できなかった旨を通知します。この場合には表示記号が残る制約があります。

## 検証

JVM 試験では API 26 と 35 について、1 MiB 相当の候補・注釈、絵文字 ZWJ、結合文字、探索上限を
超える一書記素、ページ連結、候補変更、修飾キー、240 dp 幅、文字倍率 2.0、領域高上限を確認します。
実機相当試験では専用エミュレーターの幅と文字倍率を退避してから変更し、候補領域の寸法、短い
候補で全文ボタンが出ないこと、確定を公開 UI だけで確認します。表示設定は成否にかかわらず個別に
復元し、復元結果を厳密に照合します。実 IME 試験は辞書を変更しない長い登録本文と組み込み候補を使います。別の `CandidateStatusAndroidTest` は約百万 UTF-16 単位の本文・注釈と巨大な結合文字を実 Android ビューへ渡し、実測・レイアウト・描画・ページ移動を検証します。

実行は `scripts/test-display-emulator.py --serial emulator-N` と `scripts/test-view-emulator.py --serial emulator-N` を使います。API 26・35 の実 IME 試験は文字倍率 2.0、API 30 の検証環境は OS が 2.0 を拒否するため `--font-scale 1.3` を指定します。倍率を黙って下げず、要求値を履歴へ記録します。API 26 が構成変更時に未設定の倍率を既定値 1.0 として再登録する場合は、設定削除を再実行し、未設定へ戻ったことを連続照合します。


実施日・件数・APKの対応は [継続記録](work-status.md)、残る条件は [試験対応表](test-coverage.md) に集約します。
