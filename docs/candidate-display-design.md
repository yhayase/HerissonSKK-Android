# 候補表示の設計

## 目的

候補本文、注釈、登録本文が長い場合でも、IME の候補領域を操作できる大きさに保ちます。辞書の
候補本文と注釈はそれぞれ最大 1,048,576 UTF-16 単位になり得るため、全文を通常の `TextView` へ渡しません。
候補の選択、確定、取消は従来どおり物理キーで行い、表示のために入力先のフォーカスを移しません。

## 通常表示

候補領域全体を縦方向にスクロールできる一つのビューにします。通常帯は最大 96 dp、一覧・登録・全文表示は現在の画面高の 40% を上限に広げます。この上限には状態、候補、全文表示ボタン、全文ページ、移動ボタンをすべて含めます。
`input_status` は従来どおり状態本文を持つ `TextView` の ID として維持します。

候補本文は先頭 96 書記素、注釈は先頭 64 書記素、一覧内の各候補は先頭 48 書記素を上限とする
プレビューだけを表示します。境界探索へ渡す文字列も UTF-16 で 4096 文字以内に制限します。
Unicode の拡張書記素境界を優先し、サロゲートペアを分割しません。一つの書記素が探索上限を
超える場合、通常表示では本文を複製せず「非常に長い一文字」と表示して全文表示へ案内します。

アクセシビリティノードにも 1 MiB の全文を設定しません。通常表示は同じプレビューを読み上げ、
全文は次節の有界ページを順に読み上げます。これによりアクセシビリティ IPC も有界になります。

## 全文表示

選択中候補の「候補の全文」を押すと、候補領域内に候補本文と注釈を順に表示します。別 Activity、
Dialog、Intent は使わず、IME と入力先の接続を維持します。各ページは UTF-16 で 2048 文字を目標、
8192 文字を探索上限とし、全文の参照と現在位置だけを保持します。前へ、次へ、閉じるをタッチでき、
未修飾の Left、Right でもページを移動できます。

一つの書記素が 8192 文字を超える場合だけ、進行を保証するためコードポイント境界で分割し、その
事実をページ内に表示します。この例外でも欠落や重複はなく、全ページを連結すると元の UTF-16
文字列になります。候補が変わるか入力欄が終了すると全文表示を閉じます。

全文表示中も Space、候補ラベル、Enter、`x`、Ctrl-g などは従来の入力操作へ一度だけ配送します。
その際は全文表示を閉じてから同じキーを処理します。修飾キー単独と既存ショートカットの意味は
変更しません。キー押下の所有権は既存の `KeyPressLedger` に記録し、キーアップの漏出を防ぎます。

## 自動ページ幅

自動ページ数はディスプレイ全体ではなく、候補ビューの実測幅から左右の内側余白を引いた値で
算出します。初回レイアウト前だけ、現在の `Configuration.screenWidthDp` を代替値にします。
固定／自動どちらのページ件数も、画面高の 40% から余白を引き、現在のフォント行高で割った上限まで減らします。候補一覧を状態説明より上へ置き、一行ごとの末尾省略で一覧を読めるようにします。
候補選択開始時にコアがページ件数とラベル対応を固定するため、選択中の回転、狭幅化、文字
倍率変更では再割当てしません。次の候補一覧へ入る時に新しい実測幅を使います。

## 検証

JVM 試験では API 26 と 35 について、1 MiB 相当の候補・注釈、絵文字 ZWJ、結合文字、探索上限を
超える一書記素、ページ連結、候補変更、修飾キー、240 dp 幅、文字倍率 2.0、領域高上限を確認します。
実機相当試験では専用エミュレーターの幅と文字倍率を退避してから変更し、候補領域の寸法、短い
候補の全文表示、ページキー、確定を公開 UI だけで確認します。表示設定は成否にかかわらず個別に
復元し、復元結果を厳密に照合します。実 IME 試験は辞書を変更しない長い登録本文と組み込み候補を使います。別の `CandidateStatusAndroidTest` は約百万 UTF-16 単位の本文・注釈と巨大な結合文字を実 Android ビューへ渡し、実測・レイアウト・描画・ページ移動を検証します。

実行は `scripts/test-display-emulator.py --serial emulator-N` と `scripts/test-view-emulator.py --serial emulator-N` を使います。API 26・35 の実 IME 試験は文字倍率 2.0、API 30 の検証環境は OS が 2.0 を拒否するため `--font-scale 1.3` を指定します。倍率を黙って下げず、要求値を履歴へ記録します。API 26 が構成変更時に未設定の倍率を既定値 1.0 として再登録する場合は、設定削除を再実行し、未設定へ戻ったことを連続照合します。

## 一覧の操作と未確定表示

既定では 1・2 候補目を単独表示し、3 候補目から一覧にします。単独表示中の Space は次候補、一覧中の Space は次ページへ進みます。x は一覧の前ページへ戻り、最初の一覧ページから最後の単独候補へ戻ります。先頭候補からは読みに戻ります。末尾を越えると登録へ進む既存の契約を維持します。

登録中は見出し・本文・操作案内を辞書状態より先に配置します。全文表示の前へ・次へ・閉じるは横並びで本文より上に置きます。表示内容を変えても入力先へフォーカスを移しません。

入力先へ `▽`／`▼` を表示する設定は既定でオフです。有効でも、本文を読み戻せて既知の選択位置がある場合だけ付けます。表示記号はコアの読み、候補本文、登録本文、学習対象には含めません。内部カーソルだけ表示記号の一文字分を補正します。

確定時はコアの本文で置き換えます。外部カーソル移動、引用前の保持、入力終了では、以前の表示全文と元の位置を読戻し結果で照合してから表示記号だけを除去します。入力先が先に composing span を終了しても本文を再挿入せず、現在の選択範囲を除去した文字数だけ補正します。本文の外部変更や読戻し失敗で照合できない場合は推測で削除せず、除去できなかった旨を通知します。この場合には表示記号が残る制約があります。

2026-09-17 の検証では API 35 の候補表示 E2E 3 件が合格し、実際の画面画像でも表示を確認しました。今回の範囲と残る検証は [レビュー記録](reviews/quote-learning-menu-20260917.md) に記載します。

## 2026-09-17 横並びとインライン注釈

候補一覧は左から右へ並べ、上限件数指定では最大2段まで使います。タイル幅の目安は文字倍率1で140dpとし、候補領域全体の実測幅と文字倍率から列数を求めます。「画面幅と文字サイズに合わせる」は1段に収まる件数を使います。「上限を指定」も、設定件数・横幅・高さのいずれかの上限に達したら件数を減らします。設定済みの固定／自動の選択は維持します。

ラベルと候補本文は18sp、注釈は別行の13sp・淡い灰色にします。本文32書記素、注釈24書記素までの有界プレビューを作り、各行の横幅を超える部分は省略します。タイル単位の読み上げにはラベル・本文・注釈を含めます。候補選択の開始時にページ件数とラベル対応を固定し、Spaceは引き続きページ単位に進みます。

単独候補は入力欄の候補本文の近くに、IME所有の注釈ウィンドウを表示します。注釈は有界プレビューとし、候補本文より小さく淡く表示します。単独候補の本文・注釈と全文ボタンを下部ステータスへ重複表示しません。モードや辞書状態などの一般情報は残します。

注釈の文字を入力先の未確定テキストへ挿入しません。`CursorAnchorInfo` の座標を画面座標へ変換し、候補本文を覆わない近傍に表示します。入力先がカーソル座標の通知に対応しない場合や、現在の候補と座標情報が一致しない場合は注釈を表示しません。確定・取消・一覧への移行・入力欄の変更・IME終了時には注釈を閉じます。本文を編集しない表示なので、旧InputConnectionが無効になっても注釈がアプリ本文へ残ることはありません。
