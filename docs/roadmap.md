## 初回リリース

物理キーボードとQWERTYスクリーンキーボードの双方で、日常のSKK入力・変換・登録を行える版を公開します。

| 必須範囲 | 到達点 |
| --- | --- |
| 基本機能 | 入力モード、ローマ字、送り、abbrev、接辞、候補・注釈、補完、登録・再帰登録、学習・削除、ローカル辞書管理、バックアップ、入力設定を利用できます |
| 設定UI | Androidの標準ウィジェットを用途どおり使い、項目名・現在値・セクションを区別します。構成と操作順も標準的な設定階層に従い、標準部品でできない動作だけを拡張します。内部設定値をそのまま編集欄へ写しません |
| スクリーンキーボード | QWERTYのローマ字入力とShiftによる変換開始を提供し、候補選択・取消・再帰登録までタッチで完結できます。物理キーボード接続時は文字キー画面を隠せます |
| ネットワーク辞書 | システム辞書をURL指定または著名辞書のリストから導入し、利用者の明示操作で更新できます。定期・起動時の自動更新は行いません。取得後の変換はローカルで完結します |
| 初期辞書 | S辞書の初回導入は自動化し、専用の初期設定画面で追加辞書を選べるようにします。既知辞書はS・L・人名・地名・郵便番号の5種類とします。取得失敗時も再試行とファイル導入を利用できます |
| アプリ別設定 | ショートカットとの衝突を避けるため、アプリ別にEmacs編集キーを有効／無効にできます |
| IME切り替え | 別のIMEへ物理キーボードとタッチの双方から切り替えられます |
| 候補・登録表示 | 入力欄を隠さず、候補・注釈・再帰登録の階層と操作対象を読み取れます。既存の表示修正だけで全面改善完了とは判定しません |

数値変換は実装済みですが、追加整備・受入を初回の必須条件から外します。既存機能を削除する方針ではありません。

### 2026-09-21の追加受入指摘

設定ウィジェット・初期設定・辞書管理の統一と検証は[標準ウィジェット対応記録](reviews/settings-standard-widgets-20260921.md)に記録します。

- フリック記号は矢印を除き、キー内の余白を確保した右上・右下に配置します。主文字との重なり・枠外へのはみ出しを防ぎます。
- 設定はAndroid標準の設定部品と階層へ改めます。画面内のカテゴリ選択を廃止し、タイトル・戻る操作と保存・標準化操作をスクロール領域から分離します。幅に応じた配置、ラベルと補足の文字階層、現在値と操作の対応を整えます。
- 保存は上位画面へ戻り、未保存で戻る場合は保存・破棄・キャンセルを選べます。再読込・独立した破棄ボタン・不要な説明を除きます。ローマ字規則と辞書管理は現在の構成を一覧で示してから編集します。
- 初期設定は専用画面へ移し、通常設定の最下部から開けるようにします。初回S辞書導入の手動操作を不要とし、追加辞書の選択を初期設定へ組み込みます。既知辞書はS・L・人名・地名・郵便番号の5種類で承認済みです。
- アプリ側のEmacs編集を無効にしても、IME内の見出し語編集などには有効にできる設定を設けます。
- **アプリ名とアイコンの決定を初回リリースの必須作業に追加します。このセッションでは決定・制作を行いません。**

設定階層・初期設定・辞書カタログ・フリック記号・IME内Emacs編集の変更を実装し、独立レビューと指摘の再検証を行いました。[修正・検証記録](reviews/settings-ui-20260921.md)を参照します。アプリ名とアイコンの決定は引き続き未実施です。

追加の実機指摘に対し、アプリ検索・現在値の視認性、ドラッグ式辞書管理・取得元からの更新、初期S/L構成、文字キーの描画、`てn`の予測と不成立ローマ字を修正しました。[再調整の記録](reviews/settings-input-refinement-20260921.md)を参照します。

### リリース前の作業順序と入力UIの再設計

入力欄のない画面でのスクリーンキーボード表示と、利用者が隠した後の再表示を修正しました。[表示条件](keyboard-visibility.md)に従い、OSからの表示要求と物理キーボード用ポップアップを分離しています。[修正・検証記録](reviews/keyboard-visibility-20260921.md)を参照します。

2026-09-21の実機受入で、送りの文字種、区切り記号による変換、物理候補の表示・ページ送り・選択、予測検索、フリック表示に問題が見つかりました。[対応記録](reviews/acceptance-fixes-20260921.md)に沿って修正・独立レビュー・回帰確認を完了しました。修正版でAPI 26・35各66件が成功しています。今回の修正版の実機受入は未実施です。

設計議論で承認された内容と残る論点は[入力UI再設計の合意事項](input-ui-redesign.md)に記録します。コード調査と独立レビューを踏まえた[実装計画](input-ui-implementation-plan.md)を作成しました。下部領域ゼロのポップアップと状態保持を含め、実装と自動検証を完了しました。[最終結果](reviews/input-ui-20260920.md)を参照します。

実機受入で挙がった入力UI以外の論点を先に修正し、その完了後に入力UIの設計を議論します。入力UIの再設計は初回リリース前の大きな変更として扱い、公開後へ先送りしません。ロードマップへの追加時点では、UIの詳細設計・実装には着手しません。

1. C-j／Enterの意味、Ctrl+/ のUndo、Ctrl+y のPaste、最終行のCtrl+kと削除文字列のクリップボード連携、および `se.haya.skk` への識別子変更を扱います。アプリID変更に伴う試用版からの辞書移行も対象です。
2. キーボード配列、単一候補の確定操作、モード・候補メニュー・再帰登録の表示を含め、入力UIを一体として議論・設計します。Keep横向きの入力欄が隠れる観測も、この段階で原因と対応範囲を整理します。
3. 合意した入力UIを実装し、先行修正を含む最終版で影響範囲の回帰試験と受入を行います。

2026-09-20: 手順1の先行修正と自動検証・旧試用版辞書の移行検証を完了しました。[結果と制約](reviews/nonui-fixes-20260920.md)を記録しています。その後、手順2の入力UI設計について合意し、所有者の指示により手順3の実装・自動検証を完了しました。独立レビューと指摘の再検証を経て、同じIME APKでAPI 26・35各58件が成功しました。新配列などの操作感の判定は残ります。[実装計画と検証結果](input-ui-implementation-plan.md)を参照してください。

入力UIの設計で扱う方向性は次のとおりです。表示方式をすべてのアプリで保証する実装方針まで決定したものではありません。

| 対象 | 議論する方向性 |
| --- | --- |
| モード表示 | あ／ア／Aなどをモード遷移時に短時間だけカーソル付近へ表示し、常時下部を見る必要を減らします |
| 物理キーボード時の候補 | カーソル付近の小さなウィンドウに縦並びで表示し、入力位置と候補の間の視線移動を減らします |
| スクリーンキーボード時の候補 | 指の届きやすさを優先し、キーボード直上の横並び表示を検討します |
| 再帰登録 | 階層・現在の操作対象・登録内容を把握できる表示を検討します。カーソル側へ移す範囲は後続の設計議論で決めます |
| キーボードと確定操作 | 自然なQWERTY配列と、単一候補を含む確定・取消・登録の操作を再設計します |
| アプリ側の制約 | カーソル位置を取得できない場合や、画面端・スクロール・回転・入力方式切替でも、入力欄を隠さず操作を継続できる代替表示を検討します |

カーソル位置の取得にはAndroidの `InputConnection.requestCursorUpdates`／`CursorAnchorInfo` が利用できますが、入力先アプリが位置情報を返さない場合もあります。表示ウィンドウの方式と対応範囲は設計時に検証します（[Android API](https://developer.android.com/reference/android/view/inputmethod/InputConnection#requestCursorUpdates(int))）。

### 公開と品質判定

初回はAPK配布を基本とします。Playストア公開は、その時点の制度・費用・公開条件を確認して再判断し、初回の必須条件にはしません。[配布方針](distribution.md) に確認先を記録します。

利用者が日常利用して支障がない機能・ユーザビリティ、DDSKKやCorvusSKKとの操作上の差異の小ささ、既知の重大な欠陥がないことを品質基準とします。最終的な操作感は利用者が確認し、自動試験と操作例の比較を判断材料にします。意図的な操作差異は理由と制約を記録します。固定したDDSKK参照版は維持し、CorvusSKKの比較版・操作例は検証設計で具体化します。

対象はXiaomi Pad 8とPixel 7の縦横画面、JIS／US配列、画面キーボードです。必須10アプリとシナリオの割り当ては [検証計画](validation-plan.md) に集約します。全組み合わせの総当たりE2Eを要求せず、入力欄の特性とリスクに応じた代表経路を確認します。入力消失、二重確定、誤送信、別入力欄への誤挿入、辞書破損などの重大な欠陥を残して公開しません。

## 初回公開後の優先順位

| 順序 | 対象 |
| --- | --- |
| 公開直後 | バグ修正 |
| 後続1 | 数値変換・日付入力。同じ優先度で整備します。日付の操作列・形式・通常の@との区別は設計時に定義します |
| 後続2 | アプリごとの個別キー割り当て。初回のEmacs編集オン／オフより細かく変更できます |
| 後続3 | 任意の候補ラベル |
| それ以下 | 下記のその他機能。相互の全順序は付けません |

その他機能は、回転・キーボード切断時の変換状態保持、再変換、規則・設定の入出力、辞書サーバー接続、追加DDSKK機能、追加入力方式などです。再変換は確定履歴と選択文字列を別々に評価し、対象範囲が確認できなければ変更しません。既存バッファのQによる取り込みや任意のEmacs Lisp実行の再現とは区別します。

未完ローマ字からの予測について、AZIKなど標準以外のローマ字規則に応じた候補範囲の整備は将来の拡張とします。今回の修正は標準ローマ字の`n`の曖昧性と未完英字そのものの前方一致を対象にします。

個人辞書同期は順位を保留します。このIMEの端末間同期と他のSKK入力ツールとの共有を区別し、共有できる情報、競合・削除の反映、認証・通信失敗の制約を調べてから意味と優先度を判断します。

設定の入力試行やプレビューは、初回のUI設計に必要なら初回に含めます。独立した後続機能と決めつけません。
