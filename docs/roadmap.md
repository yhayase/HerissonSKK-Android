## 目的と基本方針

物理キーボードで SKK の入力・変換・辞書機能を使える Android IME を開発します。当面は物理キーボードを優先し、入力モード、候補、注釈、単語登録などに必要な表示を提供します。ソフトウェアキーボードの将来対応は妨げず、物理キーボード接続時には文字キーの画面を隠せることを要件とします。日常の入力操作は物理キーボードで完結させます。

DDSKK の入力・変換・辞書機能を互換性の基準とします。「フル機能」は名称だけで判断せず、機能ごとの操作例、期待結果、対応状況を記録して定義します。基準のコミット・設定と機能一覧は [互換性と受入仕様](compatibility.md) に記載します。

変換はローカル辞書で完結させます。辞書の取得・更新、サーバー接続、同期は任意機能として分離します。

## 対応範囲

| 分類 | 方針 |
| --- | --- |
| 基本入力 | ローマ字かな変換、ひらがな・カタカナ・半角カナ・ASCII・全角英数を対象にします |
| SKK 変換 | 送りあり／なし、送り条件、候補送り・戻し・選択、確定・取消、abbrev、接頭辞・接尾辞を対象にします |
| 辞書操作 | 単語登録、再帰登録、学習、候補削除、注釈、複数辞書、個人辞書の入出力を対象にします |
| 高度な入力 | 見出し語補完、動的補完、数値変換、ローマ字規則とキー割り当ての変更を対象にします。追加の DDSKK 機能は互換性一覧で扱いを決めます |
| 物理キーボード | 英語配列を初期試験に使い、JIS を含む複数レイアウトに対応する設計にします。OS の文字対応付けを尊重し、修飾キー、キーリピート、接続・切断を検証します |
| ソフトウェアキーボード | 将来の拡張対象です。実装時期は未定ですが、物理キーボード接続時には隠せることを要件とします |
| Emacs のバッファ操作 | 確定済みのバッファ上の文字を Q キーなどで見出し語へ取り込む操作は、そのままの互換対象にしません。IME 内の入力状態に対する Q キーの操作は別途定義します |
| 再変換 | Android の入力先から取得できる情報を使う独立した機能として検討します。上記のバッファ操作と同一視しません |
| Emacs Lisp | Emacs 内部 API や任意の Emacs Lisp コードをそのまま実行する互換性は対象外です。必要な動的変換は機能ごとに検討します |
| アプリ互換性 | 全アプリでの同一動作は保証せず、検証済みの環境と制約を公開します |

## 設計方針

- Kotlin を採用し、SKK コア、辞書、Android 接続、表示・設定を分離します。フェーズ 1 の基盤から Kotlin で実装しています。
- SKK コアは入力状態を所有し、未確定文字列、候補、確定要求などを Android 接続層へ返します。入力先アプリの全文編集を前提にしません。
- 物理キーを内部の入力操作へ正規化し、状態ごとに「処理する」「入力先へ渡す」を明示します。OS などが先に処理するキーには代替割り当てを用意できる設計にします。
- 単語登録用の文字列は IME 内で保持します。登録途中の文字列を入力先へ確定しません。
- 入力先の変更、選択範囲の変更、接続終了と非同期の辞書検索が競合しても、古い結果を別の入力欄へ反映しない設計にします。
- パスワード欄では内容を保存・学習せず、学習禁止要求にも従います。診断ログへ入力本文を残さない方針にします。

隣接する `../skk-browser-extension` の状態遷移、ローマ字処理、辞書モデル、再帰登録、既存テストを参考にします。ブラウザの DOM 操作、HUD、IndexedDB、拡張機能 RPC は Android 用に置き換えます。

### フェーズ 1: Android IME 基盤の実装

Android の物理キーボードで Shift や Ctrl とアルファベットの同時押しを扱えることは、ATOK などの IME でユーザーが検証済みの前提とします。この可否を再調査する工程は設けず、本 IME のキー処理と入力先への接続処理を実装・検証します。

作業:

- 最小の IME、設定画面、検証用入力アプリを実装します。
- 修飾キーを含む物理キーの内部操作への変換、キーアップ、リピート、未処理キーの入力先への引き渡しを実装します。
- `InputConnection` による未確定表示、確定、削除と、最小限の候補表示を実装・検証します。
- Ctrl+j、Ctrl+g、Shift、Enter、Escape、Backspace などが本 IME の状態に応じて処理され、未処理キーが入力先へ渡ることを確認します。
- 入力欄切り替え、カーソル移動、画面回転、キーボード切断、IME 切り替え時の状態処理を実装・検証します。

完了条件:

- ソフトウェアキーボードを表示せず、対象実機で入力・変換の最小経路を操作できます。
- 変換確定用の Enter が、同時に送信や検索を発火しないことを対象アプリで確認しています。
- 処理するキーの二重入力や、キーアップだけの不整合な配送が起きないことを確認しています。
- 入力欄切り替えやカーソル移動で意図しない文字の消失や別の入力欄への誤挿入が起きないことを確認しています。
- 技術選定、実装したキー処理、アプリ依存の制約、性能目標を記録しています。

## AndroidSKK の実機評価から明確になった要件（2026-09-12）

ユーザーが AndroidSKK 2.1.0 を Xiaomi Pad 8 へ導入し、画面キーボードの占有、追加システム辞書の選択、見出し語内の編集、入力先での Emacs キーバインド、`@` による日付入力に不足を感じたと報告しました。これらは採用・改修と新規開発を比較する際の判断材料です。現時点で開発基盤の変更は決定していません。

- 物理キーボード使用時は文字キーの画面を非表示にし、必要な候補・状態表示だけを残します。既存の基本方針を維持します。
- 郵便番号辞書・人名辞書などを、個人辞書へ混ぜることなく追加システム辞書として導入・選択できることを、フェーズ 3 の複数辞書管理の具体例にします。有効・無効と検索優先順位を扱います。
- 見出し語の途中へカーソルを移し、文字の挿入・削除・修正をできるようにします。内部編集は実装し、コア試験と代表的な入力結合試験があります。対象実機・アプリでの受入は残ります。
- 未確定の見出し語がないかな・直接入力モードでも、入力先に対する `C-a/e/b/f/n/p/h/d/k` と単語移動 `M-f/b` を任意の Emacs 編集設定として実装しました。接続の安全な読み取り範囲、連続編集、Unicode 境界を単体・代表結合試験で検証しています。入力先の `InputConnection` が必要な周辺文字や選択範囲を返せない場合の制約と、対象アプリ別の操作確認は残ります。`C-y` は必須対象ではありません。
- 見出し語内の編集は IME の内部バッファで扱い、確定済みの入力先の編集は Android 接続層で扱います。後者は入力先が提供する文字列・選択範囲・編集操作の範囲に制約されます。全アプリ同一動作は約束せず、優先アプリで検証し、編集対象を確認できない場合は推測による削除を行いません。Emacs のバッファ操作全般の再現とは区別します。実装時期は基本変換と辞書管理との依存を見て決定します。
- `@` による日付入力は低優先度の拡張として記録します。具体的な操作列・出力形式・候補の種類は未確定です。日時キーワードによる変換とは別に受入例を定義し、ASCII のメールアドレス等に含まれる通常の `@` 入力との区別も決めます。

### カスタマイズと表示の追加要件

ソフトウェアキーボードそのものが不要なのではなく、物理キーボード接続時に画面を占有しないことが要件です。ソフトウェアキーボードの実装時期は未定のままとし、接続・切断時の表示方針は導入時に定義します。

ローマ字マップ、句読点・記号、AZIK、キー割当、候補ラベルと固定／自動ページ数の設定は実装しました。設定の保存・復旧と新しい入力セッションへの反映を単体試験と API 26／30／35 の代表 E2E で検証しています。候補表示の狭幅・大文字・長い本文／注釈の境界試験は追加中で、対象実機・アプリでの受入は残ります。任意の候補ラベル列の編集 UI、規則ファイルの入出力、入力試行など、[設定要件](requirements.md) で「提案」とした項目は実装済みと見なしません。

## 将来の改善項目

### 回転・キーボード切断時の変換状態の保持

Xiaomi Pad 8 の手動確認で、画面回転と Bluetooth キーボードの電源断により候補が確定されたような状態になること、回転後に未確定表示のアンダーラインが残ることが報告されました。2026-09-12 の判断では現状を許容し、この改善はフェーズ 1 の完了を妨げる条件にしません。

将来は、同じ入力欄で操作を続ける場合、回転やキーボードの切断・再接続を経ても読み・候補選択を保持し、変換を続けられる動作を目指します。アンダーラインと実際の変換状態の不一致も解消します。別の入力欄を明示的に選んだ場合に、元の欄へ表示済みの文字を残して未確定状態を終了する現行動作は許容します。

Android の構成変更に伴う IME の再開始や入力先画面の再生成と、本 IME が変換状態を終了する処理を区別して調査します。候補の確定が Android に必須の仕様とは扱いません。別の入力欄へ古い文字を挿入しないことを条件とし、フェーズ 5 の互換性・復旧動作の検証時に改善を検討します。

## 検証の進め方

コアの状態遷移テスト、辞書の永続化・中断テスト、Android 接続の統合テスト、実機での操作確認を組み合わせます。テストは各フェーズで追加し、フェーズ 5 に先送りしません。ブラウザ版のテストからは操作仕様を抽出し、Android 固有の Enter、フォーカス変更、キー配送の挙動は独立して検証します。
