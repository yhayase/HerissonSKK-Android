# ロードマップ

本書は製品のリリース範囲と将来の優先順位を示します。個別の未解決事項と実施状況は [Issue とマイルストーン](https://github.com/yhayase/HerissonSKK-Android/issues)で管理します。要求の正本は[製品要件](requirements.md)、操作は[互換性仕様](compatibility.md)、公開判定は[リリース受入条件](release-acceptance.md)です。

## 初回リリース

物理キーボードとQWERTYスクリーンキーボードの双方で、日常のSKK入力・変換・登録を行える版を公開します。

| 必須範囲 | 到達点 |
| --- | --- |
| 基本機能 | 入力モード、ローマ字、送り、abbrev、接辞、候補・注釈、補完、登録・再帰登録、学習・削除、ローカル辞書管理、バックアップ、入力設定を利用できます |
| 設定UI | Androidの標準ウィジェットを用途どおり使い、項目名・現在値・セクションを区別します。構成と操作順も標準的な設定階層に従い、標準部品でできない動作だけを拡張します。内部設定値をそのまま編集欄へ写しません |
| スクリーンキーボード | QWERTYのローマ字入力とShiftによる変換開始を提供し、候補選択・取消・再帰登録までタッチで完結できます。物理キーボード接続時は文字キー画面を隠せます |
| ネットワーク辞書 | システム辞書をURL指定または著名辞書のリストから導入し、利用者の明示操作で更新できます。定期・起動時の自動更新は行いません。取得後の変換はローカルで完結します |
| 初期辞書 | S辞書の初回導入は自動化し、専用の初期設定画面で追加辞書を選べるようにします。既知辞書はS・L・人名・地名・郵便番号の5種類とします。取得失敗時も再試行とファイル導入を利用できます |
| アプリ別設定 | ショートカットとの衝突を避けるため、アプリ別にEmacs編集キーを有効／無効にできます |
| IME切り替え | 別のIMEへ物理キーボードとタッチの双方から切り替えられます |
| 候補・登録表示 | 入力欄を隠さず、候補・注釈・再帰登録の階層と操作対象を読み取れます。既存の表示修正だけで全面改善完了とは判定しません |

数値変換の追加整備・受入は初回の必須条件から外します。既存機能の削除は予定しません。

## 初回公開後の優先順位

高・中・低の区分で扱い、同じ区分の中には順序を付けません。その他の後続機能は低優先度の候補ラベルより後に扱い、相互の順序は付けません。初回リリースの必須範囲と公開時の品質判定は別に管理します。

| 優先度 | 対象・到達点 |
| --- | --- |
| 高 | 既存の辞書取り込み・書き出しについて、DDSKK・FlickSKKとの実際の交換と往復を試験し、注釈・送り条件・候補順の保持を確認します |
| 高 | 数値変換・日付入力を整備します。日付の操作列・形式・通常の `@` との区別は設計時に定義します |
| 高 | 10キーフリックを追加し、UX設計を早期に行います。FlickSKK（iOS）の利用者が移行しやすく、タッチ入力の使い勝手を改善できる操作を検討します |
| 中 | `\` による文字コード入力を追加します。DDSKKのJIS・EUC・区点形式とUnicodeを対象とし、詳細な操作・形式は設計します |
| 中 | 動的補完の精度と使いやすさを改善します。表示・受諾キー・アルゴリズムは未決です |
| 中 | アプリごとの個別キー割り当てを追加します。初回のEmacs編集オン／オフより細かく変更できます |
| 中 | 辞書読込待機が1,024件を超えた際に受理済み入力を失う経路を修正し、1,025件目を含む回帰試験を追加します |
| 低 | 任意の候補ラベルを追加します |
| 低 | DDSKK互換の動的補完を独立した任意拡張として検討します |
| その他の後続 | 下記のその他機能を扱います。低優先度の候補ラベルより後とします |
| 調査先行・実装順位保留 | 個人辞書同期と、システム管理のローカル言語モデルの利用可能性を同じ優先度で調査します |

### 10キーフリック

かなを直接入力し、英字入力はA／Ａモードとabbrevに対応します。新しいフリックではローマ字によるかな入力を対象にせず、既存QWERTYは引き続きローマ字入力を提供します。大文字入力に頼らず簡単に入力できる方式を検討します。単語・送りの境界を明示する操作の候補としてShiftの長押し、フリック後の長押し、その他の操作を比較します。採用する操作と境界の判定方法は未決です。

### 動的補完

主目的は補完の精度と使いやすさです。DDSKKとの互換性やアルゴリズムの出力一致を主機能の目標にしません。言語モデルを利用する場合はシステム管理のローカルモデルを対象とし、アプリ独自のモデルを配布・保持しません。採用は下記の先行調査で判断し、利用できない環境では辞書・学習履歴による補完を使う方針です。既存の物理キーボード向け通常補完・動的補完の動作は[補完設計](completion-design.md)に従い、改善後の仕様を既存動作だけから確定しません。画面キーボードの予測は別の既存機能として扱います。

### その他の拡張

その他機能は、回転・キーボード切断時の変換状態保持、再変換、規則・設定の入出力、辞書サーバー接続、追加DDSKK機能、追加入力方式などです。再変換は確定履歴と選択文字列を別々に評価し、対象範囲が確認できなければ変更しません。既存バッファのQによる取り込みや任意のEmacs Lisp実行の再現とは区別します。

未完ローマ字からの予測について、AZIKなど標準以外のローマ字規則に応じた候補範囲の整備は将来の拡張とします。現行の標準ローマ字の`n`と未完英字の扱いは[補完設計](completion-design.md)を参照します。

設定の入力試行・プレビューを追加する場合は、利用目的と受入例を先に定めます。

## 先行調査

個人辞書同期とシステム管理のローカル言語モデルの調査は同じ優先度とし、相互の順序は付けません。調査結果から採用範囲と実装順位を判断します。動的補完全体の改善は引き続き中優先度です。

### 個人辞書同期

個人辞書同期は調査を先に行い、実装順位を保留します。このIMEの端末間同期と他のSKK入力ツールとの共有を区別し、共有できる情報、競合・削除の反映、通信方式、認証・通信失敗の制約を調べてから範囲と優先度を判断します。既存の辞書入出力の互換性試験とは別に扱います。

### システム管理のローカル言語モデル

最近のAndroidの対応端末に限定した機能として、OS側がモデルを管理するAPIを動的補完に利用できるか調べます。候補はML Kit Prompt APIとAICoreのGemini Nanoです。対応端末、モデルの準備、他のアプリへ入力中のIMEからの呼び出し可否、日本語補完の精度・応答速度・呼び出し制限を確認します。APIと表示・操作の詳細は採用前に固定しません。

[Androidの公式説明](https://developer.android.com/ai/gemini-nano)ではAICoreがモデルの配布・更新を管理します。一方、[ML Kitの実行制限](https://developers.google.com/ml-kit/genai#background_usage)は推論を最前面のアプリに限定しています。キーボード表示中のIMEが利用できるとは仮定せず、対応実機で確認します。

## 解決が必要な実装差

[辞書キャッシュ設計](dictionary-storage-cache-design.md)は、受理したキーを待機件数だけを理由に失わないことを要求します。現行の辞書読込待機には 1,024 件の上限があり、超えたキーを消費したまま保持しない経路があります。中優先度の修正対象とし、1,025 件目を含む回帰試験と実装修正を行います。通常の利用操作による再現条件や発生頻度は未確認です。[試験対応表](test-coverage.md#重要な検証限界)にも検証境界を示します。

その他の不具合は、利用への影響と再現条件に応じて修正順位を判断します。機能開発すべてに一律の前提条件は設けず、公開の可否はリリース受入条件に従います。
