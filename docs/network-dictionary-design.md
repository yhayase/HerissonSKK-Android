# ネットワーク辞書の導入・更新設計

本書は取得先、既知辞書の選定、通信境界、保存と失敗時の動作を定めます。辞書本文の解析と検索順位は[辞書設計](dictionary-design.md)、設定画面の操作は[設定 UI](settings-ui-design.md)を参照します。

初回の専用セットアップではS辞書を自動で準備します。その他の辞書取得・更新は利用者の選択と操作で実行します。入力中や定期処理では取得・更新しません。取得済み辞書は SQLite を正本としてオフラインで検索します。

## 操作

- 公式カタログは `SKK-JISYO.S`、`L`、`jinmei`、`geo`、`zipcode` を示します。配布 URL は `https://skk-dev.github.io/dict/SKK-JISYO.{S,L,jinmei,geo}.gz`、配布元・ライセンス情報は `https://github.com/skk-dev/dict/blob/master/committers.md` です。
- 郵便番号は `https://raw.githubusercontent.com/skk-dev/dict/master/zipcode/SKK-JISYO.zipcode` から取得します。配布元の更新は2022年5月です。他の4辞書とライセンスが異なるため、各辞書からそれぞれの配布元・ライセンスを開けるようにします。
- 初期S辞書は専用の初期設定画面で自動取得します。導入済みの辞書は再取得せず、取得失敗時に再試行できます。追加辞書は選択してから導入します。初回導入は以後の自動更新を意味しません。
- 任意の公開 HTTPS URL も指定できます。保存済みの取得元がある辞書は一覧の更新アイコンから更新し、更新も明示操作で開始します。
- 取得後は文字コード、見出し語数、候補数、重複、注釈競合を既存の確認画面に表示します。ここで適用しても設定下書きへ追加するだけで、画面の「保存」まで公開辞書は変わりません。破棄は既存の下書き契約に従います。

## 既知辞書と出典

既知の辞書は S・L・人名・地名・郵便番号の五種類です。S は初回の基礎辞書として自動準備します。初期設定で L を選んだ場合は導入成功後に S を置き換えます。人名と地名は追加選択です。郵便番号は七桁の郵便番号から住所を変換します。事業所個別の郵便番号辞書は対象外です。カタログへの掲載と自動導入を区別します。画面では `SKK-JISYO.S`、`SKK-JISYO.L`、`SKK-JISYO.jinmei`、`SKK-JISYO.geo`、`SKK-JISYO.zipcode` の配布名を示します。

配布一覧は[SKK 辞書配布サイト](https://skk-dev.github.io/dict/)、郵便番号辞書の出典と条件は[配布元の README](https://github.com/skk-dev/dict/blob/master/zipcode/README.md)を参照します。郵便番号と事業所辞書の本文は README 上で public domain と説明されています。一般辞書と条件を一括表示せず、辞書ごとに取得元、ライセンス、更新情報を持たせます。郵便番号辞書の配布元は 2022-05-05 のコミット `b20a95c79d2def932a788721e00ce5654cfc8161` であり、画面に 2022 年 5 月の更新日を示し、最新の住所データとして扱いません。取得物の版・ハッシュは[辞書出典監査](audit/dictionary-sources-20260923.json)を参照します。

## 取得境界

URL は HTTPS、ホスト必須、認証情報なし、フラグメントなしに限定します。接続前と各リダイレクト先で名前解決結果を調べ、ループバック、リンクローカル、プライベート、マルチキャストなど公開ネットワークでない宛先を拒否します。HTTPS から HTTP への転送も URL 検証で拒否します。転送は最大 5 回、接続タイムアウトは 15 秒、読み取りタイムアウトは 30 秒です。

圧縮本文と展開本文をそれぞれ 64 MiB 以下に制限します。gzip は HTTP の `Content-Encoding` または gzip マジックで判定し、通常本文も受理します。展開後は既存コーデックで strict UTF-8、失敗時 strict EUC-JP として全件を解析します。不正な一行を含む場合は全体を拒否します。

通常の辞書管理から開始した取得は中止できます。画面破棄時も接続を切断し、終了後のコールバックは画面や下書きを変更しません。取得、展開、解析、確認の取消または失敗では保存処理を開始しません。

初期設定でのS辞書と選択済み辞書の導入はプロセス内で管理し、画面回転や初期設定を閉じる操作では中断しません。プロセスが終了した場合は、復元した完了対象を再度確認して未導入分を再開します。導入完了は保存と入力への反映の両方で判定し、保存後の反映に失敗した場合は再取得せず反映を再試行します。

利用者が L を選んだ場合は、先に開始した S の取得が後から終わっても L の選択と優先順を覆しません。失敗後の再試行でも、その時点の辞書一覧と選択を読み直してから適用します。

## 保存と失敗時の状態

システム辞書にnullableな取得元URIを持たせます。既存の`originUrl`フィールドを使い、ネットワークはHTTPS、ファイルはStorage Access Frameworkのcontent URIを保存します。ファイル更新では完全一致する永続読取権限を必要とし、バックアップにURIがあるだけでは読み取りません。旧版で取得元を記録していないファイル辞書は再追加が必要です。本文、新しい世代、名前、取得元 URL は既存の設定下書きを一つの SQLite トランザクションで確定します。書き込み失敗、世代競合、中断では本文と取得元の両方をロールバックし、以前の公開世代を検索し続けます。

完全バックアップ形式は版 2 でシステム辞書の `originUrl` を追加します。版 1 は取得元なしとして引き続き復元できます。版 2 の復元では取得元も候補本文と同じ復元トランザクションへ含めます。個人辞書と組み込みフォールバックには取得元を付けません。

## 検証範囲

単体試験では URL 制約、公開アドレス制約、各転送先の再検証、HTTP 失敗、圧縮前後の容量境界、開始前取消を検証します。SQLite 試験では本文と取得元の原子性、完全バックアップの往復を検証します。実配布サーバーへの取得、通信途中の画面再作成、端末の容量不足は結合試験の対象です。
