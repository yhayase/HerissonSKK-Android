# 日付入力と限定した日付式

## 対応範囲

かな入力での `@` による今日の日付入力と、辞書内の限定した現在日付・相対日付式を提供します。日付は変換時に生成し、辞書には式と日付候補であることを保存します。任意の Emacs Lisp、利用者定義関数、任意の整形文字列やコールバックは実行しません。

互換性の参照元は DDSKK 17.2（`ddskk-17.2_Mena`、`e8bf68b27021c29781dbfa6a8ef7b770565bdb5b`）の [skk-gadget.el](https://github.com/skk-dev/ddskk/blob/e8bf68b27021c29781dbfa6a8ef7b770565bdb5b/skk-gadget.el) と [skk-vars.el](https://github.com/skk-dev/ddskk/blob/e8bf68b27021c29781dbfa6a8ef7b770565bdb5b/skk-vars.el) です。DDSKK の日付処理には整形関数や設定による変更があります。本書の形式・暦・上限は本アプリで定義する対応範囲であり、DDSKK の全設定を再現するものではありません。

## 操作と候補順

かな入力モードで読みや未消化ローマ字がないときに `@` を入力すると、`today` を見出しとして通常の候補選択へ進みます。個人辞書の既存候補と学習した順序を優先し、三形式を持つ組込み辞書を最後に合成します。同じ式と日付候補の属性を持つ候補は由来をまとめ、削除・非表示指定を優先します。新規導入時は追加辞書がなくても三形式を選べます。

| 形式 | 2026年10月10日の例 |
| --- | --- |
| 元号・全角数字 | `令和８年１０月１０日(土)` |
| 西暦・日本語 | `2026年10月10日(土)` |
| ISO形式 | `2026-10-10` |

Space で次候補、`x` で前候補へ移り、通常変換と同じ操作で確定・取消します。選んだ形式を学習すると、その形式の式を `today` の候補として保存します。確定した日付を固定文字列として学習しないため、後日も選んだ形式でその日の候補を生成します。学習禁止の入力欄や学習を無効にした設定では保存しません。

読みの入力中、abbrev、直接入力、全角英数での `@` は日付入力を開始しません。メールアドレスなどの本文として扱う `@` と区別します。

## 許可する辞書式

現在日付は省略可能な引数を含め、次の形に限定します。第1・第2引数は `nil`、第3引数だけは `nil` または `t` を許可します。

```lisp
(skk-current-date)
(skk-current-date nil)
(skk-current-date nil nil)
(skk-current-date nil nil nil)
(skk-current-date nil nil t)
```

最初の四形式は元号・全角数字の日付です。第3引数の `t` は端末の時刻を `００時００分００秒` の形で付けます。

相対日付は次の形だけを許可します。

```lisp
(skk-relative-date nil nil nil :dd -1)
(skk-relative-date nil nil nil :dd +1)
```

`:dd` の値は符号を省略できる半角整数で、範囲は −36,600〜36,600 日です。端末のタイムゾーンの暦日を移動します。年・月の移動、任意の整形、相対日付への時刻指定は対象外です。

西暦・日本語と ISO の組込み形式を SKK テキストでも保存するため、次の二つの定型だけを追加で許可します。

```lisp
(skk-current-date (lambda (date-information format gengo and-time) (skk-default-current-date date-information nil 0 nil 0 0 0 and-time)))
(skk-current-date (lambda (date-information format gengo and-time) (format-time-string "%Y-%m-%d")))
```

この二形式は式全体の固定された文字列を識別して、専用の日付処理へ対応付けます。`lambda` の評価や関数呼出しは行いません。外側の空白を除いた本文を変更したコールバックや、別の整形文字列は対応外です。許可する式の長さは256文字までです。

## 日付境界と表示の固定

一回の検索で時刻と端末のタイムゾーンを一度取得し、その検索の全候補を同じ日時から生成します。相対日付は24時間の秒数を足す処理ではなく、暦日の加減算です。

日付表示は数値変換のキャッシュの外で生成します。同じ読みを次に検索したときは日時を取り直すため、日付境界やタイムゾーンの変更を反映します。候補選択を開始した後は、その候補一覧の表示と確定文字列を固定します。選択中に日付が変わっても、選んだ候補と異なる日付を確定しません。

日付の対象は西暦1〜9999年です。元号表示は1873年1月1日以降を対象にし、明治・大正・昭和・平成・令和の境界を扱います。元年は「元」と表示します。1873年より前は西暦の日本語形式へ戻し、旧暦への換算は行いません。範囲外や暦日の計算失敗では、その式の候補を生成しません。

## 辞書・学習・バックアップ

取り込みでは許可した式の元本文と日付候補の属性を保持し、表示済みの日付に置き換えません。本文が同じでも、式として取り込んだ候補と通常の文字列候補は別候補です。式に見える文字列を保存するときは限定した `concat` で書き出し、再取り込みで日付候補へ変わらないようにします。注釈、個人注釈の属性、送り条件、見出しの区分も保持します。

数字を含む読みを数値変換で正規化する場合も、日付式の本文を数値テンプレートとして展開せず、元の式と正規化した学習先を保持します。`#4` の内側検索では日付式を表示材料にしません。

個人辞書・候補の非表示指定・予測の使用履歴では、式と通常文字列を属性で区別します。保存領域のスキーマは第7版、完全バックアップは第5版でこの属性を保持します。旧版データは通常文字列として移行し、本文だけから日付式へ推測変換しません。日付式を含むデータを旧版形式で保存することはできません。[完全バックアップ設計](complete-backup-design.md)も参照します。

組込み日付辞書は `appbuiltin-date-formats`（世代0）として通常の辞書合成・非表示指定・完全バックアップに含めます。アプリでは由来を持たない組込み候補の補充を無効にします。完全バックアップの復元時は保存された辞書構成と非表示指定をそのまま復元し、組込み辞書が含まれないバックアップに追加しません。

現在の予測候補には日付式を含めません。通常変換で生成した日付や元の式が、予測のキャッシュから古い候補として表示されないようにします。日付候補の削除・非表示では、元の式と由来を対象とし、同じ本文の文字列候補を巻き込みません。同じ式にシステム辞書と組込み辞書の由来がある場合は、両方の由来を非表示にします。非表示指定は再起動後も保持し、組込み形式を別途追加して候補を復活させません。

認識できる対応外のコールバック・整形形式と、`:yy`・`:mm` や複数のオフセット指定を使う既知の相対日付式は、警告付きの取り込みで候補単位に除外します。相対日付式の判定は既知のキーと半角整数の組を検証するだけで、年・月の移動や式の評価は行いません。整数は32ビット符号付き整数の範囲とし、`:dd` はさらに −36,600〜36,600 日に制限します。二つの固定定型はこの除外の例外です。未知の式、破損した構文、構造上限を超えるコールバック、範囲外の相対日付は取り込み全体を拒否します。厳密な取り込みでは対応外の式も拒否します。

## 受入で確認する経路

組込み辞書の扱いは、次の操作列で確認します。この一覧は受入条件であり、試験の実行結果は[要件と試験の対応](test-coverage.md)で管理します。

- 新規導入時に `@` から三形式を選べます。
- 同じ日付式が追加辞書にもある場合は、一つの表示候補に両方の由来を保持します。
- 候補を削除・非表示にすると組込み辞書の由来も非表示にし、再検索と再起動後も復活しません。
- 非表示指定を含む完全バックアップの復元後も候補を復活させません。組込み辞書のないバックアップの復元では、新たな組込み辞書を補充しません。
- 同じ本文の通常文字列候補は、日付式の削除・非表示の影響を受けません。

## 今後の範囲

日付入力は高優先度の項目の一部を実装した段階です。任意の整形設定、年・月の相対移動、日付の予測対応は未対応です。DDSKK の削除抑止式の引き継ぎも別の未完了項目です。任意の Lisp やコールバックを実行する機能は対象にしません。優先順位は[ロードマップ](roadmap.md)に従います。
