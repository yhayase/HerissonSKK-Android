# 配布・更新の手順

本書は HerissonSKK の APK／AAB を作成し、内容と更新互換性を確認するための手順です。現在の一般配布経路は Google Play を予定しており、Play での配布はまだ始まっていません。ソースは公開リポジトリにあり、プライバシーポリシーは [GitHub Pages](https://yhayase.github.io/HerissonSKK-Android/privacy-policy.html) で公開しています。サイト本文を変更したときは公開 URL への反映を確認します。公開版の判定条件は[リリース受入](release-acceptance.md)、実際に提出する情報は[掲載文案](play-store-listing.md)と[Console 申告案](play-console-declarations.md)で管理します。制度と Console の画面は提出時に再確認してください。

## 配布方針と署名

アプリ ID は `se.haya.skk` です。Google Play では Play App Signing に Google 生成のアプリ署名鍵を使用し、別のアップロード鍵で AAB を署名して提出します。外部配布する場合は Play Console から取得した Google 署名済み APK を使用し、Play 配布版と同じ署名にそろえる方針です。アップロード鍵をアプリ署名鍵として提出しません。[鍵の保管・復元と AAB 署名](upload-signing.md)に具体的な手順があります。

開発署名 APK と Google 署名済み APK は署名が異なります。同じアプリ ID でも上書き更新はできないため、既存の辞書と設定を退避し、別アプリ ID の旧試用版 `jp.hayase.skk` からの移行と同様に、[移行手順](package-migration.md)と[更新検証](upgrade-validation.md)で確認します。署名が一致する版間の更新確認では `adb install -r` を使用し、アンインストールや `pm clear` によってデータ保持の確認を回避しません。パッケージ名、versionCode、署名証明書の一致を確認します。

価格は無料、配布地域は Google Play で配布可能な全地域、公開問い合わせ先は `herisson@haya.se` とします。初回の対象年齢は 13–15 歳、16–17 歳、18 歳以上です。13 歳未満を後から含める場合は、Families、Data Safety、IARC、プライバシー説明を再評価します。これらは申告草稿の前提であり、最終的な Console の選択内容と一致させます。

## 成果物の作成

JDK 17 以上、Android SDK Platform 36、Build Tools 35.0.0 を用意し、SDK の場所を `ANDROID_HOME` または Git 管理外の `local.properties` に指定します。現行のビルド定義と必要な版は[開発ガイド](development.md)と `app/build.gradle.kts` を確認してください。

```sh
python3 scripts/verify-local.py
./gradlew :app:bundleRelease
```

`verify-local.py` はホスト・単体試験、lint、APK／AAB と通知・権限の検査を行います。結果は `build/reports/local-verification/` に保存します。キャッシュのみで実行する場合は `--offline` を指定します。個別の再現試験は[検証手順](validation-plan.md)に従います。`app/build/outputs/apk/debug/app-debug.apk` は開発署名・デバッグ可能な検証版です。benchmark APK は別パッケージの計測版です。未署名の release APK／AAB を配布済み成果物として扱いません。

公開候補は、対象コミット、未コミット変更の有無、ビルド環境、アプリ ID、版、SDK、権限、同梱通知、ファイルサイズ、SHA-256、署名証明書、試験結果と免除判断を一つの版固有の成果物記録に対応付けます。日々の試験件数をこの手順へ追記しません。署名済み AAB、鍵、パスワード、入力本文を Git に追加しません。

## 公開候補の検査

1. ソースと依存関係を固定し、必要な試験、lint、APK／AAB の構築を行います。スキップ、失敗、未完了を成功として数えません。
2. APK／AAB の ZIP 整合性、アプリ ID、版、minSdk／targetSdk、権限、debug 専用サービスの除外を確認します。辞書取得には `INTERNET` 権限を使用します。初期設定で S／L がともにない場合は S を自動取得し、追加辞書と更新は利用者の操作によります。取得後の変換はオフラインで動作します。
3. ルートの MIT 本文とアプリ同梱の本文、第三者通知・Apache・ICU・GPL の本文、外部辞書とアイコンの説明が公開候補に正しく収録されていることを確認します。[ライセンスの適用範囲](licenses.md)を参照してください。依存物や同梱データを変更した場合は通知を再確認します。
4. 署名済み AAB の署名者証明書をアップロード鍵の公開証明書と照合します。初回 Console 登録時は Google 生成のアプリ署名鍵が選択されたことを確認します。Console のアップロード証明書とアプリ署名証明書は別物として記録します。
5. Play 経由で導入した版について IME の有効化・選択、初期辞書の取得／失敗時の復旧、画面・物理入力、学習設定、辞書バックアップ・復元、ポリシーのリンクを確認します。対象端末、OS、配列、接続方法、結果を版固有の判定に記録します。エミュレーターの成功を実機・他アプリの保証へ読み替えません。
6. Console の実際の質問と公開 AAB、[プライバシーポリシー](site/privacy-policy.html)、掲載文、素材を照合します。新規の個人開発者アカウントに適用されるクローズドテストは、[公式案内](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)に従い、12 人以上の連続 14 日間のオプトインと、その後の本番アクセス申請を予定します。人数・日数だけで自動承認されません。実際のアカウントと Console の要求を提出時に確認します。公開操作には別の最終判断を要します。

特定版の承認・免除は、その版を識別したリリース記録に限定します。既存の所有者受入では、Xiaomi Pad 8 による物理キーボード・性能確認とエミュレーターでの UI／Emacs／IME 切替確認を採用し、実際のメッセージ送信、追加のブラウザー URL 確認、Pixel 7 での同内容の再試験を必須にしていません。これらは試験範囲の判断であり、未実施事項を実施済みと表示するものではありません。新しい版の変更がその判断に影響する場合は再評価します。

## 失敗時と更新時

検査に失敗した成果物は提出せず、原因の修正後に対象版の試験と同梱内容を再確認します。辞書更新が失敗・中止された場合は旧辞書を利用できることを確認します。現行 SQLite は版 5、完全バックアップの書き出しは版 3 です。旧版 SQLite からの移行では、既存辞書の取得元を未設定、過去の候補使用履歴を空として扱います。バックアップ版 1・2 は読込みに対応し、版 1 の取得元は未設定、版 1・2 の候補使用履歴はなしとして復元します。版 3 バックアップは旧版アプリで復元できません。形式と原子的な復元条件は[完全バックアップ設計](complete-backup-design.md)、更新時の確認は[更新検証](upgrade-validation.md)に従います。
