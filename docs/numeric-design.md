本書の「確認済み」は参照版の互換挙動、「Android 方針」はこのアプリで安全に

根拠は `docs/requirements.md` の F11、`docs/compatibility.md` の K16、固定参照版
の `doc/skk.texi`「数値変換」、`skk-num.el`、`skk-vars.el` です。参照版のコードや

## 検索キーと数値列

数値変換が有効なとき、読みの ASCII 数字または全角数字の連続部分を左から
`#` 一文字へ置き換えて辞書を検索します。同時に、置換前の数値列を ASCII
数字へ正規化して同じ順序で保持します。数字に挟まれた ASCII のカンマは先に
除くため、`みつもり１２,３４０えん` は検索キー `みつもり#えん`、数値列
`["12340"]` になります。符号は数値列に含めません。

小数を一つの数値とする設定は参照版でも既定で無効です。Android の初期実装も
無効とし、例えば abbrev の `v1.25` は検索キー `v#.#`、数値列
`["1", "25"]` とします。設定追加は K16 の完了条件に含めません。

候補本文中の `#` とそれに連続する一文字以上の ASCII 数字を、一つの数値
マーカーとして最長一致で読みます。形式番号の先頭のゼロは無視するため、`#01`
は `#1`、`#0003` は `#3`、`#000` は `#0` と同じです。マーカーは左から
同じ位置の数値列を一つずつ消費します。候補の通常文字はそのまま残します。
例えば読み `れいわ6ねん11がつ`、候補 `令和#3年#1月` は
`令和六年１１月` になります。辞書候補の順と注釈は維持し、展開は候補本文に
だけ適用します。

参照版は、候補内のマーカーが数値列より少ない場合、使わなかった数値列を無視
します。マーカーが多い場合は、数値列が尽きた位置以降を未展開のまま残します。
Android 方針では前者を互換挙動として受け入れ、後者は不完全な候補として候補
単位で除外します。数値列とマーカーの対応をずらしたり、最後の数値を再利用
したりしません。

## 形式ごとの結果

次を K16 の固定形式とします。

| 形式 | 結果 | 独立例 |
| --- | --- | --- |
| `#0` | 正規化済み ASCII 数字をそのまま使う | `だい12` と `第#0` → `第12` |
| `#1` | 各桁を全角数字にする | `2048` → `２０４８` |
| `#2` | 各桁を `〇一二三四五六七八九` で表す | `2048` → `二〇四八` |
| `#3` | `十、百、千、万、億、兆、京` を使う通常の漢数字にする | `2048` → `二千四十八` |
| `#4` | 数値列そのものを見出し語として辞書を再検索する | 下記参照 |
| `#5` | `零、壱、弐、参、伍、拾、阡、萬` などを使う大字にする | `2048` → `弐阡四拾八` |
| `#8` | 右から三桁ごとに ASCII カンマを入れる | `7654321` → `7,654,321` |
| `#9` | 二桁を「全角数字一字 + 漢数字一字」にする | `73` → `７三` |

`#3` と `#5` はゼロだけならそれぞれ `〇` と `零` です。上位のゼロは表示せず、
`#3` の `0012` は `十二` になります。参照版は `#3` と `#5` を 20 桁まで
扱い、それを超える値をエラーにします。`#9` はちょうど二桁だけが有効です。
`#8` は数値として扱うため先頭のゼロを保持せず、`001234` は `1,234` です。

同じ展開結果が複数候補から生じた場合は、最初の候補位置を保って一つにまとめ
ます。特に一桁では `#2` と `#3` が同じ結果になるため、辞書で先に現れた方だけ
を表示します。Android 方針では注釈を候補の同一性に含めず、先に採用した候補の
注釈を使います。

## `#4` の辞書再検索

`#4` は対応する数値列を、送りなし・abbrev ではない通常の見出し語として複合
辞書へ再検索します。検索結果が一件ならその候補本文を挿入し、複数なら元の候補
位置で同じ順序の複数候補へ展開します。複数の `#4` がある場合は、各検索結果の
直積をマーカー順に生成します。例えば次の独立データでは、`こーど314` の候補は
`地域:北区`、`地域:中央区` の順です。

```text
こーど# /地域:#4/
314 /北区/中央区/
```

再検索で候補がなければ、参照版と同じく元の ASCII 数字を挿入します。再検索中
は数値変換を無効にします。したがって `#4` の検索結果にさらに数値マーカーが
含まれても再帰評価せず、候補本文としてそのまま挿入します。Android 方針では
任意の式や関数を実行する経路を設けず、外側候補の注釈と送り条件を維持して、
再検索候補の本文だけを置換値として使います。

Android 方針として、一つの読みの数値列を 16 個、一つの `#4` 再検索結果を
256 件、一つの元候補から作る直積を 256 件、生成した候補本文の UTF-16 code
unit 合計を 65,536 までに制限します。再検索深度は上記の一段だけです。どれかの
上限を超えた元候補は部分的に表示せず候補単位で除外し、他の辞書候補は検索を
続けます。上限値は実機測定前の安全側の初期値であり、変更する場合は同じ境界
試験とメモリ測定を更新します。

## 未対応表現と失敗境界

対応する形式番号は 0〜5、8、9 だけです。参照版は形式と処理関数の対応を設定で
変更でき、未対応番号の安定した利用者向け挙動を規定していません。Android では
`#6`、`#7`、`#10` のように、先頭のゼロを除いた形式番号が対応外になる候補、
および数値列が足りない候補を候補単位で除外します。`#10` を `#1` と文字 `0`
には分割しません。巨大な形式番号は整数へ変換せず、先頭のゼロを読み飛ばした
残りが一桁の対応番号かどうかだけで判定します。例外、通知、ログへ候補本文や
読みを含めません。`#x` や末尾の `#` のように数字が続かない文字列は通常の
候補本文として保持します。

辞書形式層で許可する式は既存の安全な限定 `concat` だけです。取り込み時に拒否
された式を数値変換で再解釈せず、実行もしません。妥当な辞書の一候補だけが数値
展開に失敗した場合は辞書全体や同じ検索の他候補を失敗させません。全候補が除外
された場合は「候補なし」と区別できる一般化した数値展開失敗を返し、元の読みを
保持します。

## 受入試験

- 上表の八形式を別々に試し、`#0` の先頭ゼロ保持、`#3`・`#5` のゼロと 20 桁
  境界、`#8` の先頭ゼロ除去、`#9` の二桁制約も固定します。
- ASCII／全角数字、数字間カンマ、小数点既定無効、複数数値列の左からの対応を
  検証します。候補より数値列が多い場合と少ない場合を分けます。
- `#4` の 0 件、1 件、複数件、複数マーカーの直積、辞書優先順、重複、深度停止、
  件数上限を検証します。内側候補のマーカーや式を評価しないことも確認します。
- 未対応番号を含む候補だけが除外され、他候補、読み、候補順、注釈を壊さず、
  エラー情報に読みや候補本文を含めないことを検証します。
