# ストレージを正本とする辞書検索と有限キャッシュ

2026-09-19 の追加要件です。辞書を全件メモリーへ公開する旧設計より、本書の契約を優先します。

## 目的

辞書の件数が増えても、起動時に全候補を読み込まず入力を開始できるようにします。SQLiteに保存した辞書を正本とし、メモリー上のMapは直近に参照したレコードの有限キャッシュとしてのみ使用します。

## 必須の動作

- 通常起動では辞書の設定・世代などの管理情報だけを準備し、全候補や全見出し一覧を走査・展開しません。
- 通常検索は必要な見出しのレコードを索引経由で取得します。補完も前方一致範囲を件数・処理量の上限内で取得します。
- キャッシュには件数の上限を設け、直近に参照していないデータを追い出します。見つからなかった検索の記録にも上限を適用します。大量候補・長い注釈で件数上限だけを迂回しないよう、保持量にも制限を設けます。
- キャッシュを空にしても、プロセスが終了しても、保存済み辞書から同じ結果を再取得できます。キャッシュの内容だけを正本として扱いません。
- 学習では対象見出しの候補順・必要な管理情報だけを永続化します。全候補を再読込したり、他の見出しを再保存したりしません。
- 辞書更新・並べ替え・抑止・学習・復元に応じて古いキャッシュを失効させ、違う世代の候補と由来を混ぜません。
- 既に表示した候補の順序とラベルは選択中に変えません。古い選択からの削除や復元前の学習は既存の世代・許可検証を維持します。
- ディスクや辞書管理操作の待機でキー配送を長時間止めません。入力先の変更や取消後に届く検索結果は本文へ適用しません。
- インポート・エクスポート・完全バックアップなどの明示的な全件処理は通常の起動・検索・学習から分離します。

## キャッシュの上限と操作中の結果

常設LRUは最大128検索、合計4,096候補・抑止レコード、合計524,288 UTF-16文字を上限とします。未登録見出しの検索結果と補完結果も同じ上限へ含めます。いずれかを超える前に最近使われていない結果を追い出します。この文字数はオブジェクトを含めた総バイト数の保証ではありません。

一見出しだけで上限を超える正当な辞書レコードは、変換不能にはせず常設キャッシュへ入れません。数値変換の参照先を含め、一操作の再試行中だけ結果を保持し、操作の完了・失敗・取消・入力先変更で解放します。表示中の候補列と操作中の作業領域はキャッシュとは別です。辞書全体を保持するためには使いません。

学習を含む保存後は管理情報を更新し、旧世代のキャッシュを失効させます。新世代の候補を全件読み直すことはありません。起動・学習での全件読み出しが復活しないことを、読み込み回数と実SQLiteの試験で確認します。

入力スレッドではキャッシュだけを参照し、未取得の場合は操作状態を巻き戻して読み込みを要求します。読み込みはワーカーで行い、完了後に同じ操作を再実行します。既に受け取ったキーは順序を保って処理します。入力キューの件数だけを理由に受理済み文字を捨てません。

## 補完の列挙順

辞書間は個人辞書・有効なシステム辞書の設定順を優先し、同一辞書の見出しはUnicodeコードポイント順で列挙します。前方一致にはSQLiteの索引を使用し、並べ替えのための全件読み出しは行いません。旧メモリー実装のUTF-16順とは、同じ接頭辞の後に補助文字と上位BMP文字が混在する場合に順序が変わります。通常のかな・ASCII見出しの順序は変わりません。小規模な組み込み辞書にも同じ順序を適用します。

## 受入検証

1. 大きさの異なる保存済み辞書を起動し、通常初期化が候補全件を読まないことを確認します。
2. 同一検索のキャッシュヒット、上限を超える異なる検索の追い出し、追い出し後の再取得、未登録語の連続検索を確認します。
3. 学習前後で対象外の行が変更されず、全件読み込みも発生しないことを確認します。保存失敗と禁止時は永続化しません。
4. 個人優先、システム辞書順、送り条件、注釈、抑止、数値変換、補完の結果を既存仕様と比較します。
5. 更新・削除・並べ替え・復元・プロセス再起動後に、キャッシュの古い値が結果へ混ざらないことを確認します。
6. 実IMEで未キャッシュの変換と候補確定直後の再変換、取消・入力欄切替を検証します。
7. 初期化・初回検索・キャッシュヒット・学習の所要時間と保持量を別々に記録します。エミュレーター測定を実機の合格値として扱いません。

## 調査上の訂正

旧実装も学習時のSQL書き込みは一見出しに限定していました。問題は、その保存後に全辞書を読み直し、メモリー上の索引を再構築していたことです。全件読み直しと全件書き直しを区別して検証します。
