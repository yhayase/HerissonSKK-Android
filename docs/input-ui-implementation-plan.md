# 入力UI再設計の実装計画

## 目的と状態

[合意事項](input-ui-redesign.md)を実装可能な単位へ分け、物理キーボードでは下部領域を占有しないポップアップ、画面キーボードでは候補をタップで確定できる専用操作体系を実現します。本書はコード調査に基づく計画と実装の経過です。計画承認後に実装・自動検証を開始しました。

合意済みの操作を正本とし、以下の内部構造・試作時の初期値・境界条件は実装のための提案と区別します。既存の作業ツリーには先行修正があるため、その変更を保持して差分を追加します。

## 現行コードとの主な差

| 対象 | 現在 | 必要な変更 |
| --- | --- | --- |
| 物理側の表示 | `SkkInputMethodService`は常に入力ビューを表示し、`TouchKeyboardView`は文字キーを隠しても候補・IME切替行を残します | 下部の予約領域をなくし、IMEに属する窓へモード・候補・登録を表示します |
| 座標 | `CursorAnchorMonitor`と`InlineCandidateAnnotationPopup`は単独候補の注釈だけを対象にします | 通常のモード切替・候補・登録へ拡張し、座標がない場合も決めた場所へ表示します |
| タッチ入力 | 物理キーと多くのコア操作・候補選択状態を共有します | 予測、ページ単位の通常変換、先頭確定、タッチ専用取消・登録を明確に分けます |
| キー | ボタンのクリックと一回Shiftが中心です | 合意した4段配列・2記号面、上下フリック、ガイド、複数指Shiftを実装します |
| 候補表示 | 候補本文に有界プレビューと省略、固定件数中心のページがあります | 本文は省略せず実測幅で収容し、注釈だけ省略します。長押しをタップ確定から分離します |
| 状態保持 | 構成変更・機器リセットで`preserveText()`、入力開始で旧セッションを閉じます | 表示だけの再生成と入力接続の終了を区別します。読み・再帰登録を表示切替だけで破棄しません |
| 予測 | 現行の補完は読みを補う機能であり、候補を読み横断の利用順で出す機能ではありません | 専用の検索・使用履歴・候補確定経路と永続化を追加します |

## 最初に確認する技術条件

### 下部領域ゼロのポップアップ

既存のIME所有子窓を出発点に、非フォーカス取得の表示窓と入力ビューのinsetsを分離します。通常のアプリへのオーバーレイ権限を追加する方針ではありません。AndroidはIMEの予約高さとタッチ領域を別に報告するAPIを持ちますが、これだけで全端末で成立すると断定しません。API 26/35の専用エミュレーターで最初に小さな試作を検証します。[InputMethodService.Insets](https://developer.android.com/reference/android/inputmethodservice/InputMethodService.Insets)

合格条件は、物理側のモード・候補・登録の全状態で、IME非表示時と比較した入力先の利用可能高さが減らないこと、ポップアップ外のタッチを奪わないこと、候補タップと長押しが動くこと、フォーカスを別欄へ移さないことです。システムのナビゲーション領域とIMEによる追加占有を区別します。`onComputeInsets`だけでなく入力先に配信されるIMEのinsetsと画面実測を比較します。

座標は現在の接続に対する監視結果と行列から計算し、無効値・見えないカーソル・古い通知を拒否します。未確定文字がないモード切替でも使えるよう、既存の「候補本文とcomposingTextが一致する場合だけ」という条件をそのまま流用しません。取得拒否・応答なし・スクロールによる失効では固定位置へ切り替えます。監視はキー配送から分離します。[CursorAnchorInfo](https://developer.android.com/reference/android/view/inputmethod/CursorAnchorInfo)、[InputConnection](https://developer.android.com/reference/android/view/inputmethod/InputConnection#requestCursorUpdates(int))

試作が不成立の場合は制約を記録して設計へ戻します。下部領域を残す旧表示へ黙って置き換え、要件を達成したことにはしません。

### 同じ入力欄の状態保持

表示ビューの再生成だけなら、コアの状態を維持して描画し直します。セッション世代と表示世代を分離し、表示変更で旧タップは無効にしても、登録内容や有効な保存処理を消しません。

入力接続の再開始は別扱いです。Androidの`restarting=true`は同じ編集欄の再開始を示しますが、アプリによる本文変更でも発生します。これだけを根拠に旧状態を再挿入しません。実際の接続ライフサイクル、選択・未確定範囲・本文の整合性を確認できる範囲で保持します。確認できない場合に別欄へ持ち込まない境界を先に定義します。[InputMethodService.onStartInput](https://developer.android.com/reference/android/inputmethodservice/InputMethodService#onStartInput(android.view.inputmethod.EditorInfo,%20boolean))

API 35の実測に基づき、同じ入力欄の構成変更に限る再接続契約を実装しました。1秒以内の構成変更世代、bindingと入力属性、保存済みの完全なスナップショットと新接続の本文・絶対選択位置を照合し、`setComposingRegion`だけで未確定範囲を再設定します。本文の再挿入はしません。古い編集処理は接続世代で失効させ、保存処理には同じセッションと操作トークンを維持します。スナップショットの取得不能・部分取得・16,384文字超過や内容不一致では移管しません。[独立レビューと制約](reviews/input-ui-20260920.md)を参照してください。プロセス終了後の復元は今回の保持に含めません。

## 実装時の共通契約

- 予測リストと通常変換リストを別の状態として表現します。通常変換の候補位置・ページ・選択を予測へ流用しません。画面表示には見出し語を使い、内部の仮選択候補を入力先へ描画しません。
- タップ・長押し・右下キーは、候補種別（予測／通常変換／読みそのまま）、元候補の識別情報、読み・問い合わせの版、表示版、入力セッション、辞書結果の版、登録フレームのID・版・階層を照合します。非同期応答が来ても、指を置いた候補を別候補へすり替えて確定しません。
- 長押し後の指離しはクリックにしません。ガイド表示、注釈全文、ページ移動、画面切替、ジェスチャー取消で押下状態を残しません。
- 文字入力とIME操作を分離します。候補中のxは前ページ、Shift・上フリックによるXなどはそのまま同一操作へ潰さず、既存のSKK意味と区別します。
- 空の登録・未消化ローマ字は既存コアの終端・取消契約を基準にします。未確定入力がある間に検索・送信へ抜けないことを試験で固定します。
- 物理キーのC-j／Enterと画面右下キーは別の操作経路にします。設定「Enterで確定のみ」がタッチ確定の意味を変えないようにします。
- 通常変換のページは実測幅・文字倍率に応じて候補の連続範囲として計算します。ページを進めて戻ると同じ候補へ戻れ、候補が欠落・重複しないことを検証します。予測はページなしで表示可能な先頭範囲だけを出します。
- 縦方向まで超える極端な長文は全文を巨大なViewへ一括複製せず、有限の表示窓内で欠落なく読める構成を試作します。これは本文の省略や候補一覧の展開機能を再導入する意味ではありません。
- 画面キーボードを表示する既存設定と物理機器の有無から表示方式を決めます。物理キーを1打鍵するたびに表示を往復させません。物理接続中でも画面キーボードを表示する設定の扱いを統合試験へ含めます。

## 予測・使用履歴・移行の設計案

現行の辞書学習は、読みごとの個人候補を先頭へ移す処理です。これとは別に、候補の確定順を保存する小さな使用履歴を追加します。辞書本文全体の複製は作りません。通常変換の既存の学習順は維持します。

### 検索と候補の識別

読み補完の`complete()`は完全一致を除外して読みを返すため、流用せず候補を返す`predict()`相当の契約を追加します。完全一致も前方一致に含め、有効な辞書・優先順・候補の非表示指定を反映します。

結果は確定文字列、元の完全な読みと変換条件、辞書候補の識別情報（辞書上の読み・元の語幹またはテンプレート・送り条件など）、注釈、使用順を保持し、画面には読みを出しません。重複は最終的に確定する文字列でまとめます。代表は最新の使用履歴を持つ一致候補、未使用なら読み・辞書優先順・候補順で決め、注釈は代表の読みについて既存の辞書解決規則に従わせる案です。タップ後に入力中の短い読みで再検索・再学習せず、描画時の代表候補を確定します。

使用履歴だけから候補を生成せず、現在利用可能な辞書候補と結び付けます。送りありの語幹や数値変換のテンプレートと、確定文字列を同一視しません。既存の通常学習用の元候補と、予測順位用の確定結果を分け、両者の対応を実装前の契約テストで固定します。前方一致で使える送り条件・abbrev・数値候補の対象範囲を、その対応表に含めます。

候補の履歴順が確定する前に、任意の先頭N行で検索を打ち切って「最新順」とは扱いません。順位付けと重複集約を踏まえて取得し、結果件数・読込文字量・検索作業量を別々に制限します。短い読みで作業上限に達した場合は部分結果として明示し、全検索が完了して候補がゼロだった場合と区別します。上限到達・検索失敗・処理中を候補なしと読み替えて、読みそのままの候補を確定させません。未走査部分により順位が変わる可能性がある部分結果も、正しい最新順として確定可能にはしません。表示上限までの順位を証明できた正常結果、検索完了でゼロだった結果、順位・空の判定ができない結果を別の型で扱い、未判定を空としてキャッシュしません。旧結果の確定も防ぎ、Spaceによる通常変換への移行は残します。辞書全件をUIスレッドへ読み込みません。試験辞書のフォールバックと実辞書を混ぜる場合も、未使用候補の読み順を全体で守ります。

### 保存と障害

壁時計の時刻ではなく、DB内の単調な確定順を使用します。候補確定が入力先に受け入れられた後、現在の直列保存経路で通常学習と履歴を同じトランザクションに保存する案です。候補表示・ページ移動・拒否されたcommitTextでは履歴を更新しません。保存失敗で入力先へ確定済みの本文を再挿入したり取り消したりしません。

保護欄では予測・履歴更新を行いません。学習禁止・個人辞書保存オフの場合の書込禁止は既存のポリシーに従います。書込禁止から直ちに「既存の個人辞書や履歴も読めない」と解釈して、通常変換の既存仕様を変えることはしません。復元後やセッション終了後の遅延書込を現在の世代・保存許可で失効させます。

元候補を辞書から削除・非表示にしたときは、その候補が履歴だけから再表示されないことを保証します。同じ候補が別の有効な辞書にも残る場合と、完全に削除された場合を区別します。

### DBとバックアップ

- DB v4からv5へ使用履歴テーブルと単調な順序カウンターを追加しました。旧辞書は未使用履歴として保持し、存在しない過去の利用順を推定しません。v1〜v3からの既存アップグレードもv5まで到達させます。
- 完全バックアップは使用履歴を含むv3としました。v1/v2は従来どおり読み込み、履歴なしとして復元します。通常のSKK辞書エクスポートは従来形式を保ち、予測履歴を混ぜません。
- 辞書・非表示指定・履歴の復元を一つの置換として扱い、件数・重複・文字列・順序の不正で途中まで適用しません。旧バックアップを復元した後に、新版の古い履歴だけ残すことも避けます。
- 使用履歴は自動削除しません。完全バックアップの履歴レコード上限は10万件、ファイル全体は256 MiBです。上限超過では一部の履歴を黙って捨てず失敗として扱います。検索時の候補・履歴・非表示指定はそれぞれ件数と文字量を制限し、未走査部分が残る場合は順位未確定とします。10万履歴での実機性能を検証済みとはしていません。

予測結果のキャッシュは既存の有限キャッシュへ統合し、辞書変更だけでなく履歴更新でも順位が更新されるよう版を管理します。更新前の表示を押している間の確定対象は、表示版の契約で固定します。

### 状態間の境界

- 未確定入力を保持したままのモード切替案は撤回しました。画面の明示的なモード選択は確定後に切り替え、確定不能な状態では無効化します。具体的な状態別の確定対象は[合意事項](input-ui-redesign.md)に記録します。メニューを開いただけでは確定しません。物理q/l/Lは見出し語・インライン候補・候補メニューの状態別契約を参照例と照合し、候補選択キーをモード操作に奪いません。
- 再帰登録内の候補確定は、現在のコアでは通常学習の対象外です。登録内容を取り消しても履歴だけ残すかという違いがあるため、全入力先への候補確定と同じ書込フックへ無条件に混ぜません。今回は従来どおり登録内の確定を履歴更新の対象外とします。
- 通常変換の表示を物理／画面間で切り替える場合は、候補集合と元の読みを保持し、物理側の選択候補を含む画面側ページへ移します。画面側からは表示ページ先頭を物理側の選択候補に対応させ、確定自体はしません。この対応をセッション試験で確認しています。
- xで通常変換の先頭ページより戻る場合は、既存SKKどおり読みへ戻します。左三角は合意どおり無効とします。このキー境界を回帰試験に含めます。

## 初期値と細部の進め方

モード表示時間は800 ms、長押しガイドは400 msを試作開始値とします。フリック閾値は端末のtouch slopとキー寸法から決め、固定pxへ依存させません。値は確定仕様ではなく、誤操作・視認性の検証で調整します。三角ボタンは表示を小さくしつつ隣接候補と当たり判定を重ねません。本文は折り返し、注釈は行末省略、長押しの全文は明示的に閉じられる構成から試作します。

| 層 | 検証する内容 |

| 実SQLite・バックアップ | DB v1〜v4からv5、バックアップv1/v2互換とv3往復、辞書更新・無効化・削除・復元と履歴、途中失敗の原子性、送り・数値の元候補と確定結果、前方一致の順位・部分結果・メモリ使用 |
| API 26/35エミュレーター | 入力先の高さ、タッチの透過、座標あり／なし／失効、縦横・狭幅・文字倍率、長文と注釈、再帰登録、IME切替、物理／画面切替、別欄と保護欄への遷移 |
| 既存の自動ゲート | JVM・Android単体、ホスト試験、lint、APKとmanifest、物理Enterと編集キーを含む回帰 |

性能受入全体はやり直しません。ただし新しい前方一致検索の1文字読み・多数候補・連続入力を測定し、UIスレッドでの辞書走査や全辞書の無制限読込がないことを確認します。物理キーボード操作のPixel 7での重複受入、メッセージ送信、会話切替、ブラウザーのアドレス欄の再確認は依頼しません。
