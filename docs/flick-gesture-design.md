# フリック判定の設計

## 目的と変更理由

タップ時の指の揺れや、離す瞬間の座標のずれで、QWERTYの大文字・区切り・数字・記号が誤入力される問題を解消します。テンキーも同じ基準で見直します。

従来の開始距離は、QWERTYでは設定上のキー高さの22%、テンキーでは表示キー短辺の20%でした。Pixel 7では約8〜13dp、約1.3〜2.1mmになり得ます。表示を縮めると判定も敏感になること、離す座標だけでフリックや修飾が発動することを問題とします。キー寸法に対する割合はAndroidの標準仕様ではありません。

Androidの `ViewConfiguration.scaledTouchSlop` は一般的な移動許容距離です。かな入力専用の開始距離ではありません。また、速度を条件にするflingを必須にせず、速さや押下時間を四方向の選択条件にしません。

## 共通の認識と選択の分離

共通の認識器でタップ、中央、上下左右、未確定、取消を扱います。文字キーは方向から文字を選びます。配列切替キーは方向に加えてガイド上の位置・距離から地球儀や歯車を選びます。フリック開始の感度と、候補の配置寸法を混同しません。

| 項目 | 初期仕様 |
| --- | --- |
| フリック開始距離 | `max(24dp, scaledTouchSlop)` |
| 中央への復帰距離 | 16dp。開始距離との間は前の確定領域を維持します。 |
| 明確な方向 | 大きい軸の移動量が、もう一方の1.2倍以上 |
| 入力取消距離 | 始点から250dp以上。Pixel 7では約40mmです。 |
| 距離の基準 | 最初に触れた位置からの直線距離。経路長は加算しません。 |

24dp・16dp・250dpはアプリの試作仕様値です。OS標準値や実測済みの最適値とは扱いません。キー寸法・配列・縦横の向きによって縮めず、実機評価で調整します。OSのtouchSlopが大きい場合でも、中央復帰距離は開始距離より内側に保ちます。

初めは中央を選びます。開始距離以上で方向条件を満たせば、その方向を確定します。開始距離以上でも斜めの曖昧な範囲では初回の方向確定を保留し、そのまま離した場合は取消です。方向が確定した後は、接触中の移動によって別方向や中央へ変更できます。最初の方向を固定しません。16dpと開始距離の間、および方向の曖昧な範囲では直前の確定領域を保持します。

方向・中央の選択は表示と内部判定で共有します。中央へ戻った文字キーは通常の文字を選び、テンキーでは現在の修飾を適用します。QWERTYは上下だけを出力へ割り当て、左右や割当のない方向をタップへ戻さず取消にします。

## 移動と離す操作

`MOVE`と、その履歴にある接触中の座標を時刻順に処理します。`UP`にまとめて届いた接触中の履歴も処理します。観測点間の直線で通過する確定領域は順番に扱い、イベントが細かく分割されたかどうかで結果を変えません。観測できない曲がりや往復は推測しません。

最後の`UP`座標だけでは、フリックの新規認識、方向変更、往復修飾、ホールド有効化を行いません。最後の接触中の選択を一度だけ確定します。接触中に方向が確定しておらず、`UP`だけが開始距離以上へ飛んだ場合は取消にします。曖昧な高速操作を誤フリックとして出力しない方針です。

250dp以上への移動は、`UP`を含むすべての観測座標で判定します。一度成立したらその接触は取消のままにし、戻っても復活させません。文字も機能も実行せず、ガイドに「×」などで取消を示します。`ACTION_CANCEL`、指の識別を失った場合、入力欄変更、キーの再構築・非表示・破棄でも未実行の操作を取り消します。テンキーと配列切替キーでは追加の指でも取り消します。QWERTYの既存のShift同時押しは維持します。

## IMEウィンドウ外の座標

一部のAndroidでは、`SoftInputWindow`がIMEウィンドウ外の座標を端へ丸め、履歴も落としてからViewへ渡します。エミュレータでは260dp上へ送った点が約71dpの移動として届き、View内の判定だけでは250dpの取消を認識できませんでした。上端行や小さいキーでは、通常の24dpフリックもウィンドウ端で制限され得ます。これは距離定数を小さくする理由にはしません。

公開APIの`Window.Callback`で、表示中の文字キー領域から始まった接触だけを所有し、元のイベントを`Window.superDispatchTouchEvent`へ一度渡します。これにより既存のDialogの座標丸めを通さず、通常のView配信で始点からの移動を判定できます。ほかの領域・接触・コールバックは元の処理へ委譲します。UP/CANCELで所有を解放し、入力終了・非表示・ウィンドウ置換・破棄でも残しません。内部のキー再構築ではキー側の取消を維持し、その接触の途中から新しい入力を始めません。

隠しAPI、ウィンドウ拡大、アプリ表示領域の縮小には依存しません。イベントを二重に配信せず、診断用のタッチ座標ログを製品コードに残しません。ウィンドウ外へ伸ばして戻る実IME検証でも取消を確認します。

## テンキーの往復修飾

確定領域Aから中央または別の確定領域へ移ったとき、出てきたAの修飾を適用します。中央を通る必要はなく、斜めの移動も使えます。曖昧な境界を出ただけでは適用せず、移動先領域の確定を待ちます。

| 出てきた方向 | かな面の修飾 |
| --- | --- |
| 左 | 濁点 |
| 右 | は行は半濁点、それ以外は小書き |
| 上 | そのキーの数字 |
| 下 | 修飾解除 |

修飾は一種類だけ保持します。現在の修飾と同じ方向から再び出れば解除し、異なる方向から出れば置き換えます。中央から出ること自体は修飾を発生させません。既存の英字面などの割当も、この領域遷移規則を使います。

「か」で左→中央なら「が」、そこから上へ移動して離せば「ぐ」です。上へ入った時点では数字にならず、上から別領域へ出た時点で数字修飾に置き換わります。

## テンキーのホールド境界

押下からではなく、静止を認めた位置から設定時間を測ります。静止許容半径はOSのtouchSlopとし、キー寸法には比例させません。固定した静止基準位置からの変位が許容半径を超えた場合、確定領域が変わった場合、入力文字が変わった場合は、現在位置から時間を数え直します。小さな揺れの経路長を足し合わせません。未確定領域や出力文字がない場所では有効化しません。

ホールド時間は100〜1000ms、10ms刻み、初期値350msです。設定画面に現在値をmsで示すスライダーを置き、「保存」で反映します。既存の250・350・500msはそのまま引き継ぎます。シフトキーの長押しなど、別の長押し操作の時間には適用しません。

ホールド有効化時に位置と最終出力文字を記録し、次のいずれかで区切り指定を解除します。

- 修飾を含めた最終出力文字が変わった場合。
- 有効化位置から約1キー分移動した場合。横はキー幅、縦はキー高さで正規化した距離で判定します。

方向や内部状態が変わっても、出力文字が同じで移動量も小さければ維持します。キー寸法を使うのはこの解除条件であり、フリック開始条件ではありません。離す座標だけでも、大きな移動による解除は行います。小さな離し際のずれは維持します。

解除後は現在位置から静止時間を測り直し、古い経過時間ですぐに再有効化しません。設定時間後に再び有効化できます。全体取消を優先し、一回の確定領域遷移ごとに、方向と修飾の更新→最終出力文字→ホールド解除を一まとまりとして処理します。方向だけ・修飾だけを更新したプログラム上の途中状態で解除しません。一つのMOVE線分に複数の確定領域遷移があれば、それぞれの実際の選択文字を順番に判定します。途中の確定領域で文字が変われば、その後同じ文字に戻ってもホールドは解除します。イベントの分割数によってホールド維持が変わらないようにします。

有効化はガイド十字全体の外輪郭を太く濃くして示し、振動一回を送ります。解除は通常輪郭へ戻し、短い振動を二回送ります。再有効化時も一回振動します。端末の対応と既存の振動設定に従います。

## 配列切替キー

共通の開始・取消・離す座標の扱いを使用します。中央は配列切替、右は地球儀、その右は歯車、テンキー側の上は形状調整です。24dpは開始の最低距離であり、各候補の境界ではありません。地球儀と歯車はガイドの配置寸法によって選び、候補間のヒステリシスと引き返して選び直す操作を維持します。離した時点の選択だけを実行します。

配列切替キーで一度フリックして中央へ戻った場合は、意図しない配列切替を避けるため取消とします。文字キーの中央選択とは出力への対応だけが異なり、接触の認識自体は共通です。配列切替、IME切替、設定、調整は入力中に先行実行しません。

## 検証方針

- 小さな揺れ、離す座標だけのずれ、斜めの未確定、速い操作、移動履歴を持つ操作を分けて検証します。
- 上下左右、中央復帰、境界付近の揺れ、異なるキー寸法・密度・縦横画面で同じ距離規則になることを確認します。
- 上限超過と復帰、取消後のタイマー、追加の指、非表示・再構築、古いキーへのイベントを確認します。
- 往復の適用・置換・解除、疎なイベントと細かなイベントの結果一致を確認します。
- ホールドの静止開始、移動・文字変更による測り直し、解除・再有効化・振動、離す際の小移動を確認します。
- QWERTYの左右取消、配列切替キーの複数候補、保護入力、既存の読み・候補・登録の維持を確認します。
- 実IMEでタップの誤フリック抑制と、意図した四方向・往復・ホールド・機能操作を確認します。数値の快適さは実機評価で確かめます。
