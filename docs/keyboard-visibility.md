# スクリーンキーボードの表示条件

## 表示する場合

入力先が文字入力を受け付け、Androidまたは入力先アプリからキーボードの表示要求を受けた場合に表示します。入力欄へのタップ、アプリが入力開始時に行う表示要求などが該当します。パスワード・数値・電話番号の入力欄も対象です。物理キーボード接続時の文字キー表示は既存の表示設定に従います。

入力接続が存在するだけでは表示しません。入力開始、カーソル通知、候補や辞書状態の更新、設定変更は、それ自体をスクリーンキーボードの表示要求として扱いません。

## 非表示を維持する場合

- 利用者が戻る操作などで隠した後は、新しい表示要求を受けるまで隠した状態を維持します。
- 通知・クイック設定の開閉、画面の再描画だけでは再表示しません。
- ホーム画面や入力欄のない全画面コンテンツでは表示しません。入力属性がない接続や`TYPE_NULL`の接続も、自動表示の対象にしません。
- 入力先との接続が終了した場合は、候補・モードのポップアップも破棄します。

動画アプリやホームアプリでも、検索欄など実際の入力欄を操作した場合は通常の表示条件を適用します。アプリ名や全画面かどうかだけで禁止しません。

## 物理キーボードとの分離

物理キーボードのモード・候補・登録ポップアップ用の窓と、スクリーンキーボードの表示要求を区別します。物理入力のポップアップが必要でも、文字キー画面を表示する理由にはしません。文字キーの表示要求を持たない専用の窓を使い、下部の予約領域をゼロにする契約を維持します。物理側の表示を隠した後は、通知や描画更新だけで戻さず、次の物理入力または新しい入力先で必要な表示を再開します。Emacs風キー処理もスクリーンキーボードの表示を要求しません。

## 参照と検証

Androidの[InputMethodService](https://developer.android.com/reference/android/inputmethodservice/InputMethodService)の入力接続と表示要求の区別、およびAOSPの表示ライフサイクルを参照します。

入力欄での表示・非表示・再表示、非表示後の通知領域開閉、ホーム遷移、編集不可の全画面、パスワード欄、物理候補と回転時の状態保持を回帰検証します。修正前APK（SHA-256先頭`b7da0fe9`）へ追加した端末試験を適用し、非表示後の再表示と、全画面`TYPE_NULL`接続での表示の2件が失敗することを確認しました。タップによる再表示とパスワード入力の対照試験は成功しました。記録は`build/reports/keyboard-visibility-20260921/baseline-api35.log`です。修正版では、同じ3件がAndroid 8・15の双方で成功しました。通知領域の実開閉、非表示の継続、表示中のHome遷移、入力欄タップでの再表示、パスワード入力、全画面の`TYPE_NULL`接続を検査しています。詳細は[修正・検証記録](reviews/keyboard-visibility-20260921.md)にまとめます。
