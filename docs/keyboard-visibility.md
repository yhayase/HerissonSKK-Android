# スクリーンキーボードの表示条件

## 表示する場合

入力先が文字入力を受け付け、Androidまたは入力先アプリからキーボードの表示要求を受けた場合に表示します。入力欄へのタップ、アプリが入力開始時に行う表示要求などが該当します。パスワード・数値・電話番号の入力欄も対象です。物理キーボード接続時の文字キー表示は既存の表示設定に従います。

入力接続が存在するだけでは表示しません。入力開始、カーソル通知、候補や辞書状態の更新、設定変更は、それ自体をスクリーンキーボードの表示要求として扱いません。

## 非表示を維持する場合

- 利用者が戻る操作などで隠した後は、新しい表示要求を受けるまで隠した状態を維持します。
- 通知・クイック設定の開閉、画面の再描画だけでは再表示しません。
- ホーム画面や入力欄のない全画面コンテンツでは表示しません。入力属性がない接続や`TYPE_NULL`の接続も、自動表示の対象にしません。
- 入力先との接続が終了した場合は、候補・モードのポップアップも破棄します。

動画アプリやホームアプリでも、検索欄など実際の入力欄を操作した場合は通常の表示条件を適用します。アプリ名や全画面かどうかだけで禁止しません。

## 物理キーボードとの分離

物理キーボードのモード・候補・登録ポップアップ用の窓と、スクリーンキーボードの表示要求を区別します。物理入力のポップアップが必要でも、文字キー画面を表示する理由にはしません。文字キーの表示要求を持たない専用の窓を使い、下部の予約領域をゼロにする契約を維持します。物理側の表示を隠した後は、通知や描画更新だけで戻さず、次の物理入力または新しい入力先で必要な表示を再開します。Emacs風キー処理もスクリーンキーボードの表示を要求しません。

物理候補・登録ポップアップ表示中の Back はその窓だけを閉じ、入力先の Activity を終了させません。キー押下時は追跡を開始するだけで窓を残し、取消されていないキー解放時、または予測型 Back のコールバック時に閉じます。取消されたキー解放では閉じません。押下時に窓と Back コールバックを解除すると、Android 16 では解放時の配送先が入力先へ切り替わり得るためです。Android 13 以降の Back コールバックは物理ポップアップの親窓が表示されている間だけ登録し、入力終了・非表示・構成変更・サービス終了時に解除します。

## 参照と検証

Androidの[InputMethodService](https://developer.android.com/reference/android/inputmethodservice/InputMethodService)の入力接続と表示要求の区別、およびAOSPの表示ライフサイクルを参照します。

Android 13 以降の物理入力用ポップアップは、IME 自身のトークンに結び付けた、透明・非フォーカス・非タッチの親窓を使います。それ以前は候補専用ウィンドウと高さゼロの View を使います。どちらも文字キーの表示要求を発行せず、下部の予約領域を増やしません。Android 8.0（API 26）では、ポップアップを移動してもアクセシビリティの候補座標が旧位置に残る場合があるため、位置が変わったときだけ同じ View を取り付け直します。候補・選択・入力フォーカスは保持します。この例外を API 27 以降へ無条件に広げません。

入力欄での表示・非表示・再表示、非表示後の通知領域開閉、ホーム遷移、編集不可の全画面、パスワード欄、物理候補と回転時の状態保持を回帰検証します。非表示が一定時間続くこと、`TYPE_NULL` の接続が実際に確立したこと、候補移動後のアクセシビリティ上の可視性を確認します。単に入力欄へフォーカスを移しただけでは表示要求とみなさず、入力先の `showSoftInput` 要求を試験で明示します。API 36 では物理候補表示中に Back を押下・解放してポップアップだけが閉じ、入力先のフォーカスが残ること、取消された解放では閉じないこと、次の物理入力まで自動で再表示されないことを検証します。
