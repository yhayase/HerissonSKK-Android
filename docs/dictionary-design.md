# 辞書形式・入出力・永続化の設計契約

作成日: 2026-09-16。フェーズ 3 の実装前に固定する受入契約です。実装済みを示す文書ではありません。
[要件](requirements.md) F06〜F10、S06、N04〜N05、[互換性](compatibility.md) K11〜K13・K18〜K19、
[コア設計](core-design.md)の辞書境界を具体化します。

## 対象とデータモデル

辞書アダプターは、見出し語ごとに順序付きの候補を返します。候補は少なくとも次を別々の値として保持します。

| 値 | 契約 |
| --- | --- |
| 見出し語 | 送りなしの読み、または語幹と末尾の ASCII 小文字 1 文字からなる送りありキー（例: `おおk`）です |
| 候補本文 | 入力先へ確定する本文です。注釈、送り条件、辞書上のエスケープを含めません |
| 注釈 | 候補本文と別に表示し、確定文字へ含めません。空注釈は「なし」とします |
| 送り条件 | 任意のひらがなの送り（例: `く`）です。候補本文や実際に付ける送りとは別に保持します |
| 由来 | 個人辞書またはシステム辞書の ID と世代です。検索診断用であり、SKK テキストへは書き出しません |

候補の永続的な同一性は「候補本文と送り条件」の組です。注釈は同一性に含めません。同じ本文でも送り条件が異なれば別候補です。文字列は取り込み時の Unicode 列を保持し、正規化による同一視は初期実装では行いません。

## SKK テキスト形式

UTF-8 と EUC-JP の SKK テキスト辞書を入力とし、次を必須対応範囲とします。

- 空行、先頭の空白を除いて `;;` で始まるコメント、`;; okuri-ari entries.` と `;; okuri-nasi entries.` を受理します。区分見出しは検証の補助であり、検索結果の意味を変更しません。
- エントリーは `見出し語 /候補/候補;注釈/` とします。候補列の末尾 `/` は必須です。候補本文は空にできません。
- 送り条件ブロック `[く/候補/候補;注釈/]` を受理します。送りありキーの末尾子音と条件の対応を検証し、閉じていないブロック、空ブロック、対応しない条件はエラーにします。
- 候補本文と注釈は、生文字列または限定した `(concat "...")` の単一文字列リテラルとして読みます。候補区切りの `/` と注釈区切りの最初の `;` は式の外側だけで認識します。文字列内では DDSKK の引用表現 `\057`、`\073`、`\\`、`\"` をそれぞれ `/`、`;`、`\`、`"` に戻します。先頭 `[` または本文 `]` のように送り条件構文と紛らわしい候補も、書き出し時はこの限定表現にします。
- 注釈の先頭にある DDSKK の個人注釈マーカー `*` は構文として受理し、表示する注釈本文には含めません。注釈内の追加の `;` は注釈本文の一部として保持します。
- `(concat ...)` は上記の単一文字列リテラルだけを許します。任意の Emacs Lisp、複数式、関数呼び出しは実行せず、非対応表現として取り込み全体を失敗させます。
- 見出し語、候補本文、注釈、送り条件に NUL、改行、不正な Unicode を許しません。見出し語には空白と `/` を許しません。制御文字の許可範囲は実装前のテストデータで固定します。

文字コード指定がない場合は BOM を除いた strict UTF-8 を先に試し、失敗時だけ strict EUC-JP を試します。どちらでも不正なら失敗し、置換文字で読み進めません。画面には判定した文字コードを表示し、UTF-8／EUC-JP の明示指定でも同じ strict 復号を使います。Shift_JIS、CP932、ISO-2022-JP は文字コード選択肢として提供しません。別の文字コードのバイト列が偶然 UTF-8 または EUC-JP として妥当な場合は自動判別できないため、適用前プレビューで見出し語と候補の標本を確認できるようにします。

初期実装では入力ファイルを 64 MiB 以下、復号済み文字列を UTF-16 で 67,108,864 code unit 以下、1 論理行を 1,048,576 code unit 以下に制限します。通常の SKK 辞書を扱いつつ、全件検証中の一時メモリと異常な単一行を制限するためです。候補数にはこの三つと利用可能な保存容量以外の固定上限を設けません。全文について CR、LF、TAB 以外の C0 制御文字（U+0000〜U+001F）、DEL（U+007F）、孤立サロゲートを、コメントと空行も含めて拒否します。候補本文と注釈の通常の空白は保持しますが、見出し語の空白は区切りと衝突するため拒否します。妥当なサロゲート対と emoji は保持します。失敗表示は行番号と理由分類だけを含み、辞書本文を含めません。

同じ見出し語が複数行にある場合はファイル上の順に候補を連結します。同一候補は最初の位置を残して一つにし、最初の注釈が空で後の同一候補だけに注釈があれば、その注釈を補います。両方に異なる非空注釈がある場合は先の注釈を採用し、診断結果に競合件数を出します。

## 検索順、送り条件、重複

検索元の順は、個人辞書、設定で有効なシステム辞書の順です。各辞書内では保存された候補順を使います。複数辞書に同一候補があれば最初の候補だけを表示し、最上位の非空注釈を表示します。下位の由来と注釈は診断情報として保持します。

送りあり検索では、個人辞書と各システム辞書の優先順位を先に適用し、各辞書の中を「送り条件が一致」「条件なし」「条件が不一致」の順に安定して並べ、最後に候補本文で重複を除きます。不一致候補は初期設定では除外しません。これにより個人辞書
`おおk /大/多/[く/多/]/[き/大/]/` に対する送り `く` は `多く`、`大く` の順になります。送りは検索時の本文へ一度だけ付加し、保存候補や確定結果へ二重に含めません。

候補の学習は、確定した候補を同じ見出し語・送り条件の個人候補の先頭へ移します。システム候補も個人辞書へ同じ情報を記録して先頭にします。個人辞書にすでにある同一候補を増殖させません。候補削除は確認完了後にだけ行い、個人候補を削除し、システム由来なら個人領域の抑止記録で非表示にします。システム辞書の原本と世代は変更しません。抑止は再起動とシステム辞書更新後も、ユーザーが復元するまで有効です。

## 個人辞書の取り込みと書き出し

取り込み前に全バイトを strict 復号し、全行を解析・検証して、件数、文字コード、警告、重複・注釈競合件数をプレビューします。不正行または非対応表現が一つでもあれば適用できません。行を黙って捨てる部分取り込みは初期実装では行いません。

適用時にユーザーは次のいずれかを明示します。

- **マージ:** 取り込んだ候補順を各見出し語の先頭に置き、その後ろに既存だけの候補を既存順で残します。同一候補は取り込み側の注釈を優先し、取り込み側が空なら既存注釈を残します。
- **置換:** 解析結果を新しい個人辞書全体とします。適用前に置換対象と件数を表示します。

どちらも新しい世代へ全件を書き、検証と永続化が完了した後に一回で公開します。取消、容量不足、プロセス終了、書き込み失敗、公開競合では旧世代と学習結果をそのまま利用し、半分だけ適用しません。再試行は新しい操作 ID で行い、同じ公開操作の重複完了を許しません。

書き出しは UTF-8（BOM なし）、LF、末尾改行ありの SKK テキストとします。送りあり／なしの区分見出しを出し、区分内の見出し語は Unicode コードポイント順に並べます。候補順は変更しません。連続する同じ送り条件の候補を一つの条件ブロックへまとめ、特殊文字を前節の限定表現へ符号化します。書き出したファイルの再取り込みで、見出し語、候補本文、注釈、送り条件、候補順が一致することを K13 の往復条件とします。

システム候補の抑止記録、由来、内部操作 ID は標準 SKK テキストで表現できないため初期書き出しには含めず、完了画面に除外件数を表示します。これらを含む完全バックアップ形式は後述の未確定事項です。

## システム辞書と永続化境界

追加システム辞書は個人辞書と別の ID・世代で保存し、有効状態と検索順を設定として公開します。同じ ID の再取り込みは、その位置を保ったまま新世代へ置き換えます。新規追加は設定順の末尾です。取り外しは対象システム辞書だけを外し、個人辞書、他辞書、元の選択ファイルへ触れません。

辞書の解析・索引作成中も公開済み世代を検索に使います。新世代の全件保存と検証後に、辞書一覧、順序、世代ポインターを一つのトランザクションで公開します。失敗または中断した未公開世代は次回起動時に破棄し、旧世代を使います。変換開始時の辞書世代を候補選択終了まで固定し、更新後の世代は次の検索から使います。

現在の `BasicSkkEngine` は候補に由来を持たず、検索結果全体を送り一致で並べ替えます。複合辞書の導入時は、個人辞書とシステム辞書の優先順位を失わない構造付き候補へ移行し、送り一致の並べ替えを各辞書内で行います。現行の限定エンジンを辞書形式 codec の実装時に変更せず、この移行を複合検索の受入試験で固定します。

登録、学習、削除は各操作を原子的に永続化し、成功後にだけ新しい検索結果へ公開します。保存失敗時は成功を表示せず、旧状態を維持して再試行できます。確定成功を一意な要求 ID で確認した通常候補だけを一度学習します。K18 の送りあり登録は編集後の本文から送りを除いた語幹を候補本文として、実際の送りを送り条件として保存し、入力先には本文と送りを一度だけ確定します。

パスワード欄と `TYPE_NULL` は Android 接続層で SKK コアを迂回し、変換、候補、登録、学習を開始しません。通常欄で入力先の学習禁止要求またはユーザーの学習無効設定が有効な場合は、変換と候補確定を許可しますが、その入力セッションに由来する学習と登録保存を開始しません。登録保存には理由を表示します。方針変更は即時適用し、すでに待機中の保存もトランザクション開始直前に再検査して中止します。設定画面から明示する辞書取り込み、削除、復元は入力欄のセッション方針とは別の管理操作として扱います。禁止対象の本文・読みを診断ログへ残しません。

## 要件対応と受入例

| 仕様 | 主な受入条件 |
| --- | --- |
| F07、K11 | `にほん /日本/二本/` で `二本` を確定すると再検索の先頭です。保存失敗なら順位は変わりません。削除取消は無変更、システム候補削除は原本を変えず再起動後も非表示です |
| F08、K12 | 個人、システム A、B の順で候補を統合し、A/B の並べ替えは次の検索から反映します。更新の強制中断後も旧候補と学習順位を使えます |
| F09、K13 | UTF-8 と EUC-JP の同じ辞書を取り込み、特殊文字、注釈、送り条件、候補順を UTF-8 書き出し後の再取り込みでも保持します。不正な 1 行を加えると全件不適用です |
| F06、K18 | 登録本文 `東京` の中央で `東` を削除し、`京` だけを保存します。送りあり登録は語幹と条件を分離し、送りを二重出力しません |
| F10、K19、N05 | 通常欄の学習禁止で候補を確定しても個人辞書と抑止記録は変わらず、本文・読みを診断ログへ残しません。登録保存は理由付きで拒否します。パスワード欄と `TYPE_NULL` は変換自体を行いません |
| N04 | 個人辞書のマージ／置換、システム辞書更新、候補学習の各失敗点で、再起動後に最後に公開済みの状態だけが見えます |

## 実装と試験の段階

1. 純 JVM の形式層で strict UTF-8／EUC-JP、改行、コメント、限定 `(concat ...)`、注釈、送り条件、不正行、往復を表形式のテストにします。参照辞書そのものは複製せず、必要最小限の独自 fixture を使います。
2. インメモリ辞書で個人優先、辞書順、送り優先、重複、注釈競合、学習・削除・学習禁止を検証します。コアからは本文・注釈・条件・由来を構造で受け渡します。
3. Android の永続層で世代の stage／publish、個人辞書の原子的変更、同時更新、容量不足、各書き込み境界での強制終了、再起動回復を fault injection で検証します。
4. ファイル選択 UI を結合し、文字コード表示、マージ／置換プレビュー、全件失敗、UTF-8 書き出し、除外情報の表示を検証します。大規模辞書の時間・メモリは N06 の測定条件確定後に合格値を置きます。
5. K11〜K13・K18〜K19 の物理キー操作と IME 再起動を実機で通し、辞書処理中も公開済み辞書で入力できることを確認します。

## 未確定事項

- 抑止記録や由来まで含む完全バックアップ形式と版管理。標準 SKK テキストの K13 とは別形式にする必要があります。
- 制御文字の詳細な許可集合、1 ファイルの上限、候補数・注釈長の上限。端末測定と安全なエラー表示を踏まえて固定します。
- Unicode 正規化を将来導入する場合の既存辞書移行。初期実装は入力列を保持するため、見た目が同じ別列は別候補になり得ます。
- DDSKK の任意 Lisp 候補式、数値変換式、厳密送り除外との相互作用。F11、R01 の仕様確定までは実行も対応表示もしません。

## 参照調査

DDSKK の基準コミット `e8bf68b27021c29781dbfa6a8ef7b770565bdb5b` にある `skk-quote-char`、`skk-quote-semicolon`、`skk-eval-string` と注釈処理を読み、`\057`、`\073`、限定 `concat`、個人注釈マーカーの互換範囲を確認しました。本製品は式を評価せず、同じ文字列結果を安全な限定 parser で得ます。

隣接する `../skk-browser-extension` の `JisyoParser.ts`、`candidate.ts`、`CompositeJisyoProvider.ts`、`SystemDictionaryManager.ts` と対応テストを読み、候補と注釈の分離、送り条件、先勝ち重複排除、旧世代維持を確認しました。ブラウザー固有の IndexedDB、RPC、寛容な復号、壊れた行の読み飛ばしは本契約へ引き継いでいません。`../aquaskk` の `SKKDictionaryFile.cpp`、`SKKCandidate.h`、`SKKCandidateParser.h`、`SKKCandidateSuite_TEST.cpp` は、UTF-8／EUC-JP 辞書、区分見出し、候補と注釈、送りヒントの構造だけを調査しました。GPL のソース、辞書、fixture は複製していません。

## 現段階の実装

形式層と読み取り専用の複合検索を実装し、エンジン内の送り条件による全体再ソートを削除しました。辞書層が最終順序を決め、エンジンはその順を維持します。下位システム辞書の送り一致が上位個人辞書を追い越さないことを、実エンジンまで接続して検証しています。AndroidのSQLite保存・メモリー公開・設定UIを追加しました。保存層のネイティブ試験はAPI26・35で各6件成功しました。再帰登録と候補学習を実装し、SAF画面を含む退避・登録・学習・復元E2EはAPI30・35で成功しています。API26のSAF画面への対応と候補削除は継続中です。
