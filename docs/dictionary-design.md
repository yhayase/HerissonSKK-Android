# 辞書形式・入出力・永続化の設計契約

本書は辞書形式・検索・保存の契約を定めます。ネットワーク取得と初期 S 辞書は [ネットワーク辞書](network-dictionary-design.md) を参照します。サーバー検索・個人辞書同期は別機能です。
[要件](requirements.md) F06〜F10、S06、N04〜N05、[互換性](compatibility.md) K11〜K13・K18〜K19、
[コア設計](core-design.md)の辞書境界を具体化します。

通常起動・検索・学習では全件をメモリーへ公開せず、[有限キャッシュ](dictionary-storage-cache-design.md)を使います。

## 対象とデータモデル

辞書アダプターは、見出し語ごとに順序付きの候補を返します。候補は少なくとも次を別々の値として保持します。

| 値 | 契約 |
| --- | --- |
| 見出し語 | 送りなしの読み、または語幹と末尾の ASCII 小文字 1 文字からなる送りありキー（例: `おおk`）です |
| 候補本文 | 入力先へ確定する本文です。注釈、送り条件、辞書上のエスケープを含めません |
| 注釈 | 候補本文と別に表示し、確定文字へ含めません。空注釈は「なし」とし、個人注釈マーカーの有無は `annotationIsPersonal` として別に保持します |
| 送り条件 | 非空の照合文字列（通常はひらがなの送り、例: `く`）です。候補本文や実際に付ける送りとは別に保持し、取り込み時に文字種や見出し末尾との対応で変換しません |
| 由来 | 個人辞書またはシステム辞書の ID と世代です。検索診断用であり、SKK テキストへは書き出しません |

エントリーは `section` と一覧上の位置を保持します。区分見出しがある場合は明示された送りあり／なしを採用し、見出しがない場合だけ「非 ASCII 文字を含み、末尾が ASCII 小文字」のキーを送りありと推定します。ASCII の abbrev キーは末尾が小文字でも送りなしです。

候補の永続的な同一性は「候補本文と送り条件」の組です。注釈は同一性に含めません。同じ本文でも送り条件が異なれば別候補です。文字列は取り込み時の Unicode 列を保持し、正規化による同一視は初期実装では行いません。

## SKK テキスト形式

UTF-8、EUC-JP、EUC-JIS-2004 の SKK テキスト辞書を入力とし、次を必須対応範囲とします。

- 空行、先頭の空白を除いて `;;` で始まるコメント、`;; okuri-ari entries.` と `;; okuri-nasi entries.` を受理します。区分見出しはエントリーの区分として保存し、補完・予測・書き出しにも使います。
- エントリーは `見出し語 /候補/候補;注釈/` とします。候補列の末尾 `/` は必須です。候補本文は空にできません。
- 送り条件ブロック `[く/候補/候補;注釈/]` を受理します。条件は非空の文字列として保存し、ASCII 文字を含む条件や見出し末尾の子音と対応しない条件も保持します。送りなし見出しに付いたブロックも保存しますが、これはメタデータの保持であり DDSKK の送りなし検索と同じ候補解釈を保証しません。検索時の条件一致・条件なし・条件不一致の順位付けは変更しません。閉じていないブロック、空条件、空ブロック、入れ子はエラーにします。条件内の `/`、`[`、`]`、`"` は、このブロック構文で往復できないため拒否します。条件の Unicode の検証は候補本文と共通ですが、改行を含む制御文字はすべて拒否します。
- 候補本文と注釈は、生文字列または限定した `(concat "...")` の単一文字列リテラルとして読みます。候補区切りの `/` と注釈区切りの最初の `;` は式の外側だけで認識します。文字列内では DDSKK の引用表現 `\057`、`\073`、`\\`、`\"` をそれぞれ `/`、`;`、`\`、`"` に戻します。`\n` と `\012` は LF、`\r` と `\015` は CR に戻します。本文・注釈内の LF/CR は文字列の値として保持し、書き出しでは `\n`・`\r` に符号化します。先頭 `[` または本文 `]` のように送り条件構文と紛らわしい候補も、書き出し時はこの限定表現にします。
- 注釈の先頭にある DDSKK の個人注釈マーカー `*` は構文として受理し、表示する注釈本文には含めません。マーカーの有無を別の真偽値として保存し、書き出し時に復元します。注釈本文そのものが `*` で始まる場合は限定 `concat` で区別します。個人マーカーだけの空注釈はマーカーなしの null にします。注釈内の追加の `;` は注釈本文の一部として保持します。
- `(concat ...)` は上記の単一文字列リテラルだけを許します。任意の Emacs Lisp、複数式、関数呼び出しは実行しません。既定の厳密解析では非対応表現として失敗します。設定画面の取り込みだけは、既知の `skk-current-date`（省略可能な 3 引数: 関数指定、書式、時刻の有無）と `skk-ignore-dic-word`（1 個以上の非空の引用文字列の引数）を含む候補を警告付きで除外します。本文または注釈が該当した場合は候補単位で除外し、同じ行や送り条件ブロック内の対応候補は保持します。日付式の関数指定は `nil`、引用されたシンボル／リスト、関数引用、または `lambda` を識別します。書式は `nil` または文字列、時刻の有無は `nil` または `t` を識別します。保存されたコールバック内は構造だけを検証し、実行時の妥当性は判定しません。読み取り特殊構文（バッククォート、カンマ、任意の `#` 指令、ドット対）は識別せず拒否します。構造の深さは 64、構造ノード数は 4,096 以下に制限します。引用文字列のエスケープは `\057`、`\073`、`\n`、`\r`、`\\`、`\"` だけを識別します。抑止式を本アプリの抑止記録へ変換することはしません。未知の式、壊れた `concat`、不正な引用や区切りは失敗させます。
- 見出し語と送り条件に改行を許しません。候補本文と注釈は限定文字列から復号された LF/CR だけを許し、生の候補構文に制御文字を許しません。NUL、TAB、その他の C0 制御文字、DEL、不正な Unicode は本文・注釈でも拒否します。見出し語には空白と `/` を許しません。制御文字とサイズの制限は以下に定義します。

文字コード指定がない場合は BOM を除いた strict UTF-8、strict EUC-JP、strict EUC-JIS-2004 の順に復号を試します。次の文字コードへ進むのは復号失敗時だけで、構文解析の失敗で再判定しません。置換文字で読み進めません。EUC-JP と EUC-JIS-2004 の重なるバイト列には異なる文字対応があるため、自動判定は従来の EUC-JP を優先します。この場合は利用者が EUC-JIS-2004 を明示指定します。coding cookie による判定は行いません。画面には判定した文字コードを表示し、各明示指定でも同じ strict 復号を使います。Shift_JIS、CP932、ISO-2022-JP は文字コード選択肢として提供しません。適用前プレビューは文字コード・件数・重複等を表示しますが、自動判定の意味上の正しさまでは保証しません。EUC-JIS-2004 は固定した JIS X 0213:2004 の対応表で復号し、JIS X 0212 への代替復号はしません。対応表の根拠とライセンスは [ライセンス一覧](licenses.md) を参照します。

初期実装では入力ファイルを 64 MiB 以下、復号済み文字列を UTF-16 で 67,108,864 code unit 以下、1 論理行を 1,048,576 code unit 以下に制限します。通常の SKK 辞書を扱いつつ、全件検証中の一時メモリと異常な単一行を制限するためです。候補数にはこの三つと利用可能な保存容量以外の固定上限を設けません。全文について CR、LF、TAB 以外の C0 制御文字（U+0000〜U+001F）、DEL（U+007F）、孤立サロゲートを、コメントと空行も含めて拒否します。候補本文と注釈の通常の空白は保持しますが、見出し語の空白は区切りと衝突するため拒否します。妥当なサロゲート対と emoji は保持します。失敗表示は行番号と理由分類だけを含み、辞書本文を含めません。

同じ見出し語が複数行にある場合はファイル上の順に候補を連結します。見出し語の位置と区分は、対応候補を持つ初回の保持された出現を採用します。警告で候補全体を除外した行は、この位置・区分を確定しません。同一候補は最初の位置を残して一つにし、最初の注釈が空で後の同一候補だけに注釈があれば、その注釈本文と個人マーカーを一緒に補います。両方に異なる非空注釈または個人マーカーの相違がある場合は先の注釈を採用し、診断結果に競合件数を出します。

## 検索順、送り条件、重複

検索元の順は、個人辞書、設定で有効なシステム辞書の順です。各辞書内では保存された候補順を使います。複数辞書に同一候補があれば最初の候補だけを表示し、最上位の非空注釈本文と個人マーカーを一緒に採用します。下位の由来と注釈は診断情報として保持します。

送りあり検索では、個人辞書と各システム辞書の優先順位を先に適用し、各辞書の中を「送り条件が一致」「条件なし」「条件が不一致」の順に安定して並べ、最後に候補本文で重複を除きます。不一致候補は初期設定では除外しません。これにより個人辞書
`おおk /大/多/[く/多/]/[き/大/]/` に対する送り `く` は `多く`、`大く` の順になります。送りは検索時の本文へ一度だけ付加し、保存候補や確定結果へ二重に含めません。

候補の学習は、確定した候補を同じ見出し語・送り条件の個人候補の先頭へ移します。システム候補も個人辞書へ同じ情報を記録して先頭にします。個人辞書にすでにある同一候補を増殖させません。候補削除は確認完了後にだけ行い、個人候補を削除し、システム由来なら個人領域の抑止記録で非表示にします。システム辞書の原本と世代は変更しません。抑止は再起動とシステム辞書更新後も、ユーザーが復元するまで有効です。

## 個人辞書の取り込みと書き出し

取り込み前に全バイトを strict 復号し、全行を解析・検証して、件数、文字コード、警告、重複・注釈競合件数をプレビューします。設定画面の個人辞書・追加辞書・URL／カタログ辞書の取り込みは、上記の既知の非対応式と、候補列が妥当な空見出し行を除外して対応データをプレビューします。除外した候補数・見出し行数・理由別件数と行番号を適用前に表示し、除外データが保存されないことを明示します。警告は本文を保持せず、行番号と理由のサンプルは先頭 100 件に制限し、全件数は保持します。除外対象だけで対応候補がないファイルは適用できません。従来の空ファイルは空辞書として扱います。除外対象を含む行でも候補列全体を検証し、壊れた行、不正な文字コードや制御文字が一つでもあれば全体を適用できません。完全バックアップと初期設定の自動辞書取得は既定の厳密検証を維持します。

適用時にユーザーは次のいずれかを明示します。

- **マージ:** 取り込んだ候補順を各見出し語の先頭に置き、その後ろに既存だけの候補を既存順で残します。同一候補は取り込み側の注釈を優先し、取り込み側が空なら既存注釈を残します。
- **置換:** 解析結果を新しい個人辞書全体とします。適用前に置換対象と件数を表示します。

どちらも新しい世代へ全件を書き、検証と永続化が完了した後に一回で公開します。取消、容量不足、プロセス終了、書き込み失敗、公開競合では旧世代と学習結果をそのまま利用し、半分だけ適用しません。再試行は新しい操作 ID で行い、同じ公開操作の重複完了を許しません。

書き出しは UTF-8（BOM なし）、LF、末尾改行ありの SKK テキストとします。送りあり／なしの区分見出しを出し、区分ごとに安定して分け、区分内の見出し語は入力または保存の順序を保持します。候補順は変更しません。連続する同じ送り条件の候補を一つの条件ブロックへまとめ、特殊文字を前節の限定表現へ符号化します。書き出したファイルの再取り込みで、見出し語、区分、区分内の見出し順、候補本文、注釈、個人マーカー、送り条件、候補順が一致することを K13 の往復条件とします。

システム候補の抑止記録、由来、内部操作 ID は標準 SKK テキストで表現できないため初期書き出しには含めず、完了画面に除外件数を表示します。これらを含む別形式は [完全バックアップ設計](complete-backup-design.md) に定義・実装しています。

## システム辞書と永続化境界

追加システム辞書は個人辞書と別の ID・世代で保存し、有効状態と検索順を設定として公開します。同じ ID の再取り込みは、その位置を保ったまま新世代へ置き換えます。新規追加は設定順の末尾です。取り外しは対象システム辞書だけを外し、個人辞書、他辞書、元の選択ファイルへ触れません。

辞書の解析・索引作成中も公開済み世代を検索に使います。新世代の全件保存と検証後に、辞書一覧、順序、世代ポインターを一つのトランザクションで公開します。失敗または中断した未公開世代は次回起動時に破棄し、旧世代を使います。変換開始時の辞書世代を候補選択終了まで固定し、更新後の世代は次の検索から使います。

複合辞書は候補の由来を保持して辞書ごとの優先順を解決し、エンジンは結果を再ソートしません。通常検索・補完は [有限キャッシュ](dictionary-storage-cache-design.md) に従って必要な範囲だけ取得します。

登録・学習・削除は原子的に永続化します。学習は対象見出しだけを更新し、保存後は管理情報とキャッシュ世代を更新します。保存前の既存候補の順位反映は [学習待機の契約](core-design.md#非同期保存待ちの学習順位) に従い、失敗時に取り消します。登録の語幹・送りと保存／確定の分離は [登録設計](registration-design.md)、削除・抑止は [候補削除設計](candidate-deletion-design.md) を参照します。

パスワード欄と `TYPE_NULL` は Android 接続層で SKK コアを迂回し、変換、候補、登録、学習を開始しません。通常欄で入力先の学習禁止要求またはユーザーの学習無効設定が有効な場合は、変換と候補確定を許可しますが、その入力セッションに由来する学習と登録保存を開始しません。登録保存には理由を表示します。方針変更は即時適用し、すでに待機中の保存もトランザクション開始直前に再検査して中止します。設定画面から明示する辞書取り込み、削除、復元は入力欄のセッション方針とは別の管理操作として扱います。禁止対象の本文・読みを診断ログへ残しません。

## 要件対応と受入例

| 仕様 | 主な受入条件 |
| --- | --- |
| F07、K11 | `にほん /日本/二本/` で `二本` を確定すると再検索の先頭です。保存失敗なら順位は変わりません。削除取消は無変更、システム候補削除は原本を変えず再起動後も非表示です |
| F08、K12 | 個人、システム A、B の順で候補を統合し、A/B の並べ替えは次の検索から反映します。更新の強制中断後も旧候補と学習順位を使えます |
| F09、K13 | UTF-8・EUC-JP・EUC-JIS-2004 の辞書を取り込み、特殊文字、区分、区分内の見出し順、個人注釈マーカー、本文・注釈の LF/CR、送り条件、候補順を UTF-8 書き出し後の再取り込みでも保持します。不正な 1 行を加えると全件不適用です |
| F06、K18 | 登録本文 `東京` の中央で `東` を削除し、`京` だけを保存します。送りあり登録は語幹と条件を分離し、送りを二重出力しません |
| F10、K19、N05 | 通常欄の学習禁止で候補を確定しても個人辞書と抑止記録は変わらず、本文・読みを診断ログへ残しません。登録保存は理由付きで拒否します。パスワード欄と `TYPE_NULL` は変換自体を行いません |
| N04 | 個人辞書のマージ／置換、システム辞書更新、候補学習の各失敗点で、再起動後に最後に公開済みの状態だけが見えます |

## 層ごとの検証

- 純 JVM の形式試験で strict UTF-8／EUC-JP／EUC-JIS-2004、引用した LF/CR、区分と区分内の順序、コメント、限定 `(concat ...)`、注釈、送り条件、不正行、往復を検証します。参照辞書は複製せず、必要最小限の独自 fixture を使います。
- 複合辞書の試験で個人優先、辞書順、送り優先、重複、注釈競合、学習・削除・学習禁止を検証します。コアと辞書の間では本文・注釈・条件・由来を構造で受け渡します。
- SQLite の故障注入で世代の stage／publish、個人辞書の原子的変更、同時更新、容量不足、各書込み境界の中断、再起動後の回復を検証します。
- ファイル選択の試験で文字コード表示、マージ／置換プレビュー、全件失敗、UTF-8 書き出し、除外情報の表示を検証します。大規模辞書の時間・メモリーは [性能測定](dictionary-performance.md) の条件で評価します。
- K11〜K13・K18〜K19 の物理キー操作と IME 再起動を確認し、辞書処理中も公開済み辞書で入力できることを検証します。

## 拡張の境界

SQLite の破損時は既定の自動削除・再作成を行わず、元の DB ファイルを保持して本文・ファイルパスを含まない失敗として返します。容量不足で SQLite がトランザクションを自動で巻き戻した後、終了処理も失敗した場合は、元の容量不足例外を主たる失敗として保持し、終了失敗を付随情報にします。成功として公開せず、旧候補と世代を維持します。プログラムから作った個人辞書の空注釈は保存時に null へ正規化し、マージ元が空なら既存の非空注釈を残します。候補行と由来世代・優先順は同じ読取トランザクションで取得し、異なる時点の値を混ぜません。

完全バックアップの版・容量は [専用設計](complete-backup-design.md)、数値テンプレートは [数値設計](numeric-design.md)、ネットワーク取得・初期 S 辞書は[ネットワーク辞書設計](network-dictionary-design.md)に定めます。任意の Emacs Lisp は実行しません。厳密送り照合や Unicode 正規化の導入は別の設計判断であり、現在は元の Unicode 列を保持します。

## 互換性の根拠
