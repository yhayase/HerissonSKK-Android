## 2026-09-20 の計画・検証履歴

## 方針と開始点

利用者は初回リリースまでの開発と、作業難度に応じたサブエージェントへの委任を承認しました。実装結果は別担当がレビューし、指摘はさらに別担当が現行要件・コード・再現条件から検証します。通常の技術判断は開発側で行い、実機の本人操作、操作感の受入、公開ライセンス・本番署名・公開の所有者判断を利用者へ渡します。

開始コミットは `8b3052d` で、開始時の作業ツリーに変更はありません。範囲・優先順位の正本は [ロードマップ](roadmap.md)、受入判定は [リリース受入チェックリスト](release-acceptance.md) と [検証計画](validation-plan.md) です。この記録は完了の証拠を伴わない計画を実装済みとして扱いません。

## 作業順序と完了条件

1. 初回必須とコードの差分を確認し、画面構成・入力経路・辞書更新の契約と受入例を具体化します。
2. ネットワーク辞書・初期S辞書、アプリ別Emacs設定、QWERTY・IME切り替え、設定UI・候補登録表示を実装し、各作業を独立レビュー・指摘検証へ回します。
3. 統合した版の自動試験、保存・更新・通信失敗・入力境界・表示・配布物を検証します。既存試験の成功を追加機能の証拠へ転用しません。
4. 両端末・縦横・JIS/US・画面キーボードと必須10アプリを代表ケースへ配分し、実機受入・性能測定を行います。接続・認証・実打鍵・操作感は利用者、準備・自動操作・解析・修正は開発側が担当します。
5. 公開ライセンス・署名・配布先の判断材料、署名後の最終成果物、導入・更新手順、既知の制約を揃え、公開判断へ渡します。一般公開は所有者の判断後です。
