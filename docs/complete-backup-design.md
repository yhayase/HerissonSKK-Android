# 完全辞書バックアップと原子的復元の設計

作成日: 2026-09-16。これは実装・独立レビューに渡す設計契約です。本書の追加だけでは機能の実装・検証完了を意味しません。

## 要件と採用範囲

[要件](requirements.md) N12 の辞書バックアップ、N04 の失敗・中断時の既存データ保持を具体化します。[互換性](compatibility.md) K13 の標準 SKK テキスト往復は既存の別機能として維持します。本書を完全バックアップの形式・復元契約の正本とします。

必須の保存対象は、個人辞書の全候補、注釈、送り条件、候補順、システム候補の全抑止記録、全システム辞書の内容・ID・名前・世代・有効状態・優先順、および形式の版情報です。無効な辞書も省略しません。抑止の同一性は `(sourceId, entryKey, templateText, okuriCondition)` です。注釈・現在のソース世代は抑止の同一性に含めません。削除済みソースを参照する抑止も保存します。

設定、キー割り当て、入力途中の状態、入力先の本文、パスワード欄の情報、進行中の確認・保存トークンは対象外です。設定の書き出しはこの要件の必須項目に追加しません。バックアップは辞書を含む平文です。保存先選択画面でそのことを表示します。

形式、上限、API、組み込み辞書の扱い、復元時の世代割り当ては以下の設計上の選択です。要件に特定の JSON 形式や容量が指定されているわけではありません。

## 形式 v1

非圧縮の UTF-8 JSON Lines を採用します。識別子は `skk-android-dictionary-backup`、拡張子は `.skkbackup`、SAF の MIME は `application/octet-stream` とします。ZIP、任意パス、SQL、実行可能な式は含めません。圧縮展開・パストラバーサルの処理自体を持ちません。

各行は一つの平坦な JSON オブジェクトです。配列と入れ子オブジェクトを禁止し、文字列内の改行は JSON エスケープだけで表します。出力は BOM なし、LF、最終行の後にも LF とします。入力は BOM なしの strict UTF-8 と LF だけを受け付けます。最終 LF 欠落も未完了ファイルとして拒否します。

レコード順を次に固定します。各レコードは表の全フィールドが必須で、任意の null は明記した列だけに許します。

| `type` | フィールド（`type` 以外）と意味 |
| --- | --- |
| `header` | `format` は上記識別子、`version` は整数 `1`、`producerVersion` は作成アプリの表示用版文字列です |
| `source` | `id`, `name`, `kind`（`personal` / `system`）, `generation`, `enabled`, `order`。個人一件を先頭に、全システムを優先順に出力します |
| `candidate` | `sourceId`, `entryKey`, `ordinal`, `text`, `annotation`（null 可）, `okuriCondition`（null 可）。ソース順、見出し語のコードポイント順、候補順で出力します |
| `suppression` | `sourceId`, `entryKey`, `templateText`, `okuriCondition`（null 可）。同一性の各文字列をコードポイント順で比較して出力します |
| `sourceVersion` | `sourceId`, `lastGeneration`。削除済みソースを含む世代台帳を ID 順で出力します |
| `end` | `sourceCount`, `candidateCount`, `suppressionCount`, `sourceVersionCount`。各セクションの実測件数と完全一致させます |

`header` と `end` は各一件です。空セクションを許しますが、個人ソースは ID `personal`、`kind=personal`、`enabled=true`、`order=0` の一件が必須です。システム ID は個人 ID と衝突させず、システムの `order` は 0 起点の連番とします。空辞書は source のみで表現できます。

同じソース・見出しの ordinal は 0 起点の連番です。候補の同一性 `(sourceId, entryKey, text, okuriCondition)`、抑止の同一性、ソース ID、台帳 ID の重複はエラーとし、黙ったマージをしません。候補は宣言済みのソースだけを参照します。台帳は全宣言済みソースを含み、`lastGeneration >= generation` を満たします。参照先がない抑止と台帳は有効です。

出力した世代は作成時の由来として保存します。復元時の実行世代は後述の規則で変わるため、復元後の再出力で世代だけが増加することは仕様です。候補、抑止、ソース ID、名前、有効状態、順序は一致させます。

## 入力境界と全件検証

外部ファイルの MIME、名前、プロバイダーが返す長さを信用しません。読取中に実バイト数を計測し、次の上限を超える前に中断します。書き出しにも同じ上限を適用し、復元できないバックアップを成功として作りません。

| 項目 | v1 の上限 |
| --- | --- |
| ファイル | 256 MiB |
| 一行の UTF-8 バイト数 | 8 MiB（LF を除く） |
| 一つの復号済み文字列 | 1,048,576 UTF-16 code unit |
| ID と名前、作成アプリ版 | 各 1,024 UTF-16 code unit |
| ソース数 | 個人を含め 1,024 |
| 候補数 | 全ソース合計 1,000,000 |
| 抑止数 / 世代台帳数 | それぞれ 100,000 |
| JSON コンテナー深度 | 1（ルートオブジェクトだけ） |

256 MiB はメモリー使用量の保証ではありません。ストリーム解析とアプリ専用領域の検証済み一時ファイルを用い、全 JSON オブジェクトをメモリーへ蓄積しません。レコード数・重複・参照整合性の検証にも上限を適用します。試験で対象端末の実用上限を評価し、上限超過は分割を促す明示エラーにします。既存辞書がこの上限を超える場合、完全バックアップを作れない制限を表示します。

JSON の重複フィールド、未知のフィールド・レコード種別、欠落フィールド、型違い、末尾の別値、コメント、非有限数、指数・小数表記の整数を拒否します。整数は十進の厳密な非負整数で、Long / Int の各用途の範囲内に制限します。version が未知なら書込み前に拒否し、推測による変換をしません。

不正 UTF-8、孤立サロゲート（JSON エスケープ経由も含む）、禁止制御文字を拒否します。候補・見出し・注釈・送り条件は既存 SKK コーデックと同じ意味検証を共有します。候補本文と見出しは空不可、空注釈と空送り条件は null に統一した正規表現だけを受理します。ID・名前は空白だけを不可とし、制御文字を許しません。文字列は Unicode 正規化しません。

`end` がない、件数が違う、余分なデータがある、読取・close が失敗した場合も全体を失敗にします。エラーにはレコード番号と分類だけを渡し、個人辞書本文をログへ残しません。終端件数は切断検出用であり、改ざん防止やファイルの信頼性を保証する署名ではありません。

## 組み込み辞書と完全性

現在の `DictionaryRuntime` は DB 外の `BuiltinDictionary.source` を fallback として追加しています。完全バックアップにはその内容・ID・世代もシステムソースとして含めます。DB 内に同 ID がある場合は DB のソースを優先し、fallback を重ねません。無効な DB ソースでも同 ID の fallback を復活させません。通常検索の管理情報には無効ソースを含む全保存済みIDを持ち、除外判断に使います。通常検索は全候補を読みません。完全バックアップの明示操作だけが全ソース・全候補を読み出します。

復元後は、バックアップ中の組み込み辞書も通常の DB 内システムソースとして保存します。アプリの組み込みデータが将来変わっても復元内容は変えません。manager の候補削除で `IMMUTABLE_SYSTEM` 承認を使うのは現在 DB 内に存在しない fallback ID だけとし、保存済みソースは必ず `STORED_SYSTEM` の世代検証を通します。

バックアップにない現在の fallback を勝手に追加しないため、DB に「完全復元済み」のフラグを保存します。このフラグがあるスナップショットでは fallback 全体を補いません。フラグも辞書置換と同じトランザクションで更新します。通常の新規 DB は従来どおり fallback を使います。従って検索結果はファイル内のソース集合に一致し、追加されたアプリ内辞書によって変化しません。

## API と準備済み復元

以下は責務を説明するAPIの略記です。正確な型・引数は対応するcodec・repository・managerの実装を参照します。

- `CompleteDictionaryBackupCodec.write(snapshot, output)` と `validate(input, privateStaging)` が形式処理を担当します。検証成功時は外から構築できない `ValidatedDictionaryBackup` を返します。
- `SQLiteDictionaryRepository.exportCompleteSnapshot()` は一回の読取トランザクションで全ソース・全候補・抑止・台帳・fallback 方針を読みます。manager が固定した fallback を補い、同一時点のエクスポートを作ります。既存の有効辞書だけの `loadSnapshot()` は使用しません。
- `DictionaryManager.prepareCompleteRestore(input, callback)` は直列 I/O キューで検証し、件数・名前・上書き範囲と、現在 DB の revision を含む `PreparedRestore` を返します。辞書本文はプレビューの既定表示に含めません。
- `DictionaryManager.restoreComplete(prepared, callback)` は同じ直列キューで repository を呼び、復元後に一度だけ検索スナップショットを公開します。
- `SQLiteDictionaryRepository.restoreComplete(validated, expectedRevision)` は全件置換だけを提供し、マージ・部分復元は v1 に追加しません。戻り値は件数と旧バックアップ世代から新実行世代への対応を含む `RestoreSummary` とします。

検証済みファイルはアプリ専用ディレクトリーに固定し、外部 URI を適用時に再読込しません。検証時のバイト数と SHA-256 を記録し、適用直前に再照合します。変更・欠落時は失敗です。内部ハンドル以外からパスを渡せないようにし、キャンセル・確認画面の破棄・成功時に削除します。プロセス再起動後は準備状態を復元せず、改めて検証します。

全外部データの意味検証は書込トランザクション開始前に完了させます。容量・I/O・現在 revision の照合など実行時にしか確定しない条件は、トランザクション内でも検証して例外時に rollback します。

## 原子的置換と世代

辞書 DB に単調増加の `dictionaryRevision` と、前節の fallback 方針を追加します。既存 DB の移行は既存データを保持します。候補変更、抑止変更、ソース追加・削除、有効状態・順序変更、完全復元のすべてで revision を同じ書込トランザクション内で増加させます。プレビュー後に学習などが発生した場合も revision 不一致で適用を拒否し、新しいプレビューを要求します。

復元では一つの SQLite トランザクションで次を行います。

1. `expectedRevision` を照合し、現在の全ソース世代と削除済み ID を含む台帳を確保します。
2. 復元する各ソースの実行世代を `max(現ソース世代, 現台帳世代, バックアップ世代, バックアップ台帳世代) + 1` で割り当てます。存在しない値は 0 とします。Long 加算はオーバーフローを検出し、全体を拒否します。
3. 候補・ソース・抑止を全件置換します。台帳は消さず、既存とバックアップを ID ごとの最大値で統合して新世代を記録します。削除したソースの最終世代も残します。
4. fallback 方針を完全復元済みにし、revision を増加させ、コミットします。

個人世代は空辞書から空辞書への復元でも必ず更新します。復元前の削除確認、抑止解除、個人辞書置換の expectedGeneration は拒否されます。候補の世代だけでは復元前の入力由来要求を判別しないため、managerのrestore epochで失効させます。入力セッションまたは辞書由来操作の開始時に書込コンテキストを取得し、登録・学習・削除要求へ渡します。保存関数の呼出時だけに epoch を取得すると、復元前から開いていた登録を復元後に初めて保存した場合にすり抜けるため、その実装は認めません。受理時と実際の適用直前にコンテキストを検証し、復元前の許可を無効化します。UI も復元完了通知で候補・登録・削除の旧確認を終了します。DB コミット後、公開失敗時にも epoch を更新し、STALE の旧 snapshot からの入力由来登録・学習・削除は再公開成功まで拒否します。通常文字の入力・検索は続けられます。

DB 外の実辞書ファイルを交換しないため、SQLite のトランザクションでファイル交換を巻き戻せるという前提はありません。検証用一時ファイルの削除失敗は掃除対象で、成功した DB コミットを巻き戻したことにはしません。

## 結果・中断・SAF

コミット前の失敗は既存 DB と公開 snapshot を保持し、`Failed` を返します。UI 向けには `INVALID_FORMAT`、`UNSUPPORTED_VERSION`、`LIMIT_EXCEEDED`、`CAPACITY`、`CONFLICT`、`IO` の理由を区別します。詳細分類は専用結果型で追加しても、既存の全操作結果型へ理由を追加しても構いません。

コミット後の読込・構築・公開失敗は `SavedButNotApplied(summary)` です。「復元は保存済み、入力への反映は未完了」と表示し、再試行は `loadAsync` に限定します。復元トランザクションを再実行しません。再起動は復元後 DB を読みます。コミット前にプロセスが止まれば旧 DB、コミット後なら全復元済み DB が見えることを試験します。

SAF 書き出しはユーザーが「完全辞書バックアップ」を選び、`ACTION_CREATE_DOCUMENT` で保存先を決定した後だけ行います。自動的に実利用者データを書き出しません。まず専用領域で全体の作成・検証を完了し、その後に選択 URI へコピーします。全書込みと close が成功した場合だけ完了表示します。SAF プロバイダーの原子的置換は保証しないため、途中失敗した外部ファイルは未完了として通知します。元の辞書は変更しません。

復元は `ACTION_OPEN_DOCUMENT` で読み、全件検証後に「現在の辞書全体を置き換える」ことと件数を示して適用を受け付けます。選択キャンセル・確認キャンセルでは DB を変更しません。保存先の選択や復元の適用は製品利用時の明示操作であり、開発作業中に実データで試す許可を意味しません。

## 実装と検証の完了条件

codec、全辞書API、revision・fallback方針・epoch、SAF UIは実装済みです。以下は受入条件の一覧であり、実施済みの範囲と残件は [試験対応表](test-coverage.md) に集約します。実利用データ・任意プロバイダーの受入まで完了した意味ではありません。

| 層 | 必須試験 |
| --- | --- |
| JVM codec | 全対象の往復、null・特殊文字・emoji・送り条件・数値テンプレート・候補順、空辞書、重複・未知版・未知フィールド・不正 UTF-8・不正サロゲート・深い入れ子・型違い・末尾切断・件数不一致、各容量境界の直前／一致／直後 |
| repository | 無効ソース・孤立抑止・削除済み台帳を含む全件置換。名前／有効状態／順序を保持。新世代と単調台帳、revision 競合、Long オーバーフロー、復元前確認の拒否、二回復元でさらに世代が進むこと |
| SQLite native | 実 SQLite の容量不足、行置換途中・コミット直前の障害、トランザクション rollback と接続再作成後の内容一致。別プロセスを終了してコミット前後の再起動整合性を検証し、モックだけで代替しません |
| manager | 保存成功／公開失敗の結果と旧 snapshot、再読込だけの再試行、epoch による遅延保存拒否、STALE 中の入力由来保存拒否、復元後 fallback の二重追加と IMMUTABLE 誤分類の防止 |
| Android E2E | テスト用 SAF プロバイダーで作成→別 DB へ復元→変換・抑止・辞書順の確認。選択／確認キャンセル、短い読取、読取例外、書込／close 例外、プロセス再起動を含めます |
| 対象実機 | Xiaomi と実 SAF プロバイダー、物理キー、IME 再起動、最大級辞書の時間・メモリーを確認します。実機不在では未実施として残します |

試験用辞書と分離した DB・一時 URI を使い、実利用者の辞書を置換しません。独立レビューでは特に、入力全件検証の抜け、世代巻き戻り、fallback 再追加、公開失敗後の旧候補による書込み、SQLite と外部ファイルの原子性の混同を確認します。
