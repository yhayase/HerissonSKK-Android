# 登録・学習・候補削除の状態契約

2026-09-16。K09〜K11、K18〜K19 の採用設計です。以下は受入条件であり、実装完了報告ではありません。

## 入力と保存の責務

登録中の本文はコアの編集バッファで保持します。登録本文、子の読み、子の候補を入力先の composition に流しません。入力先には登録開始前の読みを保持し、登録完了時だけ語幹と送りを一度確定します。子の完了は親の編集位置へ挿入し、入力先へは出力しません。

候補未検出と辞書未準備・読込失敗を区別します。後者では登録へ進まず読みを復元し、再試行できる理由を表示します。候補を使い切った場合は最後の候補・ページを戻り先として保持します。

登録フレームは一意なフレーム ID と版、親フレーム ID、検索条件、検索時の辞書世代、戻り先、本文の書記素境界カーソル、内側の変換状態、固定した設定版を所有します。通常かなで出力された文字は登録本文へ挿入します。内側の読み・候補・残余がある Enter はその確定だけを行い、次の Enter で登録保存を要求します。内側に未確定状態がない C-j と空本文の BS は登録を終えません。

C-g は内側の候補、読み、残余を先に取り消します。それらがなければ一段だけ登録を中止します。候補を使い切って開始した登録は最後の候補・ページへ、候補なし検索からの登録は登録前の読みに戻ります。明示登録と保存待ち中止は開始時の戻り先・保存状態に従います。空本文の Enter は保存せず、登録開始直前の読みまたは候補へ戻します。本文内の Left／Right／Home／End／BS／Delete は書記素境界で扱います。

登録スタックは最上位を含めて 16 段、各本文は UTF-16 で 65,536 コード単位を上限とします。上限を超える子登録の開始または挿入は、その操作全体を適用せず、既存の本文、カーソル、内側状態を保って理由を表示します。本文長の検査後もカーソルは書記素境界に限定します。

## 非同期保存と入力接続

ディスク操作は辞書管理器の直列キューで行います。登録の Enter は `SaveRegistration` 効果を一度だけ発行し、一意な操作 ID、フレーム ID と版、親フレーム ID、入力セッション世代、検索条件、本文、元セッションの保存方針を付けます。コアは `Saving` へ移り、この時点では `CommitText` を発行しません。保存待ち中は同じ登録を重ねて保存せず、本文と内側状態を変更しません。

`Applied` と `SavedButNotApplied` はどちらも永続化成功です。同じ操作 ID、セッション世代、フレーム ID と版、親フレーム ID が現在の状態と一致するときだけ成功応答を一度受理します。子なら保存本文を親の現在の書記素境界カーソルへ挿入し、最上位なら入力先への `CommitText` を発行します。`SavedButNotApplied` は再送せず、確定後に辞書の再読込が必要なことを表示します。永続化前の `Capacity`、`Conflict`、`PolicyRejected`、`General` は本文を保持して編集可能な状態へ戻し、安全な理由だけを表示します。再試行は新しい操作 ID を使います。

`Saving` 中の C-g はそのフレームの画面上の操作だけを中止し、「保存処理は完了する可能性があります」と表示します。受理済みの書込みを取り消したとは表示しません。その後の成功は辞書には残りますが、破棄済みの子を親へ挿入せず、破棄済みの最上位を入力先へ確定しません。遅い応答、重複応答、入力欄の切替・接続終了後の応答もコアと入力先を変更しません。

明示的に受理された保存は、その後入力欄を切り替えても完了する可能性があります。入力欄を切り替えると、登録開始前から入力先に表示していた読みだけを従来の `EditorSession.preserveText` と同じ規則で旧入力欄に残し、登録本文、子の読み、候補を新旧どちらの欄にも挿入しません。遅い保存完了も新旧どちらの欄にも挿入しません。

子の保存成功後に親を取り消しても、保存済みの子は残します。送りあり登録は語幹だけを候補本文とし、送り条件を別に保存します。表示・入力先確定にだけ送りを付けます。

## 学習と削除

候補選択時には、検索キー、候補本文、送り条件、表示に採用した注釈、個人候補の有無、全由来の辞書 ID と世代を不透明な選択 ID として固定します。候補の同一性は検索キー、候補本文、送り条件で判定し、注釈は同一性に含めません。学習・削除まで `DictionaryCandidate` だけへ平坦化せず、この選択 ID を保持します。

通常学習の確定成功・保存境界は後述の「通常候補の学習を接続する実装境界」に集約します。保存待ち中の順位を次の検索へ反映し、失敗・失効で取り消す契約は [コア設計](core-design.md#非同期保存待ちの学習順位) を参照します。

候補削除の確認、個人候補とシステム抑止、由来世代、解除と競合の契約は [候補削除設計](candidate-deletion-design.md) に集約します。登録内の候補にも同じ契約を適用し、親の本文と入力先を変えません。

## 個人データの制約

パスワードと TYPE_NULL は既存規則どおりコアを迂回します。通常欄の学習禁止要求、および個人データを保存しない設定では、候補確定時の学習要求を発行しません。登録の確定時も保存を要求せず、理由を表示して本文を保持します。

保存アダプターは受付時とトランザクション開始直前の両方で方針を検査します。入力欄の切替だけでは元セッションで許可された要求を禁止へ変えません。元セッションが学習禁止なら最初から受け付けず、個人データを保存しない全体設定が待機中に有効になった場合はトランザクション前に `PolicyRejected` とします。トランザクション開始後または永続化後は取り消せません。入力欄の世代は完了結果の表示・挿入可否に使い、別の入力欄の方針を過去の要求へ適用しません。

入力本文・辞書本文を例外や診断ログに含めません。保存失敗の説明は容量不足、競合、一般的な保存失敗など、安全な分類だけにします。

## 実装時に必須の試験

- K09 の通常登録、送りありの語幹保存、保存失敗後の本文保持と再試行をコア単体・保存統合で確認します。
- K10 の再帰登録で子の確定が親だけへ入ること、親取消後も保存済みの子が残ること、古い子の完了が別の親へ入らないことを確認します。16 段と本文 65,536 UTF-16 コード単位の境界、その超過で状態を変更しないことも確認します。
- K18 の本文途中編集、結合文字・絵文字、内側の確定と登録確定の Enter 分離を確認します。
- K11 の学習順位、注釈保持、重複抑止、確定拒否後の非学習、候補確定直後の文字入力、削除肯定・否定、世代競合、システム候補の永続的な抑止、システム辞書不変を確認します。
- K19 の入力欄由来の禁止では書込キューへ要求自体が入らないこと、全体設定の変更では待機済み要求がトランザクション前に拒否されることを検査し、再起動後の個人辞書にも残らないことを確認します。
- 遅延保存中の入力欄切替・接続終了、二重 Enter、Saving 中の C-g、重複・古い完了、容量不足・競合・方針拒否・一般失敗、検索世代の公開失敗を制御可能な実行キューで検証します。
- Android E2E では登録本文が入力先へ漏れないこと、入力欄切替時に元の読みだけが旧入力欄へ残ること、最上位の保存成功と `commitText` 成功時に一度だけ挿入することを別アプリから観測します。

## 通常候補の学習を接続する実装境界

通常候補の確定では、確定文字列とは別に、検索条件・確定候補・入力セッション・一意な要求番号を凍結した学習効果を返します。注釈は同一性に含めず、候補本文と送り条件を保持します。直接入力・読みの無変換確定・取消からは学習効果を出しません。登録内で確定した子の候補も入力先への確定ではないため、この通常確定の学習経路では保存しません。登録の最終本文は明示的な登録保存で扱います。

Android接続層は、その効果と同じ結果に含まれる `commitText` の成功を確認してから一度だけ学習を依頼します。確定拒否、無効な入力セッション、学習禁止入力では依頼しません。通常文字で候補確定と次の入力が同じ結果へ合成されても、候補に対応する効果は一つです。保存は入力先への確定を取り消さず、失敗時も入力本文を消しません。

学習の保存は最新の個人辞書の一見出しだけに対して実行し、同一本文・送り条件を先頭へ移します。並行する登録・取り込み後の辞書全体を古いスナップショットで置換しません。保存禁止の受理時検査と書込直前の再検査は登録と共用します。非空注釈の保持、二つの連続確定、保存失敗時の旧順位、入力先確定拒否、禁止欄での要求未投入を別々に検査します。
