# 候補削除・抑止・復元の設計契約

F07、K11、K19 の候補削除契約です。現在の複合辞書、SQLite 保存、
登録・学習の非同期境界を前提に、候補削除を個人候補の削除とシステム候補の
抑止に分けます。DDSKK 固定参照版
`e8bf68b27021c29781dbfa6a8ef7b770565bdb5b` は、候補選択中の `X` で現在候補を
示した明示確認へ入り、肯定後に個人辞書から削除します。本アプリではシステム
辞書を読み取り専用に保つため、同じ操作を永続的な抑止まで拡張します。

## 確認操作と状態遷移

候補選択中の物理 `X` だけが削除確認を開始します。通常文字としての `X` と
混同しない専用アクションに正規化し、確認開始時には候補を確定しません。確認には
読み、候補本文、送り条件を表示します。注釈は補助表示できますが同一性には含め
ません。

初期キーは小文字 `y` を肯定、`n`、`C-g`、Escape を否定とします。Enter、
`C-j`、BS とその他の文字は削除も候補確定もせず、確認を維持して操作案内を表示
します。否定では同じ候補位置へ戻り、辞書、候補順、入力先を変更しません。DDSKK
の固定参照版が使う `yes-or-no-p` と完全に同じ文字列入力 UI にはせず、物理キー
だけで完結する K11 の選択として一打鍵の `y`／`n` を採用します。

肯定時は一意な操作 ID を持つ削除効果を一度だけ発行し、完了待ちへ移ります。
待ち中のキーは候補や登録本文を変更せず、二度目の要求も発行しません。肯定後の
保存は取り消せないため、待ち中の `C-g` は画面上の待機だけを閉じ、「削除は完了
する可能性があります」と表示して、候補を確定できない読みの状態へ戻します。遅い
完了は辞書へ残っても、破棄した状態や別の入力欄へ適用しません。

## 固定する表示候補と保存由来

検索結果を `DictionaryCandidate` だけへ平坦化せず、候補選択時に次を不透明な
選択 ID として固定します。

- 入力セッション世代、選択 ID、実際の入力読み、送り、abbrev の有無
- 表示候補本文、表示に採用した注釈
- 検索時の個人辞書世代
- 候補を構成した全由来について、辞書 ID、辞書世代、個人／システムの区別、
  正規化後の辞書見出し、展開前の候補テンプレート本文、送り条件

表示候補は、現在の `CompositeSkkDictionary` の契約どおり本文だけでまとめます。
同じ本文を作る由来の送り条件や注釈が異なっても、表示上は一候補です。削除要求には
その表示候補が表した全由来を固定し、各由来の保存上の同一性を「辞書 ID、正規化後の
辞書見出し、展開前の候補テンプレート本文、送り条件」で別々に保持します。注釈は
表示用であり、削除の同一性には含めません。採用注釈は従来どおり辞書優先順で最初の
非空値とします。

数値変換では、たとえば入力読み `だい12`、辞書見出し `だい#`、保存候補 `第#0`、
表示候補 `第12` を区別します。削除・抑止には `だい#` と `第#0` を使います。一つの
テンプレートが `#4` などで複数の表示候補を生成する場合、一つを削除するとその由来の
テンプレート全体が対象となり、同じ由来からの他の展開結果も表示されなくなります。
これは現行 SKK 保存形式に展開結果単位の永続 ID がないための最小単位です。確認画面
には表示候補を示し、複数の数値展開を含むテンプレート全体が対象になる場合はその範囲も
示します。

確認表示中に候補一覧が更新されても対象 ID は差し替えません。肯定後、直列保存
キュー内のトランザクション開始直前に、個人辞書世代と固定した全由来の辞書世代を
照合します。どれかが消失または更新されていれば競合として削除せず、最新一覧を
再検索して `X` からの再確認を求めます。同じ本文が残っていても世代変更を黙って
受け入れません。アプリ同梱の読み取り専用辞書は安定した辞書 ID と世代を持たせ、
直列保存キューで固定した公開世代の承認表と照合します。確認時に無効だった辞書や、
その後追加された辞書など、選択 ID が表していない由来は削除・抑止しません。

## 原子的な削除と抑止

一回の肯定操作を一つの SQLite トランザクションにします。

1. 個人辞書世代と全由来世代を検査します。
2. 固定した各個人由来があれば、正規化見出し、展開前テンプレート本文、送り条件が
   一致する候補だけを削除し、残りの順を保ちます。
3. 固定した各システム由来について、辞書 ID、正規化見出し、展開前テンプレート本文、
   送り条件の抑止を
   `INSERT OR IGNORE` します。
4. 個人辞書世代を一度だけ進め、成功時だけコミットします。

システム辞書の候補行、辞書世代、優先順、元の SAF ファイルは変更・削除しません。
個人由来とシステム由来が同じ表示候補へまとまった場合は、固定した全個人由来の削除と
全システム由来の抑止を
同じトランザクションで行います。個人候補だけなら抑止を作りません。システム候補
だけなら個人候補行を作らず抑止だけを保存します。

抑止は由来単位です。削除時に有効だった同一候補の全システム由来を抑止しますが、
後から別 ID の辞書が同じ候補を導入した場合は自動では抑止しません。同じ辞書 ID
の更新後には抑止を引き継ぎます。登録や学習で同一候補を個人辞書へ明示的に追加
した場合は個人由来として表示しますが、既存のシステム抑止は明示復元まで残します。

## 最小の永続形式

既存 DB へ次の抑止表を追加する最小移行とします。

```text
candidate_suppressions(
  source_id TEXT NOT NULL,
  entry_key TEXT NOT NULL,
  candidate_text TEXT NOT NULL,
  okuri_condition TEXT NOT NULL,
  PRIMARY KEY(source_id, entry_key, candidate_text, okuri_condition)
)
```

送り条件なしは空文字で保存します。現行の辞書形式は空の送り条件を許可しないため、
`null` と衝突しません。`entry_key` の検索索引を設けます。組み込み辞書と取り外した
辞書の抑止も保持できるよう `source_id` に外部キーを付けません。新規取り込みは
新しい UUID を使うため、取り外した辞書と偶然同一視しません。

スナップショット構築時に、各システム由来へ完全一致する抑止があればその由来だけを
除きます。他に未抑止の由来または個人由来が残れば候補は表示します。全由来が消えた
候補だけを一覧から除きます。個人辞書のマージ、置換、書き出し、システム辞書更新は
抑止表を変更しません。SKK テキストには抑止を表す互換形式がないため、個人辞書の
書き出し対象は候補行だけとし、画面でその範囲を明記します。

## リポジトリ境界とスナップショット世代

最小 API は保存値だけを受け取り、表示用本文や注釈を永続 ID として受け取りません。
型名は実装時に調整できますが、境界は次の形にします。

```kotlin
data class StoredCandidateOriginRef(
    val sourceId: String,
    val sourceGeneration: Long,
    val kind: CandidateOriginKind,
    val entryKey: String,
    val templateText: String,
    val okuriCondition: String?,
)

data class DeleteCandidateRequest(
    val expectedPersonalGeneration: Long,
    val origins: List<StoredCandidateOriginRef>,
)

data class CandidateSuppressionKey(
    val sourceId: String,
    val entryKey: String,
    val templateText: String,
    val okuriCondition: String?,
)

fun deleteCandidate(
    request: DeleteCandidateRequest,
    approvedImmutableSources: Map<String, Long>,
    mayWrite: () -> Boolean,
): DictionarySourceInfo
fun listCandidateSuppressions(): CandidateSuppressionSnapshot
fun restoreCandidateSuppression(
    key: CandidateSuppressionKey,
    expectedPersonalGeneration: Long,
): DictionarySourceInfo
```

`deleteCandidate` は空要求と重複した由来を拒否し、一トランザクション
内で保存済み辞書の存在、種別、全世代を検査します。組み込み辞書は DB に由来行がない
ため、管理器が同じ直列キュー上で固定した不変の辞書 ID・世代表と完全一致する場合だけ
抑止できます。要求に未知の組み込み辞書 ID を書くだけでは受理しません。復元は対象辞書
が取り外されていても、完全一致する抑止を削除できます。

すでに同じ抑止がある由来は、確認時の表示候補に含まれないはずなので競合として拒否
します。削除要求は冪等な成功にはせず、固定した世代と一意な操作 ID で通常の再送を
防ぎます。応答喪失後は最新スナップショットを再読込し、表示される候補だけを改めて確認
します。

個人辞書の世代を、個人候補と抑止を合わせた利用者所有の辞書状態の版として使います。
個人候補を削除しないシステム抑止だけの操作、復元も、成功時にこの世代を一度だけ進め
ます。検索対象の候補行・抑止・ソース世代を一貫した読み取りで固定します。管理器は書込成功後に管理情報を更新し、旧世代のキャッシュを失効させます。通常の公開で全候補を読み直しません。公開失敗時は旧公開状態を維持し、`SavedButNotApplied` を返します。詳細は [ストレージとキャッシュ](dictionary-storage-cache-design.md) に従います。復元一覧も抑止行と個人辞書世代を同じ
読み取りトランザクションで返します。

辞書 ID を削除後に再利用して古い世代と一致することを防ぐため、辞書 ID ごとの最終世代
を、辞書行を削除しても残る台帳で管理します。新規追加、更新、同じ ID の再追加では台帳
から必ず単調増加させます。抑止キーには世代を含めず、同じ ID の辞書更新後にも抑止を
維持します。世代は確認後の差し替えを拒否するためだけに使います。

抑止は表示候補への本文まとめと数値展開より前に、保存由来へ適用します。同じ表示本文に
まとまった由来のうち、削除確認時に固定されなかった無効辞書や新しい辞書の由来には影響
しません。数値変換層は学習対象とは別に各表示結果の外側テンプレート由来を保ち、複数の
テンプレートが同じ表示本文へ収束した場合は、その全由来を表示候補へまとめます。`#4`
が参照した数値そのものの辞書候補は削除対象にしません。

## 復元 UI

辞書管理画面に「非表示にしたシステム候補」を追加し、抑止を検索キー、候補本文、
送り条件、由来辞書名で一覧表示します。由来辞書が現在なければ「現在利用できない
辞書」と表示し、内部 ID を製品文言へ出しません。一件ずつ「再表示する」を選び、
対象を示す確認後に抑止行だけを原子的に削除します。個人辞書から削除済みの候補は
復元せず、そのシステム由来が現在存在する場合だけ再び検索結果へ現れます。

一覧取得時の個人辞書世代を復元要求へ付けます。世代が変わっていれば無変更で一覧を
更新し、再操作を求めます。存在しない抑止を成功扱いにしません。復元成功でも公開
スナップショット更新に失敗した場合は「保存済み・未反映」を区別し、再読込操作を
案内します。候補本文は画面の明示一覧以外のログ、例外、診断へ含めません。

## 個人データ方針と登録中の操作

パスワード欄と `TYPE_NULL` は従来どおりコアを迂回するため、候補削除へ入りません。
通常欄でも入力先の学習禁止要求または「個人データを保存しない」設定が有効なら、
`X` による削除は個人辞書も抑止表も変更するため受け付けず、候補を保持して理由を
表示します。登録・学習と同じ許可証を受付時とトランザクション開始直前に検査し、
待機中に全体設定が禁止へ変わった要求も実行しません。

辞書管理画面からの復元は、入力欄に由来しない明示的な管理操作です。入力セッション
の学習禁止とは分離し、復元できない状態を作らないため管理画面から実行可能とします。

登録中の内側候補でも同じ確認を使えます。成功後は親の登録本文、カーソル、入力先の
composition を変えず、内側の同じ検索だけを最新世代でやり直します。候補がなくても
自動で子登録を開始せず、内側の読みへ戻して次の操作を待ちます。登録保存待ち中には
候補削除を開始しません。

## 非同期完了と失敗境界

`Applied` では最新世代で同じ検索をやり直し、削除した候補を除いた一覧へ移ります。
`SavedButNotApplied` は永続化成功として再送せず、画面上の固定候補を現在の一覧から
除外して辞書再読込を案内します。候補がなくなった場合は読みへ戻し、削除を契機に
単語登録へ自動遷移しません。

容量不足、競合、方針拒否、一般失敗では候補と読みを保持し、候補本文を含まない理由
だけを表示します。競合時だけ最新検索後の再確認を求めます。同じ操作 ID の重複応答、
別の選択 ID、入力セッション切替後、確認取消後の応答はコア、登録本文、入力先を変更
しません。トランザクションのどこで失敗しても、個人候補削除、抑止追加、世代更新を
すべてロールバックします。

## 必須試験

- コアで `X` が候補を確定しないこと、`y` だけが一要求を発行すること、`n`、
  `C-g`、Escape、Enter、`C-j`、BS、二重 `y`、遅延・重複完了を検証します。
- 確認開始後に候補や世代が変わっても固定 ID を別候補へ適用せず、個人辞書または
  一つのシステム由来の世代変更で競合することを検証します。
- 個人だけ、システムだけ、重複由来、個人＋複数システム由来を削除します。同じ表示本文
  にまとまった送り条件違いを含む全保存由来を処理し、確認時に無効だった辞書や後から
  追加された辞書の未固定由来は残します。注釈差だけでは別候補にしません。
- 数値入力では表示本文ではなく正規化見出しと展開前テンプレートを削除・抑止し、一つの
  `#4` テンプレートから出た別の展開結果にも同じ抑止が効き、内側の数値辞書候補は残る
  ことを検証します。
- 各書込故障点で個人候補、抑止、世代が一緒にロールバックし、再起動後も旧検索結果が
  一致することを実 SQLite でも確認します。
- 同一システム辞書の更新後も抑止が効き、システム候補行と世代を削除操作が変更せず、
  別 ID の新規辞書は自動抑止しないことを確認します。
- 復元で対象抑止だけが消え、削除済み個人候補は復活せず、取り外し済み由来も安全に
  一覧・復元できることを確認します。
- 学習禁止セッションでは要求をキューへ入れず、待機中の全体方針変更では書込直前に
  拒否します。管理画面の復元が入力セッション方針に依存しないことも分けて試します。
- 登録中の削除成功・取消・失敗で親本文と入力先が不変であり、通常候補でも削除完了
  だけでは入力先へ文字を確定しないことを JVM と Android E2E で確認します。
