## 適用単位と保存境界

入力セッションの開始時に、次の不変な `CustomizationSnapshot` を一つ固定します。

- ローマ字プロファイルと検証済み規則木
- 句読点・記号プロファイル
- 状態別のコマンド割り当て
- 候補ラベルとページ表示方針
- 設定のスキーマ版、保存世代、各カテゴリの標準値との差

設定変更は次の Android `onStartInput` から反映し、入力中の読み、候補、登録本文、削除確認、
補完巡回を確定も消去もしません。未確定入力が空へ戻るたびに差し替える案は採用しません。
固定した `InputConnection` と設定世代の対応を一つにし、同じ入力欄で設定変更が途中から混ざる
ことを避けるためです。同じ入力セッション内では画面回転や辞書再公開があっても設定世代を
差し替えません。個人データ保存禁止のように保存直前にも確認する方針はこのスナップショット
の対象外です。

この文書で新設するカスタマイズ項目だけを、`documentVersion` と単調増加する `generation` を
持つ JSON としてアプリ専用領域の `AtomicFile` へ UTF-8 で保存します。`show_status`、
`dynamic_completion`、個人データ保存方針など既存の一般設定は当面 `SharedPreferences` に残し、
JSON へ移行も二重書きもしません。個人辞書も JSON に含めません。

読み込みと保存は一つの直列 executor に限定します。設定画面は読み込んだ `generation` を保持し、
保存時に `expectedGeneration` として渡します。公開世代と一致しなければ一切書かず競合を返し、
再読込後に利用者が変更を見直します。全カテゴリを解析・検証し、次世代を一つの文書として
`finishWrite` できた場合だけ公開して成功を表示します。失敗時は公開済み世代を維持します。
文書内の版と世代を唯一の正本とし、別の移行済みフラグは置きません。

`AtomicFile` のバックアップは中断した書き込みを回復するために使います。構文が壊れた主ファイル
から任意の過去世代を復元できるとは扱いません。読み込み時に JSON の版、構文、値を検証できない
場合は不正ファイルを上書きせず保持し、メモリー上の標準カスタマイズと一般化した復旧案内を使い
ます。標準値の保存は利用者が「カスタマイズを標準へ戻す」を明示してから同じ世代照合で行います。
この操作は個人辞書と既存の一般設定を変更しません。

設定画面には「保存」「変更を破棄」「カスタマイズを標準へ戻す」を表示します。復旧操作は
カスタムキーに依存せず、タッチと Android の通常フォーカス操作で実行できます。カテゴリ別の
初期化は提案、設定ファイルの取り込み・書き出しはその他の後続です。

## ローマ字規則

一件の規則は次の値を持ちます。

```text
input          入力列
output         規則成立時の出力
remaining      成立後も未消化として残す入力列
terminalOutput Enter、C-j、読み確定時だけ使う出力（省略可）
```

標準プロファイルは現行規則をそのまま独立データにします。カスタムプロファイルは標準への
「追加・置換・無効化」を保存せず、適用後の完全な規則集合を保存します。これにより標準規則の
更新で既存カスタム設定の意味が変わりません。画面には元にした標準版を表示します。

入力列は 1〜16 文字の ASCII 図形文字とし、2 文字以上の入力列では最後の一文字だけ空白を許します。`z<SPACE>` を規則として扱うためです。`remaining` は空文字または最大 16 文字の ASCII 図形文字です。制御文字、surrogate、改行を許しません。`output` と `terminalOutput` は正しい UTF-16 で各 64 コード単位以下、規則は最大 4,096 件、全文字列の合計は 1 MiB 以下とします。

SKK では大文字を読み・送り開始へ使うため、入力と残余の大文字を原則拒否します。例外は標準と同じ `zL → ⇒`（残余・終端出力なし）だけです。標準規則をそのままカスタムへ複製できます。有効な規則の継続は標準・カスタムのどちらでも文字コマンドより優先します。継続にだけ使う記号を単独入力で規則開始とみなさず、通常の句読点処理を維持します。

適用前に次を検証します。

1. `input` は一意とします。同じ入力列の後勝ちは許しません。
2. `k` と `ka` のような接頭辞共有は正当です。完全一致しても、より長い `input` の接頭辞なら
   次の入力を待ちます。次の入力で長い規則に一致しなければ、成立済みの最長の非終端規則を適用
   して残りを再評価します。長い接頭辞がなければ非終端規則を直ちに適用します。
3. `remaining` をたどる有向グラフに循環がなく、各書換えが有限回で停止することを保存時に
   証明します。実行時にも一打鍵当たり「規則数 + 1」回を上限にします。
4. `terminalOutput` を持つ規則は終端時だけ成立し、`output` と `remaining` は空でなければなりません。
   終端出力のない完全一致は終端時に通常の `output` と `remaining` を適用します。出力、残余、
   終端出力をすべて持たない規則、不正 UTF-16、上限超過を拒否します。
5. プロファイルが文字キーを SKK コマンドより先に取得する場合、その文字と重なる全コマンド
   に代替キーがあることをキー競合検査で確認します。

検証失敗時は行番号、項目、理由を表示しますが、規則本文を一般ログへ出しません。一件だけを
黙って無視した部分適用はしません。保存前試行を初回UIに採用する場合は、新しい変換器を別インスタンスで動かし、
公開中の入力セッションを変更しません。取り込み・書き出し UI は任意拡張として後回しにし、
実装する場合も同じ版付き JSON と全件検証を使います。

## AZIK

AZIK は必須の選択プロファイルです。一次仕様は考案者の木村清による
[「AZIK総合解説書」2025年5月改訂版](https://note.com/actbemu/n/n74f1c04c9a2e)
（2025-05-01 公開、2026-09-16 確認）に固定し、QWERTY 配列の論理文字を初期対象にします。
撥音拡張、二重母音拡張、互換キー、特殊拡張という仕様上の分類と、公開された入力例から期待
動作を独立に記述します。一次仕様の表や文章をアプリへ複製せず、規則データと受入例を本プロジェクト
で独立に作成します。初回の仕様照合には少なくとも `kz` → `かん`、`kgp` → `きょう`、
`ngz`／`ngn` → `にゃん`、`:` → `ー` を含め、通常ローマ字と併用できることも確認します。

SKK との統合は DDSKK `ddskk-17.2_Mena` の固定コミット
`e8bf68b27021c29781dbfa6a8ef7b770565bdb5b` にある `skk-azik.el` と同版マニュアルを参照します。
ここでは `q` を撥音入力に使うためかな切替を英語配列の `[` へ移すこと、小書き母音を `la` では
なく `xxa` などで入力すること、一部の標準規則を除いて AZIK 規則を適用することが確認できます。
この統合事実も動作だけを独立実装し、GPLv3 の規則表やコードを転記しません。

AZIK プロファイルは標準規則への単純追加ではなく、専用の完全規則集合、かな切替割り当て、
文字所有範囲を一体として検証します。通常入力、読み開始、送り開始、登録内入力、撥音、促音、
小書き文字、かな切替の受入例が揃うまで K17 の AZIK 対応を完了扱いにしません。利用者による
外部プロファイル取り込みを必須対応の代替にはしません。JIS／US配列は初回の検証対象です。ACT、かな入力、
親指シフト、TUT-codeはその他の後続です。

## 句読点と記号

句読点はローマ字表を書き換えず、コマンド判定後の文字入力へ適用する別レイヤーにします。
ひらがな・カタカナの通常入力と読み入力に共通して適用し、直接入力と abbrev には適用しません。
半角カナは既存の半角変換を使い、この「あ／ア」設定から独立させます。登録の内側でも現在の
内側モードに同じ規則を使います。

必須の選択肢は次です。

| 入力 | 選択肢 | 標準 |
| --- | --- | --- |
| `.` | `。`、`．`、`.` | `。` |
| `,` | `、`、`，`、`,` | `、` |
| `(` と `)` | `（ ）`、`( )` | `（ ）` |
| `[` と `]`、`{` と `}` | 全角の組、半角の組 | 半角の組 |

開き・閉じ記号は組で保存し、片側だけ異なる幅にはしません。出力は正しい UTF-16 の 1〜8 コード
単位、改行なしとします。「テーブルに従う」はカスタム規則がそのキーを取得する場合だけ選べます。
`/`、`>`、大文字、Space など状態上の SKK コマンドを記号設定で上書きしません。任意の記号別
上書き、モード別上書き、直前文字種による自動句読点は任意拡張として延期します。

## コマンド割り当て

割り当て対象は、モード切替、読み開始、変換・次候補、前候補、確定、取消、半角切替、接頭辞・
接尾辞、通常補完の前後、動的補完受諾、候補削除確認と、S02 の Emacs 編集操作です。コアには
意味を持つ `BasicSkkAction` だけを渡し、Android のキー表をコアへ持ち込みません。

一つの入力ジェスチャーは次のどちらかです。

- OS 配列適用後の Unicode scalar と Ctrl／Alt／Shift の組
- Enter、Tab、Escape、矢印など文字を生成しない Android key code と修飾の組

物理位置や US／JIS の独自再配置は初期対象外です。まず `getUnicodeChar` と dead-key 合成を
完了し、右 Alt 等で実際に文字が生成された場合は AltGr の文字として扱います。その後に状態別
コマンド、候補ラベル、内部編集、入力先編集、未割当キーの引き渡しの順で解決します。

現行コアの `q`、`Q`、`l`、`L`、Space、`>`、大文字による読み・送り開始は文字分岐に埋め込まれ
ています。カスタム実装では、割当可能なものを `ToggleKana`、`StartReading`、`StartAbbrev`、
`StartSuffix`、`StartConversion` などの意味操作へ分離します。文字を生成したジェスチャーについて
は、現在状態で明示的なコマンド割り当てがあればその操作、なければプロファイルが所有する入力、
句読点設定、通常文字の順で一度だけ処理します。大文字による読み開始と送り境界は SKK 文法と
してプロファイルに明示し、単なる `lowercase()` で修飾情報を失いません。これにより AZIK の
`q` を入力規則へ渡しながら、移動先へ設定したかな切替を同じ打鍵で重ねて実行しません。

割り当てには適用状態を持たせます。少なくとも通常、未消化ローマ字、読み、abbrev、候補、候補
一覧、登録本文、登録内の各入力状態、保存待ち、削除確認、補完巡回を区別します。同じジェスチャー
でも適用状態が交わらなければ競合ではありません。状態が一つでも交わり、異なる操作へ到達する
場合は保存を拒否して、競合する操作名と状態を表示します。

次の予約境界は変更できません。

- パスワード欄と `TYPE_NULL` の全面迂回
- AltGr を含む文字生成の優先
- 保存待ちの二重送信防止と、削除確認の明示的な肯定
- OS の Back、設定画面の標準復旧操作

候補削除の肯定 `y` など危険な確認文字を変更可能にする場合も、一打鍵の明示肯定を維持し、通常
文字を確認画面から入力先へ漏らしません。最低一つの確定と取消経路が各状態に必要です。すべてを
消す設定は拒否します。

Emacs 編集は一括オン／オフを必須とし、初期値はオフです。C-a/C-e、C-b/C-f、C-h/C-d、C-k、
C-p/C-n、M-b/M-f の論理行、縦移動の目標列、Unicode 書記素、決定的な単語境界、C-k の改行
削除、内部状態と入力先の配送・失敗境界は [emacs-editing-design.md](emacs-editing-design.md) を
正本とします。表示行移動、kill ring、C-y は対象外です。カスタマイズ層はオン／オフと競合のない
コマンド割り当てだけを保存し、編集意味を変更しません。

## 候補ラベルとページ

候補設定は次の不変値としてコアへ渡します。

```text
labels            例: "asdfjkl" または "1234567"
inlineCount       一覧前の単独候補数（初期値 2、範囲 0〜9）
showCompositionMarkers  未確定の表示記号（初期値 false）
pageMode          Fixed(count) または Auto(minSlotDp)
```

既存UIのラベルは ASCII のプリセット `asdfjkl` と `1234567` から選びます。初期値は
`asdfjkl`、`inlineCount` は 2、固定ページ数は 7 です。候補状態の次候補、前候補、取消、
削除確認、確定に割り当てたジェスチャーとの重複は拒否します。任意ラベル列と Unicode scalar
ラベルの編集は、コードポイント単位の入力・選択契約を別に追加してから提供する任意拡張です。

`Fixed(count)` は `1..labels.size` を許します。実際に表示する件数は幅・高さ・文字倍率でも制限します。ページ件数とラベルを選択中に固定する契約、横並び配置、本文・注釈の省略と全文導線は [候補表示設計](candidate-display-design.md) に集約します。アクセシビリティ説明へ全文を無制限に格納しません。候補選択キーは [互換性仕様](compatibility.md) に従います。注釈の表示オフは未実装です。

## 検証と受入境界

- カスタム `ka → か゚`、`n` の終端、残余を持つ促音、正当な接頭辞共有、重複・循環・不正 UTF-16・
  上限超過を JVM で検証します。
- 標準、カスタム、AZIK の各プロファイルで通常入力、読み、送り、登録内入力、確定、C-g、BS、
  モード切替を同じ状態表で検証します。AZIK は上記の固定出典から独立記述した受入例を使います。
- 句読点の全組合せを、ひらがな、カタカナ、半角、直接入力、abbrev、読み、登録内で確認します。
- キー競合は同一状態、状態非重複、AltGr、dead key、未割当 Ctrl／Alt、保護入力を検証します。
- `asdfjkl` と `1234567`、固定 1/7、自動の最小・最大、端数ページ、回転中のラベル不変、長い
  本文・注釈を検証します。全候補へ物理キーだけで到達できることを確認します。
- 保存前取消、世代競合、保存失敗、中断書き込みのバックアップ回復、構文破損時の非上書きと
  メモリー標準、再起動、明示的な標準復旧を辞書から分離した設定試験で確認します。復旧前後で
  個人辞書と既存 `SharedPreferences` が変わらないことを確認します。

ここで扱う設定は既存実装の契約です。初回UIの再設計と未実装のアプリ別設定、後続の任意ラベル等の範囲は [ロードマップ](roadmap.md) に集約します。入力試行は初回UIの目的に必要なら含めます。

## 統合時に確定した契約

設定文書の現行版は 4 です。版 1 は現在の標準キーで読み込みます。版 2・3 の半角カナが旧標準 C-q の場合はその割当を外し、競合がなければ引用を C-q に追加します。半角カナの明示的な別キーや、C-q を使う別操作は保持します。版 2 は追加の省略可能操作も既存割当を優先して補います。版 4 未満の表示記号はオフとして読み、次の明示保存で版 4 を書きます。一般設定や辞書は移行しません。

既存のキー設定UI は操作ごとに一つのキーを指定します。適用状態は操作の契約に固定し、状態集合自体の編集は提供しません。通常・未消化・読み・abbrev・候補・一覧、登録の内側、保存待ち、削除確認、読み／abbrev の補完巡回を配送と競合検査で区別します。Emacs 編集がオフならそのキーは配送と競合検査の対象外です。オンにして保存する時には同じ集合で衝突を拒否します。

キー表記は `C-` が Ctrl、`M-` が Alt、`S-` が Shift、`U-` が修飾なしの生成文字を表します。`U-Q` は Shift／CapsLock のどちらで作られた Q でも同じ操作になり、`U->` は配列による Shift の差に依存しません。明示的な `S-Q` とは照合方針が異なります。両方が同じ実ジェスチャーを受け付ける場合は状態の重複として検査します。特殊キーは `<ENTER>`、`<TAB>` など、空白は `<SPACE>` です。

AZIK の専用文字、および標準規則から追加・変更したカスタム規則の先頭文字を、同じ状態の文字コマンドが取得する設定は保存できません。既存標準規則の複製は標準のコマンド優先関係を引き継ぎます。標準・非標準のどちらでも、有効な規則継続は途中の文字コマンドより先に処理します。

保存待ちと削除確認では通常のモード操作を解決せず、取消・確認だけを優先します。削除確認の `y`／`n` は予約し、キー変更から奪えません。OS の Back と保護入力はこの設定で上書きしません。

引用 `QUOTE_NEXT` と半角カナ `HALFWIDTH` は省略可能な割当です。標準は引用 C-q、半角カナは未割当とします。引用は Android 接続層で次の物理キーを渡す操作で、コアの文字種切替ではありません。修飾キー単独と引用開始キーの反復では待機を消費せず、入力欄・構成の変更などで待機を取り消します。

表示記号の設定は接続層だけに適用し、読み・辞書キー・学習・確定本文へ混入させません。入力先の本文読戻しに対応していることを付与条件とします。終了時の一致確認と除去できない場合の制約は [候補表示設計](candidate-display-design.md) を参照します。
