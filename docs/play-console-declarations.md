## データ セーフティの回答ゲート

Google は「収集」をアプリから端末外へのユーザーデータ送信と定義します。SDK による送信も含みます。端末内だけの処理は収集に該当しません。端末外での一時処理は質問票には記入し、厳密な条件を満たす場合だけストア表示から除外されます。「共有」には第三者への端末外送信のほか、他アプリへの端末内直接転送も含まれます。一方、サービス提供者による指示に基づく処理や、利用者が具体的に開始し共有を予期する転送などは共有表示の例外があります。いずれも単なる HTTPS の利用だけで例外になるわけではありません。[Google の定義](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)。

| データ・経路 | 暫定回答 | 確認が必要な点 |
| --- | --- | --- |
| 入力文字・周辺テキスト・学習・個人辞書 | 現行本番コードでは端末内で処理・保存。通常欄では学習が既定で有効。データ セーフティの「収集」は **いいえ** の候補 | 公開 AAB に送信経路がないことを再確認します。パスワード欄では変換・候補・学習を抑止しますが、IME としてキーイベントは扱います。 |
| 起動可能アプリ一覧、アプリ別設定 | 端末内で一覧化し、選択したパッケージ名のみ保存。「インストール済みアプリ」の収集は **いいえ** の候補 | 公開 AAB と推移的依存を確認します。 |
| GitHub Pages の辞書配布通信 | 初期設定で S／L がどちらもない場合に S を自動取得します。S／L／jinmei／geo の配布元は GitHub Pages。通信先には IP 等の要求情報が届き、GitHub Pages はセキュリティ目的で訪問者 IP をログに記録・保存すると説明しています | **推奨案（保守的な解釈）:** デバイスまたはその他の ID（IP アドレス）を収集・共有、非一時的、必須として申告します。目的は「アプリの機能」（辞書配布要求に必要なネットワーク通信という推論）と「不正利用防止、セキュリティ、法令遵守」（Google の一つの選択肢。Pages が明記するのはセキュリティ目的）を候補にします。Google が IP を必ずこのデータ型・共有に分類する明示要件ではありません。初回の自動取得は利用者による個別の取得操作やオプトアウトを伴わないため、必須の提案です。[GitHub Pages のログ説明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#data-collection)。 |
| 郵便番号辞書および任意 URL | 郵便番号辞書は `raw.githubusercontent.com` から取得します。利用者は任意の公開 HTTPS URL も指定できます。接続先には IP 等の通信情報が届きます | Pages のログ説明を Raw や任意 URL に一般化しません。Raw 配布元・任意 URL・リダイレクト先の運用条件は別途未確認です。任意 URL は利用者が明示入力した場合だけ対象です。 |
| SAF による辞書書出し・完全バックアップ | ローカル保存先への読書きは端末内。利用者がクラウド文書プロバイダーを選ぶと、そのサービスへの転送が起こり得ます | **推奨案:** クラウド保存先への明示的な転送を「ファイルとドキュメント」／任意／アプリの機能として申告します。利用者が選んだ保存先への共有表示例外が適用される可能性があります。Drive／Dropbox の「アプリがデータにアクセスしない」FAQ 例外は、このアプリが作成・読み取る辞書・バックアップにはそのまま当てはまりませんが、すべての SAF 転送を収集扱いと決める根拠にもなりません。Console の実際の質問票で要検証です。バックアップは暗号化されません。 |
| クリップボード | kill-line が削除文字列を OS クリップボードへ書き、連続操作時に自ら書いた項目を確認します。アプリ自身のネットワーク送信はありません | これは端末内の OS 共有領域への書込みです。他アプリが読める可能性だけを理由に、アプリによる端末外収集として扱いません。一般的なクリップボード履歴取得はありません。 |
| 計測・広告・障害報告 | 現行本番依存に Analytics、Crashlytics、広告 SDK はなく、送信経路も見つかりません | 公開 AAB の推移的依存・merged manifest と実機通信を確認します。Google Play／OS 自身の処理はアプリの独自 SDK と混同しません。 |

**推奨する保守的な入力案は「はい」です。** GitHub Pages の既定辞書配布が IP をセキュリティ目的でログ保存するとの説明に基づき、デバイスまたはその他の ID（IP アドレス）を収集・共有、非一時的、必須とする案です。目的は辞書配布要求に必要なネットワーク通信としての「アプリの機能」と、Pages が記録する IP ログについて明記するセキュリティ目的を候補にします。Google の「不正利用防止、セキュリティ、法令遵守」は一つの選択肢であり、Pages が明記するのはセキュリティ目的です。このデータ型・共有扱い・必須性は Google が明示的に定めた IP の一律分類ではなく、確認した事実から導く保守的な申告案です。必須性の根拠は初期設定時、S／L が未導入なら S が自動取得され、個別の取得操作やオプトアウトがないことです。クラウド向け SAF 書出しは別途「ファイルとドキュメント」／任意／アプリの機能を推奨し、Console の実際の質問文で共有例外を確認します。GitHub Pages の説明を Raw や利用者指定 URL へ一般化しません。辞書通信は HTTPS ですが、任意の SAF 保存先や推移的 SDK も含む全体の暗号化回答は未確定です。ログの保持期間や削除依頼の可否も未確認です。Google は不確かな場合に[下書き保存を認めています](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)。

この提案は、[現行コードの監査](audit/play-data-flows.md)と[公開ポリシー](site/privacy-policy.html)に整合させます。辞書配布元と任意の HTTPS 先は、入力内容・個人辞書・固定の端末固有 ID・アプリ一覧を要求に付加しません。固定 User-Agent `skk-android/1` はインストール ID ではありません。GitHub Pages のポリシー閲覧は外部ブラウザーの処理で、アプリ内辞書取得と別経路です。

## 審査担当者へのアクセス案内文案

> アカウントとログインは不要です。アプリを開いて初期設定を進め、「入力方法を有効にする」をタップして Android の設定で HerissonSKK を有効にしてください。続けて「入力方法を選ぶ」をタップし、HerissonSKK を選択してください。後で設定する場合は「あとで設定する」を選び、設定 → 辞書の管理から辞書を導入できます。任意のテキスト欄を開いて日本語入力を試してください。初期設定時に基本辞書 `SKK-JISYO.S` を取得します。インターネットに接続できない環境では、設定 → 辞書の管理から SKK 形式の辞書ファイルを選択して導入できます。辞書が必要な状態で取得が失敗した場合は、接続を確認して辞書設定から再取得してください。権限ダイアログで連絡先・位置情報・マイク等の許可を求めません。アプリは `INTERNET` 権限を宣言しています。

OS の IME 有効化画面に表示される警告は Android の標準画面です。テストでは架空の文章を使用してください。審査用に資格情報や専用アカウントは必要ありません。実際のボタン名・画面遷移は Play 経由のインストールで確認してから案内文へ反映します。[審査アクセスに関する公式案内](https://support.google.com/googleplay/android-developer/answer/9859455?hl=en)。


## 提出時に確定する点

データ セーフティの IP アドレスと SAF 転送の分類、GitHub Pages のログ保持・削除条件、GitHub Raw と任意 URL の条件、公開 AAB の依存 SDK・権限・実通信、IARC の結果は草稿段階では確定していません。Console の質問文と公開版の実態に合わせて、この申告案・掲載文・プライバシーポリシーを照合します。対象年齢は 13–15 歳、16–17 歳、18 歳以上で、13 歳未満は含めない方針です。後から追加する場合は Families 要件と関連申告を見直します。テストと提出の順序は[配布手順](distribution.md)を参照してください。
