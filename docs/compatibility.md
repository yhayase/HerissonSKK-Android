## 基準と設定

- 基準は DDSKK 17.2 リリース（タグ `ddskk-17.2_Mena`）、コミット `e8bf68b27021c29781dbfa6a8ef7b770565bdb5b` とします。[固定したソース](https://github.com/skk-dev/ddskk/tree/e8bf68b27021c29781dbfa6a8ef7b770565bdb5b)。ローカルの `/home/hayase/tmp/ddskk` でリリースタグの参照先を確認しました。作業ツリーの変更やタグ以外の版を基準に含めません。
- 標準のローマ字規則を基準とし、個人の `.skk` は読み込みません。通常学習と数値変換は有効、動的補完は初期状態では無効にします。ネットワーク辞書は無効にします。
- Enter は未確定入力があれば確定だけに使います。見出し語・候補では DDSKK の `skk-egg-like-newline = t` に対応しますが、通常かな状態の未消化ローマ字にも適用する点は Android 独自の仕様です。未確定入力がない Enter は入力先へ渡します。
- 最初の 2 候補は単独表示し、3 候補目から `a s d f j k l` の最大 7 ラベルで一覧表示します。一覧開始位置は 1〜10 候補目から設定でき、`1234567` への変更、固定数／画面幅による自動調整にも対応します。画面高と文字サイズによる上限も適用します。
- 送り条件に一致する個人辞書候補を優先します。比較用 DDSKK は `skk-henkan-strict-okuri-precedence = t`、`skk-henkan-okuri-strictly = nil`、`skk-process-okuri-early = nil` とします。不一致候補の除外は初期状態では行いません。
- 新しい入力セッションはひらがなで開始し、パスワード欄は直接入力に限定します。アプリをまたいだモード記憶は初期仕様に含めません。
- DDSKK と異なる Android 向けの選択は本書を優先します。DDSKK 実行との自動差分検証は未実施です。

## 追加要求と既存仕様の関係

2026-09-12 に、見出し語内のカーソル編集と、未確定の見出し語がない状態での入力先に対する Emacs 編集キーが追加要求になりました。[ロードマップの追加要件](roadmap.md#androidskk-の実機評価から明確になった要件2026-09-12)を参照してください。以下のキー表と「未割当 Ctrl／Alt を入力先へ渡す」規則は現在の基準です。任意の Emacs 編集設定を有効にした場合の優先順位・状態別動作は、実装前に別途定義します。X01 は Emacs バッファ操作全般を対象外とする規定であり、この限定的な入力先編集を除外する意図ではありません。

## 特殊な入力欄の優先規則

パスワード欄と `TYPE_NULL` では、現行基盤と同じく SKK 処理を迂回し、直接入力に限定します。以下の通常キー表より優先し、C-j・大文字・SPC を含むキーは SKK コマンドとして処理せず入力先へ渡します。候補表示・変換・登録・学習・入力先に対する Emacs 編集を行いません。これは本製品の制限であり、Android 全般で処理が不可能という意味ではありません。

学習禁止要求だけがある通常の入力欄は別です。かな入力・変換・候補表示は可能ですが、学習・登録保存を抑止します。

## 状態と共通操作

`C-j` は Ctrl+j、`C-g` は Ctrl+g、`SPC` は Space、`BS` は Backspace です。大文字は Shift 付き入力を表します。以下の未消化ローマ字の出力例は、開始モードがひらがなの場合です。`▽` と `▼` は状態の説明記号で、確定文字には含めません。入力先にも表示する設定は既定でオフです。本文読戻し未対応の入力先には付けず、終了時は元の位置の本文が一致する場合だけ表示記号を除去します。本文の外部変更などで一致を確認できない場合は削除を推測せず、除去できなかった旨を表示します。

| 状態 | Enter | C-j | C-g | BS |
| --- | --- | --- | --- | --- |
| ASCII、未確定なし | 入力先へ渡します | ひらがなに切り替えます | 入力先へ渡します | 入力先へ渡します |
| かな、未確定なし | 入力先へ渡します | ひらがなにします | 消去対象なしとして消費します | 入力先へ渡します |
| 未消化ローマ字 | ひらがな・標準規則では `n` は `ん`、変換結果のない未消化列はそのまま確定します（`k` → `k`、`ky` → `ky`）。改行しません | 同様に確定しひらがなにします | 未消化部分を捨てます | 未消化部分を一文字削除します |
| 見出し語・abbrev | 読みを確定します。改行しません | 読みを確定しひらがなにします | 見出し語を取り消します | 未消化部分を先に削除し、次に読みを削除します。空の見出し語でさらに BS を押すと通常状態へ戻ります |
| 候補・候補一覧 | 候補を一度だけ確定します | 候補を確定しひらがなにします | 読みを保持して見出し語へ戻ります | 前候補へ戻ります。先頭では見出し語へ戻ります |
| 削除確認 | 確認の明示的な肯定操作だけで削除します | 削除しません | 候補表示へ戻ります | 削除しません |

候補選択に使わない通常文字は、候補確定後に新しい入力として一度だけ処理します。Escape は未確定・登録中では C-g 相当、通常状態では入力先へ渡します。未割り当ての Ctrl／Alt ショートカットは渡します。ただし AltGr などによる文字生成は先に判別し、ショートカットとして一律に除外しません。文字とキー割り当ては OS の選択レイアウトに従います（[レイアウトの責務](validation-plan.md)）。C-q は次の修飾キー以外のキーを、その反復・解放まで入力先へ渡す引用操作です。C-q 自体の反復は引用待機を消費しません。半角カナは初期割当なしで、設定から任意の競合しないキーへ割り当てます。削除確認は候補中の X で開始し、y で肯定、n または C-g で戻ります。通常補完は読み末尾の TAB で開始・前進、Shift+TAB で後退し、端では循環しません。C-g は補完前の読みへ戻します。動的補完は既定でオフとし、有効時の未受諾提案は Right だけで受諾します。提案中の SPC は元の読みを変換し、TAB は通常補完を開始します。詳細は [補完設計](completion-design.md) を参照します。これらのキーを変更する設定はフェーズ 4 です。

ひらがな状態の `n Enter`／`k Enter`／`ky Enter` は、それぞれ `ん`／`k`／`ky` を確定し、ひらがなを維持します。同じ開始状態の C-j も同じ終端処理です。他のかなモードも切替前の文字種で終端処理し、その後 C-j でひらがなへ戻ります。カタカナでは n → ン、半角カナでは n → ﾝ です。カスタム規則の終端出力の表現方法は U03 で定義し、終端出力のない残余列はそのまま保持する方針とします。

Q による空の見出し語開始と、見出し語全体の q によるカタカナ確定は K02〜K03 の基本操作です。候補中・未消化列あり・内部カーソルが途中の場合の Q／q の対象と復帰状態は、コア設計の U01 状態表に従います。入力先の既存文字の取り込みとは分離します。

## 登録の状態遷移

1. 候補なし、または候補を使い切った場合は、戻り先（読み、候補位置、ページ）を保持して登録へ入ります。
2. 登録内に未確定文字がある Enter は登録内での確定だけを行います。次の Enter で非空の登録文字を保存します。送りありは語幹を保存し、入力先へは送りを付けます。
3. 登録内に未確定文字がない C-j は何もしません。空の登録で BS も何もしません。
4. C-g は登録内の候補→見出し語、見出し語→消去、未消化ローマ字→消去の順で内側を取り消します。内側に未確定がなければ登録を一段だけ中止します。最上位では通常入力へ戻します。
5. 空の登録で Enter は保存せず、保持した直前の読み・候補・ページへ戻します。
6. 子の登録完了は親の登録文字だけへ反映します。親を取り消しても、明示的に保存済みの子の辞書項目は残します。

## 標準ローマ字の記号継続

標準規則に `zh/zj/zk/zl/zL` の矢印（順に `←/↓/↑/→/⇒`）、`z<SPACE>` の全角空白を含めます。その他は `z* → ※`、`z, → ‥`、`z- → 〜`、`z. → …`、`z/ → ・`、`z0 → ○`、`z@ → ◎`、`z[ → 『`、`z] → 』`、`z{ → 〖`、`z} → 〗`、`z( → （`、`z) → ）` です。`fa/fi/fe/fo` は `ふぁ/ふぃ/ふぇ/ふぉ` です。読み入力でも継続を優先し、z の後の Space を変換開始、L を全角英数切替・送り開始にしません。単独の記号は通常の句読点設定に従います。

### 送り開始の大文字を母音で指定した場合

見出し語の末尾に未変換の子音があり、大文字の母音で有効なローマ字規則が完成するときは、その子音から送りを開始します。`KasU` と `KaSu` は同じ読み `か`・送りキー `s`・送り `す` で検索します。標準の `zL` など既に定義済みの大文字継続規則を優先し、通常の読み開始や無関係な大文字入力の扱いを変えません。
