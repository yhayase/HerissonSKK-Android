# Android 検証計画

更新日: 2026-09-19。リリース範囲・順序は [ロードマップ](roadmap.md)、実施済みの証拠は [試験対応表](test-coverage.md) と [継続記録](work-status.md) を参照します。本書のケースは計画であり合格記録ではありません。

## 初回の対象環境

- Xiaomi Pad 8とPixel 7の双方で、縦画面・横画面を確認します。Pad 6ではありません。過去のPad 8初回確認は [phase1.md](phase1.md) に保存します。
- 物理キーボードはJIS／US配列を初回対象とします。QWERTYスクリーンキーボードも確認します。OS・アプリの版、実キーボード・接続方式・OS配列を記録します。
- 最低API 26、compileSdk／targetSdk 35は現在の実装値です。API 26／30／35の専用エミュレーターに試験実績がありますが、実機の受入を代替しません。
- 公開はAPKを基本とし、Playの制度・費用は公開前に再確認します。[配布方針](distribution.md) を参照します。

## 品質と検証の分担

利用者の日常利用に支障がないユーザビリティ・機能、DDSKKやCorvusSKKとの操作差異の小ささ、既知の重大な欠陥がないことを初回の基準とします。利用者が操作感を判断し、自動試験と比較操作例で裏付けます。DDSKKの固定版は [互換性仕様](compatibility.md) に従い、CorvusSKKの比較版・操作例は検証設計で具体化します。意図的な差異は理由と制約を記録します。

共通の状態遷移・保存・接続境界は単体試験と検証用アプリで広く検証します。実アプリのE2E・手動確認は入力欄の特性とリスクに応じて絞ります。全アプリ×全端末×縦横×全キーボードの総当たりを要求しません。両端末・縦横・JIS／US・画面キーボードが代表ケースで覆われるよう配分し、問題が出た範囲を追加検証します。具体的なケース配分は実行前に決めます。

結果にはアプリ／入力欄、環境、入力操作、期待結果、実結果、APK識別子、未確認範囲と制約を残します。入力消失・二重確定・誤送信・別欄への誤挿入・辞書破損などの既知の重大欠陥を残して公開しません。

## 初回追加機能の受入設計

- QWERTYでShiftによる変換開始、候補選択・取消・再帰登録をタッチだけで完結し、物理キーボードとの表示切り替えを確認します。
- アプリ別Emacs編集オン／オフで衝突を回避し、アプリ切り替え時の適用を確認します。個別キー割り当ては後続です。
- IME切り替えを物理キーとタッチで確認します。
- 辞書リスト・URLからの導入、手動更新、中断・失敗時の旧辞書保持、無断で更新しないこと、取得後のオフライン変換を確認します。S辞書の提供経路は決定後にケース化します。
- 設定UIは機能の意味・利用目的と操作の流れが対応しているかを利用者と確認し、編集欄の有無だけで合格にしません。
- 候補・注釈・再帰登録の階層と操作対象が、狭幅・大きな文字・縦横でも読めることを確認します。

## レイアウトの責務

Android が物理キーと修飾キーから文字へ対応付ける機構を持つため、IME はその結果を尊重します。`KeyEvent.getUnicodeChar` とイベントの修飾状態を使い、US 配列を仮定してキーコードから文字を自作しません。生のスキャンコードも端末共通の識別子として扱いません。

IME の責務は、その文字・修飾状態を SKK の入力やコマンドへ変換することです。文字入力と Ctrl 系コマンドの判定を分離し、Ctrl による制御文字化だけでコマンドを判定しません。初期のキー割り当ては論理文字を基準にし、物理位置を基準とする割り当ては必要に応じて別の設定として検討します。

記号、Shift／Caps Lock、AltGr、デッドキー、レイアウト切替を試験対象にします。AltGr の文字入力を一律にアプリのショートカットとして除外しないよう、[互換性仕様](compatibility.md)の Ctrl／Alt 引き渡し規則を適用する前に文字生成との関係を判定します。QWERTY 以外のレイアウトについても論理文字を正しく処理することを目指し、実機で確認したレイアウトだけを対応実績として公開します。

## 接続層の受入ケース

| ID | 操作 | 期待結果 |
| --- | --- | --- |
| I01 | Ctrl+j、Shift+文字、キーアップ、長押し | 定義した内部操作が順に届き、二重処理されません。修飾キー対応自体の可否は再調査しません |
| I02 | 候補表示中に Enter、その後もう一度 Enter | 最初は一度だけ確定し、検索・送信しません。次は入力先へ渡します |
| I03 | ASCII でアプリのショートカットを操作 | IME の割り当て以外は入力先の操作として機能します |
| I04 | 未確定文字表示を更新・削除 | 表示と内部状態が一致し、周辺の確定文字を巻き込みません |
| I05 | 辞書検索中に入力欄 A から B へ移動 | A の検索結果を B に反映しません。古い非同期結果を破棄します |
| I06 | 未確定中にアプリ側でカーソル・選択範囲を変更 | 古い位置を使った削除・確定を行いません。IME 自身の更新通知と外部移動を区別します |
| I07 | 再帰登録中に入力先切替・IME 切替 | 登録用文字を別の入力欄へ流しません。未保存の登録状態の終了方針を一貫させます |
| I08 | 回転、接続切断、プロセス終了 | 個人辞書を維持し、再開時に古い確定要求を再送しません |
| I09 | ソフトキーボードを出さず候補・注釈・登録を操作 | 状態を読め、物理キーだけで選択・登録・取消ができます |
| I10 | パスワード・学習禁止欄で入力 | パスワード欄・TYPE_NULL では C-j、大文字、SPC、登録キーでも SKK 処理へ入らず、入力先へ渡して候補を表示しません。パスワードをログへ残しません。学習禁止要求だけの通常欄では変換を許し辞書を変更しません |
| I11 | 絵文字・結合文字の隣で削除 | UTF-16 の途中を破壊しません。登録内ではユーザーが認識する文字単位の削除を検証します |
| I12 | 辞書更新中断・ストレージ書き込み失敗 | 旧辞書を使え、成功と誤表示しません。保存失敗後の再試行で重複登録しません |
| I13 | 複数の OS レイアウトで英字・記号・修飾キー・デッドキーを入力 | OS の文字対応付けを保持し、SKK のキー割り当てが US 固有の位置に依存しません。未確定中のレイアウト変更でも以前のキー状態を持ち越しません |

## 性能の測定方法

デバッグログへ入力本文を記録せず、合成した入力と試験辞書を使います。リリース相当ビルドで機種、OS、辞書ハッシュ・件数、ビルド識別子を記録します。

| 指標 | 測定方法 | 判定時期 |
| --- | --- | --- |
| 初回表示 | プロセス停止状態と起動済み状態を分け、入力開始要求から状態表示までを各 30 回測ります | 実機測定で評価します |
| 打鍵反映 | 合成キーの受信から表示反映までを 1,000 回測り、p50／p95／最大値を記録します | 初回の代表入力で測定します |
| 辞書検索 | 小辞書・大辞書、初回・キャッシュ済み、送りあり／なし、補完を分けて各 1,000 回測ります | 初回の辞書構成で測定します |
| メモリ | 辞書導入前後、検索後、IME 非表示後の PSS を記録します | 初回の代表状態で測定します |
| 学習保存 | 合成の登録・順位変更と、保存中断後の再起動を検証します | 初回 |

性能目標値は測定前の推測で合格扱いにせず、実機結果と操作感を踏まえて記録します。エミュレーターの数値は実機の代用にしません。

予備測定用のビルドと実行手順は [実機の性能測定](performance.md) に記録します。そこで取得する起動・打鍵の代理指標は、上表の測定境界と区別します。
