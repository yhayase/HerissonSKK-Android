## 判定方法と実行記録

この表は [機能要件](requirements.md)、[互換性と受入仕様](compatibility.md)、[Android 検証計画](validation-plan.md) に対して、現行の試験が直接示す範囲と未実装の範囲を分けて記録します。「部分」は代表経路または限定フィクスチャの証拠であり、製品要件の受入完了ではありません。

最新の集計・履歴は [開発の継続記録](work-status.md) と各レビュー記録を正とします。試験数は実行されたアサーション群の数であり、独立要件数や網羅率を表しません。未実行・失敗・スキップを成功に含めません。

| 層 | 主な試験 | 証拠の範囲 |
| --- | --- | --- |
| コア JVM | 基本変換、ローマ字・文字種、Unicode編集、辞書形式・複合検索、登録状態 | Androidなしでの状態遷移と境界 |
| Android 単体 | EditorSession、キー変換、SQLite、辞書管理器、登録接続、ピッカー状態 | 接続の失敗・遅延、保存・公開・方針変更 |
| Python | 実行器の成功・失敗判定 | instrumentationのスキップ・途中終了を拒否 |
| 入力E2E | API26・30・35の PhysicalInputTest と CoreUnicodeTest、各12件 | 別アプリへのキー配送・候補表示・確定と保護欄 |
| Native SQLite | API26・35の SQLiteDictionaryAndroidTest、各8件 | 実容量不足、破損保存、再接続、文字コード往復、未コミット中の子プロセス終了 |
| SAF経路 | SafDictionaryE2eTest、API26・30・35で各1件成功 | 公開画面での退避・取込・IME反映・書出し・復元 |

専用結合ハーネスは候補ビューの固定 ID `input_status` を IME 起動確認に用います。専用エミュレーターでは `show_status` を既定値の有効に保つ必要があります。保持済み設定でこれを無効にすると、IME 自体の製品動作とは別に、ハーネスの準備待ちが失敗します。

## Unicode と配布物

内部編集は ICU4J 77.1／Unicode 16 の書記素境界を使います。ライセンスは `core/src/main/resources/META-INF/icu-LICENSE.txt` に置き、`app` と `test-editor` の APK に同梱します。JVM の公式コーパス 1 件と Android の `CoreUnicodeTest` 2 件は API 26／30／35 で成功しています。これはライブラリの読み込みと代表操作の証拠であり、全端末での容量・性能・Unicode 互換性の受入判定ではありません。

## 辞書形式層と保護入力の追加検証

純JVMの辞書形式層19件と複合検索8件、生成キー列の不変条件1件を追加し、コア全91件が成功しました。形式層はK13のUTF-8/EUC-JP、特殊文字・注釈・送り条件・順序の往復と不正入力拒否、複合検索はK04/K12の個人優先・有効状態・送り優先・重複・由来を検査します。Androidの保存層・管理器を実装して単体と実SQLite試験を通しました。ファイルUIの退避・置換・登録・書出し・復元E2EはAPI30で成功しました。

I10について、パスワード欄のASCII通過、候補中からパスワード欄への切替での漏出防止、学習禁止通常欄の変換を別アプリE2Eへ追加しました。パスワード欄にはcomposition spanと候補UIも残りません。API26/30/35で各12件（入力10件＋Unicode2件）が成功しました。保存抑止と実機での確認は別途必要です。

## 数値変換と抑止保存の追加検証

K16は数値変換部品12件と接続14件を追加しました。八形式、正規化した見出し、テンプレート間重複、処理量上限、元テンプレートの学習、登録の保存見出しと展開後確定文を検査します。登録の `#4` は保存要求時の辞書で展開し、要求後の再公開では確定文を変えません。要求前後で実際にManagerを再公開する試験もあります。実IMEの八形式と学習禁止の非変更はAPI26・30・35で成功しました。API30では試験側の外部書換えと選択通知の競合を除き、連続変換として再検証しました。

K11の保存層は個人候補と全システム由来の原子的な削除・抑止、世代競合、辞書ID再利用による旧確認の誤適用防止、復元、故障時ロールバックを検査しました。読み取り層では本文による表示重複排除を維持し、由来ごとの送り条件を正確に抑止します。通常辞書と組み込み辞書の抑止がManagerの再公開で反映されることも検査しました。入力中の削除確認と復元UIは未接続です。

Native SQLiteはAPI26・35各8件です。旧v1スキーマを直接作ったデータのv2移行、個人候補を復活させない抑止復元・再接続・同一辞書更新後の抑止も成功しました。現在の詳細な実行記録は[継続記録](work-status.md)を参照します。
