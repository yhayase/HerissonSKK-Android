# 要件と試験の対応表

更新日: 2026-09-16

## 目的と判定方法

この表は、[機能要件](requirements.md)、[互換性と受入仕様](compatibility.md)、[Android 検証計画](validation-plan.md)に対して、現行の試験が何を証明するかと、次に追加する試験を追跡するためのものです。現在の `:app:testDebugUnitTest` は API 26／35 を含む 53 件の試験呼出しが成功していますが、試験数やフェーズ 1 の接続確認が通ることだけでは、製品要件の受入完了を意味しません。

「既存」は対象要件の一部を直接検査する試験です。「部分」は前提または狭い経路だけを検査し、受入例全体の証拠ではありません。「未」は該当する自動試験がありません。実機・エミュレーターで未実行の試験は、コードが存在しても受入済みとは記録しません。

## 試験の層

| 層 | 目的 | 合格の証拠 | 他層の代替にならないもの |
| --- | --- | --- | --- |
| 設計単体試験 | 純粋 Kotlin のコアがキー列、辞書応答、内部状態、未確定表示、確定要求を正しく遷移すること | Android API・画面・実 DB を使わない JVM 試験。辞書と出力先は偽物に差し替える | 実際の `InputConnection`、キー配送、候補表示、アプリへの Enter 配送 |
| Android 接続単体試験 | セッション、入力欄、選択範囲、キー変換の接続境界を検査すること | `EditorSessionTest`、`HardwareKeyMapperTest`、`KeyPressLedgerTest`、Robolectric | 実 IME 選択、別プロセス入力欄、OS の物理キー配送 |
| 受入結合試験 | 実 APK の IME を別アプリの入力欄へ接続し、指定操作を観測すること | `test-editor` instrumentation を専用エミュレーターで実行。IME 有効化・選択を含む | 実機 Bluetooth、対象アプリ全体、性能 |
| 実機・アプリ互換性 | Xiaomi Pad 8 と選定アプリ・配列・接続方式での利用可能性を確認すること | 端末、OS、アプリ版、配列、接続方法、結果を記録する | エミュレーターだけによる全アプリ対応、性能目標の達成 |

フェーズ 2 の K01〜K08 は、まず設計単体試験を受入例ごとに作り、その後に Android 接続を通す代表シナリオを受入結合試験として追加します。K01〜K08 の全組合せを UI 試験で重複させる必要はありません。一方、I01〜I13 は接続層の要件なので、設計単体試験だけで完了とはしません。

## アーキテクチャ要件の試験可能性

| 要件 | 必要な設計上の試験境界 | 現状 | 最初の作業 |
| --- | --- | --- |
| N01、N10: コアと Android 接続を分離する | Android 型を参照しないコアに、入力操作、状態スナップショット、確定要求、候補・辞書照会要求を置く。偽辞書と偽出力先で JVM 試験する | `PilotEngine` は `app` モジュール内、`EditorSession` が直接 `InputConnection` を持つ。K01〜K08 用の純粋コアはない | コアの公開契約と辞書ポートを決め、K01 のキー列試験を最初に置く |
| N02: 要件ごとの回帰 | 要件 ID と標準・取消・失敗・境界列をテスト名または表で対応付ける | Phase 1 接続の一部は試験済みだが K01〜K08/I01〜I13 を完全には追跡していない | この表の「最初に追加する試験」を実装時に ID 付きの試験へ更新する |
| N03、N04: セッションと非同期の安全性 | 世代、入力欄、読み、キャンセルを照合し、失敗時は再配送・二重確定しないことを接続試験する | セッション切替と選択移動の保護は既存。実際の非同期辞書・保存はない | 遅延辞書と失敗する保存ポートを用意し、I05/I12 の結合試験を追加する |
| N05: 保護入力と学習抑止 | 入力種別判定と保存可否を別に渡し、診断出力を観測可能にする | パスワード判定とネットワーク権限なしは試験済み。学習禁止・登録抑止・ログ試験はない | 保存ポートが呼ばれないこととログに本文がないことを試験する |
| N08: Unicode 編集 | 内部カーソルと削除を UTF-16 添字だけで扱わず、ユーザー認識文字単位の境界を試験する | `PilotEngine` の読みに対する削除のみ。見出し語途中・登録内編集は未実装 | 絵文字・結合文字を含む内部バッファの移動、挿入、削除の単体試験を作る |
| F05、F13、S02: 内部編集と入力先編集を分離する | 見出し語・登録内編集はコア、未確定なしの入力先 Emacs 編集は Android 接続として別に試験する | 両機能は未実装。優先順位など U01/U02 は未決 | 未決事項を確定後、内部編集の JVM 試験から開始し、入力先編集は対象アプリ別に結合試験する |

## フェーズ 3 以降と非機能要件

K09〜K19、F05、F13、設定 S01〜S08、N04〜N12 は、現在の限定実装または未実装の範囲を含み、受入済みではありません。フェーズに応じて次を追加します。

- K09〜K13、K18〜K19: 再帰登録、学習、複数辞書、入出力、保存失敗・中断・再起動、学習禁止の設計単体試験と I07/I08/I10/I12 の結合試験。学習禁止通常欄でも変換を許す Phase 1 境界試験は成功したが、保存・登録の抑止と永続化は未実装である。
- K14〜K17 と S03〜S08: 補完の未受諾部分、数値展開、設定検証・復旧、候補ラベルと幅変更を、設定を差し替える単体試験と代表 UI 試験で検査。
- F05/F13/S02 と N08/N09: 見出し語・登録内の Unicode 編集、入力先 Emacs 編集、長い候補・注釈と幅変更を、責務ごとに分けて検査。
- N06/N07/N11/N12: 性能測定計画の回数・実機記録、API 26 と安定版 Android、ビルド・Lint、更新時データ保持は、結果と環境を記録して判定する。現時点では性能目標未確定のため達成判定をしない。

## 次の試験実装順

1. フェーズ 2 コアの契約を固定し、偽辞書を使う K01 の設計単体試験を追加する。
2. K02〜K08 を状態遷移ごとに追加し、候補本文・注釈・送り・abbrev・接頭辞／接尾辞を文字列の寄せ集めにしない契約を確立する。
3. 新コアを `EditorSession` に接続し、K03 の代表列と I01〜I04・I06・I09 を `test-editor` instrumentation で拡張する。
4. 非同期辞書と保存が入るフェーズ 3 で I05、I07、I08、I10〜I12 を追加する。I13 は対象配列・OS・端末を記録したエミュレーター／実機試験として実施する。

この順序では、設計単体試験が変換契約を固定し、結合試験が Android の配送・表示・入力欄境界を固定します。どちらか一方の成功だけで、もう一方の要求を満たしたとは扱いません。
