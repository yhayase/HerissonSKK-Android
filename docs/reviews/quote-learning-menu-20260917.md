# 引用・学習・候補表示のレビュー記録

日付: 2026-09-17。今回の変更と独立レビューの記録です。DDSKK 全体との互換性達成を示すものではありません。

## 問題と変更

C-q が半角カナ切替に割り当てられ、次のキーを入力先へそのまま渡せませんでした。標準割当を引用へ変更し、半角カナは設定で割り当てる省略可能操作にしました。設定文書は版 4 とし、旧標準 C-q を移行しつつ他の明示的な割当を保持します。

二本の確定直後は非同期保存・辞書再公開が終わるまで古い順位で検索していました。保存待ちの学習を既存候補の並べ替えへ反映し、次の「にほん」から二本を先頭にします。保存済み辞書を再公開した後はその順位へ引き継ぎます。保存待ちの項目は元の保存許可と入力コンテキストを持ち、失敗・禁止・復元で失効します。候補の由来と個人辞書世代は作り替えません。

一覧中の Space が一候補ずつ進んでいたため、ページ単位の移動へ変更しました。一覧行を状態説明より上へ置き、画面高とフォント行高でもページ件数を制限します。登録は見出し・本文・操作案内を先に表示します。

未確定の `▽`／`▼` は既定オフの任意設定として追加しました。本文読戻し未対応の入力先には付けず、確定・学習へ含めません。終了時は元の位置の表示全文を照合し、記号だけ除去して実際の選択範囲を補正します。照合失敗時はユーザー本文を削除せず、記号が残る場合を通知します。

標準ローマ字へ DDSKK の z 系記号と `fa/fi/fe/fo` を追加しました。有効な継続を文字コマンドより先に解決し、`zL` や z の後の空白をモード切替・送り開始・変換開始にしません。矢印は `zj → ↓`、`zk → ↑` です。大文字例外は正確な標準規則 `zL → ⇒` だけです。

## 独立レビューと修正

- C-q 自体の長押しが引用待機を消費し、反復・解放を入力先へ漏らす問題を検出しました。開始した物理キーを device・keyCode・downTime で識別して除外し、サービス試験で回帰を確認しました。
- 一覧の Space 仕様変更により登録内の候補ラベル試験が余分なページへ進むことを検出しました。入力列を新しいページ契約へ合わせました。
- 保存待ち順位の許可証、復元の epoch、候補由来、数値テンプレート、送り条件の照合を確認しました。復元直後に未実行の学習順位が消え、旧コンテキストの書き込みを拒否する試験を追加しました。復元後の再公開成功・失敗の両方が合格しています。
- 表示記号の除去は元の位置と全文の一致を条件とし、終了済み span へ本文を再挿入しないこと、外部の選択範囲を保持すること、読戻し不能時に推測で削除しないことを確認しました。
- `zL` の大文字例外、入力列末尾だけの空白、`canStart` による単独句読点の維持、コアの継続優先を独立に読み、対象試験も実行しました。追加の修正対象は見つかりませんでした。

- API 26 の表示 E2E がレイアウト前のアクセシビリティ情報を取得する問題に対し、全行が可視になるまで上限付きで待つようにしました。独立レビューでは画面座標が親によってクリップされる点も指摘し、行本来の高さとの比較を待機条件と最終検査の両方へ追加しました。独立レビューで指摘の解消を確認し、強化後の API 26／35 の文字倍率2と API 35 の横画面で各3件が成功しました。実画面では API 35 の通常・文字倍率 2・横画面と API 26 の文字倍率 2 で全候補行の表示を確認しています。

## 確認結果と限界

統合担当のローカルゲート `20260917T072603932299Z` は core 265 件、app 536 件、host 22 件が合格しました。lint、APK 構築、通知・権限検査も成功しています。API 35 の候補表示 E2E は 3 件が合格し、実際の画面画像も確認しています。独立レビューではローマ字、辞書管理器、表示記号、引用サービス・キー追跡の対象試験を再実行して合格しました。

修飾キー変更の E2E では、Shift 付きキーを小文字 `C-S-q` と指定していた試験と OS が生成する大文字 Q が一致しない点を確認しました。試験指定を `C-S-Q` に修正し、実 KeyEvent の単体回帰試験と API 26／35 の設定 E2E が成功しました。引用の押下・反復・解放、表示記号の確定時除去、標準ローマ字を公開 UI から確認しています。

DDSKK 実行との自動差分比較、および全入力先アプリでの本文読戻し対応は検証していません。保存待ち順位の即時反映は手動 executor の管理器試験、永続化と学習抑止はサービス試験で確認しました。API 26／35 の SAF E2E でも、二本の確定直後に同じ入力欄で再変換すると二本が先頭になることと、保存・再読込を確認しました。任意の数値 `#4` 展開組合せを網羅したものではありません。表示記号を付けた後に入力先の本文が外部変更された場合や読戻し不能になった場合は、安全に除去できず記号が残る制約があります。
