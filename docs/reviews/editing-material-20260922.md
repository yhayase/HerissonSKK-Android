# 編集キーと設定テーマの修正（2026-09-22）

## 目的と変更

物理キーボードのインライン変換では Backspace / C-h で候補を確定し、末尾の一書記素を削除します。学習には削除前の候補を渡します。空の見出し語の `▽` は C-h でも取り消します。候補メニューの戻り操作と、画面キーボードの Backspace による取消は維持します。

C-m は物理 Enter と同じ SKK 処理を通り、入力先へ渡す場合は修飾なしの Enter を送ります。入力先の検索・送信・改行の定義に従います。既存の「Enter では確定のみ」の設定と登録中の扱いも物理 Enter に合わせます。

入力先で連続した C-k は、削除した文字をクリップボードへ順番に連結します。文書末尾では内容を保持し、`End of buffer` を表示します。他の操作・入力先切替・外部の選択変更・クリップボード置換では連続を終了し、自分の削除に伴う選択通知は連続を保ちます。

設定画面は Material 3 のテーマと実際の MaterialSwitch、MaterialToolbar、MaterialButton、Material のダイアログを使います。AndroidX Preference の項目・階層・保存処理を維持し、ウィジェットを独自描画しません。対応端末ではシステムの動的配色を使います。Emacs 編集の二つの設定には、入力先で有効な間は IME 内でも有効であることを明記します。

## 根拠

DDSKK のインストール済みソース `/usr/share/ddskk/skk.el:1624` と `/usr/share/ddskk/skk-vars.el:1522` で、`skk-delete-implies-kakutei` の既定値が t であり、候補一覧の Backspace は前候補のままであることを確認しました。ユーザーが指定した挙動を実装します。

Material の[配色の説明](https://github.com/material-components/material-components-android/blob/master/docs/theming/Color.md)に従い、M3 テーマでビュー作成前に動的配色を適用します。`SwitchPreferenceCompat` が要求する `switchWidget` ID と `SwitchCompat` 型に、派生クラスの `MaterialSwitch` を結び付けます。

- 入力接続の独立レビュー: Astra / low。テーマの担当が指摘を再検証しました。
- テーマの独立レビュー: SKK 担当の Sol / medium。別の Astra / low が指摘を再検証しました。

## 指摘と判定

| 指摘 | 独立した判定 | 対応 |
| --- | --- | --- |
| クリップボード所有確認中にセッションが失効すると、古い C-k がクリップボードを書き換え得る | 妥当。所有確認コールバック後、書込み前の確認が欠けていました | コールバック後に要求の有効性を確認し、連続の世代も再確認します。終了・期限切れ・連続中断を注入する回帰試験を追加しました |
| MaterialToolbar が framework の属性名を使い、戻るアイコンを失う | 妥当。AppCompat の属性と名前空間が異なります | app 名前空間へ修正し、アイコンと説明を検査します |
| ダークテーマでもシステムバーの暗色アイコンを強制する | 妥当 | テーマに合わせた前景色へ変更します |
| 個別の設定画面のダイアログが従来の platform builder のまま | 妥当。Material のテーマ適用に漏れがあります | 設定画面内の builder を統一します |

## 自動試験で見つかった追加問題

API 26 の E2E で、貼り付け後の C-b で入力先のカーソルが動いた直後、IME への選択通知より先に C-k が届くと、古い座標との不一致で C-k を拒否する問題を再現しました。本文を記録しない一時診断で順序を確認し、別の担当も試験の期待値と再現を検証しました。ネイティブ操作後の C-k は通知を最大 500 ms 待ち、その後、新しい状態から通常の厳密な照合を行います。通知が来ない端位置でも無期限には待ちません。再レビューで待機フラグが残り毎回待つ問題を検出し、別担当の検証後、タイムアウト時にも待機状態を消費する修正と回帰試験を加えました。一時診断は削除しました。

ライト・ダークの実画像では、API 26 のシステムバー背景がページ背景と異なることを確認しました。同じコントラスト問題の再修正になったため、担当を Sol / medium から Astra / low に上げ、実際のバー背景とアイコン色を検査する方針に変更しました。

Material の標準リストでは、API 35 の狭幅画面で追加元の「ファイル」がスクロール下部に隠れました。実際の階層で正常なスクロール一覧であることを確認し、E2E を一覧内のスクロールに対応させました。また、追加前の失敗で試験辞書が存在しない場合も個人辞書の復元を続けられるよう、試験の後処理を修正しました。この判定は別の担当がソース名の一意性・表示名・削除操作を照合して確認しました。

## 検証上の制約

Android の通知では、自分の操作に対して待機中の選択通知と、全く同じ値の外部通知を区別できない場合があります。クリップボード更新と入力先への削除もアプリをまたぐ原子操作にはできません。拒否・不明な削除を再送せず、既存の安全側の制約を維持します。

検索・送信の Enter 同等性は、外部へ送信しない専用入力欄で試験します。実際の会話への送信は行いません。

複数のネイティブ移動で途中の選択通知だけが届き、本文取得の座標とまだ一致しない場合、C-k は安全側に拒否します。後続通知を契機に既に拒否した削除を再送しません。この残る入力先依存の通知制約を、複数移動の中間通知を注入する試験で確認します。
