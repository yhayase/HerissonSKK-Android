# 表示・更新保持・配布物のレビュー

## 対象と担当

N09 の候補表示、S01・S06・S08 の設定操作、N12 の更新保持、バックアップの I/O 障害、配布物を対象にしました。実装とレビューは別担当へ分け、通常の実装・検証は Terra / medium、複数の状態を扱う実装・レビューは Sol / medium、プライバシーと IPC 境界は Astra / low に割り当てました。ビルド、端末操作、Git 操作はメイン担当へ集約しました。

## 採用した指摘

- 候補本文・注釈・登録本文を無制限に TextView へ渡すと表示領域とレイアウト処理が膨らむため、表示量と書記素探索を有界にしました。全文は IME 内のページで確認し、画面高の 40% を上限にします。
- 自動ページ数の算出に表示領域の内側幅を使います。狭い幅で横並びのボタンがはみ出す問題は縦配置へ変更しました。
- カーソル前の巨大な結合文字、削除確認の送り、同じ候補識別子で短い全文へ置き換わった場合を独立レビューで追加しました。古いページ位置の再利用を止め、回帰試験を追加しました。
- 設定画面から Android の物理キーボード設定へ移動できます。設定 Activity の起動拒否・未搭載時も代替操作または説明を表示します。
- 辞書ごとの処理対象と失敗を表示します。保存後に snapshot の公開が失敗した `Ready(STALE)` を「利用可能」としないよう修正しました。
- 更新試験は旧 APK の導入を試みた時点から復旧責任を持ち、現行 APK の再導入が成功するまで対象 IME を再有効化しません。端末情報を変更前に取得し、切断時も復旧記録を残せるようにしました。
- 表示試験の親実行器から子を強制終了すると子の設定復元を中断するため、期限は子の各 ADB 操作に置きます。画面サイズと文字倍率は独立して復元・照合します。

## 指摘の再検証

辞書操作中の画面再生成で旧内容を誤って「利用可能」と表示するという指摘は、直列実行器の順序から撤回しました。新画面は古い行を保持せず、一覧取得は進行中の書き込みの後に実行されます。回転で操作固有の一時通知が失われる制約はありますが、永続化と利用可能な内容を取り違える根拠にはしません。

設定復元前の IME 停止に失敗してもファイルを書き戻す提案は採用しません。動作中の AtomicFile 書き込みと競合するため、停止確認できなければ失敗とし、退避と復旧情報を保持します。

## 実行中に判明した試験環境の差

- API 30 の SettingsProvider は文字倍率 2.0 を拒否するため、当該エミュレーターでは明示的に 1.3 を指定します。API 26・35 は 2.0 を使います。
- API 26 は構成変更中に未設定の文字倍率を 1.0 として再登録する場合があります。削除を再実行し、元の未設定状態が続くことまで検査します。
- 別アプリの設定画面へのキー注入には UiAutomation を使います。入力確認アプリ内だけを対象とする Instrumentation.sendKeySync と区別します。
- androidTest APK の別プロセスには target APK の Kotlin 実行時が入りません。障害プロバイダーは Android/JDK API のみを使う Java へ変更しました。異常終了で残った専用 UUID DB を明示的に清掃し、日常用 DB は変更していません。

## プライバシー・配布境界

独立したソースレビューでは新たな具体的な脆弱性は確認されませんでした。IME の BIND_INPUT_METHOD、非公開の辞書・復元画面、保護入力と保存許可の再検査、入力ログとネットワーク処理の不在、staging と復元権限を対象にしました。試験専用プロバイダーは target アプリの UID、固定 URI と UUID、サイズ上限を検査し、実ユーザーのファイルを扱いません。

配布物検査では通知の同梱、ZIP 整合性、INTERNET 権限の不在、release／benchmark からの crash 試験サービス除外、アプリ APK からの障害プロバイダー除外を確認します。実行結果と未検証範囲は [継続記録](../work-status.md) と [配布手順](../distribution.md) を参照します。ソースレビューだけで実機・OEM・任意のプロバイダーへの保証とはしません。
