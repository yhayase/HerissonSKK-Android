# 要件レビューの判定と反映（2026-09-16）

## 基準と手順

DDSKK 17.2 リリースのタグ `ddskk-17.2_Mena` を、DDSKK のローカルチェックアウトで確認しました。参照先は `e8bf68b27021c29781dbfa6a8ef7b770565bdb5b` で、`skk-version.el` の版も 17.2 です。現行の要件と互換性仕様を更新しました。過去の AndroidSKK 評価に含まれる旧参照は、当時の調査根拠として維持します。

ユーザー指定どおり、独立した `gpt-6-astra`／`high` のレビュアが [一次レビュー](requirements-20260916-review.md) を実施し、別の `gpt-6-astra`／`high` が [メタレビュー](requirements-20260916-meta-review.md) を行いました。主担当はメタレビューの判定と現行実装を照合し、以下の範囲に絞って文書を修正しました。

## 指摘別の反映

| 一次指摘 | 判定・修正 |
| --- | --- |
| 1: Q／q の受入不足 | 一部採用です。内部 Q は既に別途定義する方針でした。空の見出し語開始と見出し語の q によるカタカナ確定の受入例を追加し、残る状態別操作を U01 のフェーズ2実装前の事項に結び付けました。既存バッファ取り込みの除外は維持します |
| 2: Enter の参照説明・残余列 | 採用です。通常かなの未消化列にも改行抑止を適用するのは Android 独自仕様と明記しました。標準の `n`／`k`／`ky` の Enter・C-j の出力とモードを明確化しました。DDSKK の挙動へ合わせて送信を許す変更はしません |
| 3: 送り優先の参照設定 | 採用です。比較用 DDSKK の一致優先を t、不一致候補の除外を nil とし、個人辞書の送りブロックと候補順の受入例を追加しました。複数辞書の統合順位は既存 U06 で定義します |
| 4: 特殊欄の例外 | 一部採用です。候補への露出禁止は既存要件でした。現行 `EditorSession.handle` の保護入力迂回とサービスの password／TYPE_NULL 判定を確認し、C-j 等より優先する製品上の直接入力制限として明文化しました。学習禁止要求だけの通常欄とは分離します。実装の漏えい発見とは扱いません |
| 5: 半角カナの期限 | 採用です。標準キーの決定をフェーズ2前、キー変更設定をフェーズ4に分けました。削除確認・補完巡回も該当実装前へ統一しました |
| 6: 進捗・環境情報 | 一部採用です。限定実装・初回確認済みという状態へ更新しました。API 36・ビルド番号も既に取得済みでした。未検証の互換機能やアプリを合格扱いにはしていません |

## 実現性の結論と残る範囲

IME 内部の読み・候補・登録文字の編集は実現可能な対象として維持します。入力先の確定済み文字の編集・再変換は、文字列・対象範囲・編集操作を確認できる場合に限定します。Emacs と同じ無制限のバッファ操作や、全アプリでの同一動作は要求しません。

設定初期値・行や単語の境界・カスタム規則・状態別操作など、既に未決とした製品判断を今回のレビューだけで一括確定していません。対応する U 項目の期限までに受入仕様を追加します。

修正後のメタレビューで、送り完成後の余分な SPC と、終端出力例の開始モードの曖昧さを追加で指摘され、例を修正しました。

今回の変更は文書のみです。一次レビュアの DDSKK 限定プローブはレビュー報告に記録しています。Android の実装変更・実機再試験・全 DDSKK テスト実行は行っていません。
