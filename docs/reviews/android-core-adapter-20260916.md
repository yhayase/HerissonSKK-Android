# コア接続と遅延通知のレビュー

実施日: 2026-09-16

純Kotlinコアへの接続変更について、実装担当とは別の担当が入力先所有、保護入力、選択通知、確定・編集拒否、表示、権限とログ出力を確認しました。今回の変更に起因する情報漏えいは確認しませんでした。実機・全アプリでの安全性を保証する判定ではありません。

## AND01: 遅延した選択通知によるカーソル位置の巻き戻り

以前の未確定文字に対する選択通知を受けると、既に進んだ入力位置を古い値に置き換える問題を指摘しました。`Nihon SPC Enter` で `日本` を確定し、続けて `Nihon` を入力した後、先の未確定範囲 `[0,1]` に対する通知を届けて Left を押す列が再現条件です。

修正では、通知に対応する待機履歴を消費しても、それより新しい操作がある場合は予測済みの最新座標を保持します。最初の入力位置が不明な場合に通知から範囲を取得する処理は維持します。

主担当がガードだけを一時的に外し、新規回帰試験を実行しました。API26/35の両方で「期待位置4、実際2」と失敗しました。必ず元へ戻す処理で修正を復元した後、Android単体試験67件が成功しました。失敗・エラー・スキップは0件です。

## 確認範囲と制限

- パスワードと `TYPE_NULL` は通常コアを迂回します。学習禁止通常欄の変換は継続しますが、保存機能はまだ未実装です。
- 接続はセッションに固定され、終了した旧セッションから新しい入力欄へ送信しません。編集拒否では同じキーを再送しません。
- ネットワーク権限と入力本文の診断ログ出力はありません。
- 未知の初期選択位置では内部カーソルの絶対位置を推測しません。
- 既存の `finishComposingText()` の失敗を表示へ反映しない制限、実エディターの非同期通知の全組合せ、実機レイアウトは未確認です。

## 試験器のレビュー

モード表示を「あ」に変更した結果、従来の「かな」を探す準備待ちが失敗しました。表示名に依存せず、IMEのパッケージと `input_status` リソースIDで候補・状態表示を確認する方式に変更し、API26/30/35の各9件が成功しました。

実行器は履歴を端末別・マイクロ秒付き時刻のディレクトリへ残し、APKのSHA-256、API、ソースコミットと変更の有無を記録します。シリアルは `emulator-` と数字だけへ制限し、既存の履歴へ上書きしません。失敗・スキップ・実行件数の不整合は成功にしません。

状態表示を無効にした設定は `install -r` で残るため、準備待ちが失敗します。専用エミュレーターでは初期値の「入力モード・候補を表示する」を有効にして実行します。テスト準備の失敗を製品の入力不具合と混同しません。
