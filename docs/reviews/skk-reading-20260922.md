# 読み確定・送り・補完・登録中候補の修正（2026-09-22）

## 対応内容

| 指摘 | 原因と修正 |
| --- | --- |
| 見出し語の l / L が英字入力になる | 見出し語状態で英数切替を配送していませんでした。かなの読みを確定し、未完成のローマ字は破棄、n など終端規則で完成できるものは確定して、l は半角、L は全角英数へ移ります |
| xtu が入力できない | 標準規則に別名がありませんでした。xtu → っ を追加し、xtsu と独自テーブルを維持します |
| 物理入力の再帰登録中に変換候補が見えない | 物理インライン候補は一覧に含めない設計ですが、登録本文側にも表示していませんでした。登録中のポップアップに現在の変換候補本文を表示します。本文は省略しません。登録外のインライン変換は従来どおり一覧を出しません |
| TasSi が たsし になる | 大文字による送り開始の前に、保留中の s を文字として終端処理していました。sS の重子音規則から得た っ を語幹へ入れてから送り境界を置き、し を送りとして検索します |
| 補完の . / , がない | Tab で開始した補完巡回中に限り、. を次、, を前の操作として配送します。先頭・末尾では止まり、取消・確定後は通常の句読点入力へ戻ります |

既存のキー設定で見出し語中の l に補完などを明示的に割り当てた場合は、それを維持します。英数切替キーを変更している場合も新しいキーを使います。ローマ字の途中の zl / zL は矢印入力として維持します。補完中の句読点にも明示的な操作割当があれば、その割当を優先します。

`/usr/share/ddskk/skk-vars.el` の標準規則と実行時の規則表で xtu / xtsu の両方を確認しました。補完巡回の . / , と端で停止する動作は [DDSKK の補完説明](https://github.com/skk-dev/ddskk/blob/master/docs/06_apps.rst) でも確認しています。

## 分担と独立レビュー

入力状態の変更は Sol / medium、登録中の表示と xtu は別々の Terra / medium、キー配送・統合試験はメインで担当しました。別の Sol / medium が実装をレビューしています。

レビューでは、n+l がローマ字の残余規則に先取りされ、物理キー配送で新しいモード切替へ到達しない問題を指摘しました。メインでも同じ原因を確認し、別の Terra / medium が規則と配送順序を独立検証しました。読みの英数切替に限り残余規則より操作を優先し、zl / zL のようにキーを消費する規則は維持するよう修正しました。実キー配送からエンジンへ渡す試験を追加しています。
