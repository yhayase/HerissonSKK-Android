# SQLite 辞書永続化レビュー

履歴資料です。対象時点の判定を保持しています。現在の仕様・残件との区別は [レビュー履歴の案内](README.md) を参照します。

実施日: 2026-09-16

対象は `SQLiteDictionaryRepository` とその Robolectric 試験です。辞書 UI、IME への非同期接続、学習、登録、削除は対象外です。入力は `SkkDictionaryCodec` が全件解析・検証済みの `SkkDictionaryDocument` とします。

## 判定

原子的な置換・マージ、世代競合、読み取りスナップショット、破損時の原本保持について、対象範囲の試験は成功しました。独立レビューで見つかった「プログラム生成文書の空注釈が既存注釈を消す」問題は、空文字の正規化と既存注釈の保持へ修正し、固定値の回帰試験を追加しました。修正後の独立再レビューで、対象範囲に残る具体的な正しさの問題は報告されませんでした。

## 採用した境界

公開 API はすべてブロッキング I/O で、内部スレッドを生成しません。呼出側が executor で実行し、起動時または書込み成功後に `loadSnapshot()` で全有効辞書を一度読み込み、`CompositeSkkDictionary` として公開する契約です。特定キーだけを調べる `lookup(key)` も残し、`entry_key` を先頭にした索引で対象行だけを検索します。

個人辞書は固定 ID `personal` とし、システム辞書とは種別、ID、世代、有効状態、優先順を分離しました。候補は辞書 ID、見出し語、候補順、本文、注釈、送り条件を別の列に保存します。検索スナップショットは個人辞書、システム辞書、各世代を型付きで返し、システム辞書のリストを防御的に複製して変更不能にしています。

## 原子性と競合

個人辞書の置換・マージとシステム辞書の追加・更新は、候補行の変更、世代更新、公開を一つの SQLite トランザクションに含めます。行変更後と commit 直前に failpoint を設け、どちらで例外が発生しても旧候補、旧世代、辞書一覧を rollback します。世代指定のある更新はトランザクション内で現在値を比較し、古い世代を拒否します。

`lookup(key)`、`loadSnapshot()`、個人辞書の書出し、辞書一覧取得も明示的な read transaction 内で Cursor を最後まで読みます。別の repository instance が CursorWindow の補充中に公開しても、由来世代、候補行、優先順を異なる時点から混在させません。同じ instance の close と各操作は同期しています。

個人辞書マージは、取り込み候補を先頭へ置き、その後ろに既存だけの候補を残します。同一性は本文と送り条件の組です。取り込み注釈を優先し、取り込み側が null または空文字の場合だけ既存注釈を保持します。codec を経由しないプログラム生成文書の空注釈も保存時に null へ正規化します。システム辞書更新は同じ ID の行だけを変更し、個人辞書と他のシステム辞書へ触れません。

## 破損時の保存

Android の既定 `DefaultDatabaseErrorHandler` は破損を検出すると DB ファイルを削除します。N04 のデータ保存要件に合わないため、repository は独自 `DatabaseErrorHandler` を渡し、自動削除や再作成を行わず、辞書本文やファイルパスを含まない一般化した例外を返します。根拠は AOSP の [`DefaultDatabaseErrorHandler`](https://android.googlesource.com/platform/frameworks/base/+/6dd38cc5343106251c8d66ab11bb93550082e594/core/java/android/database/DefaultDatabaseErrorHandler.java) です。

候補保存には例外を投げる `insertOrThrow()` を使い、失敗を無視しません。repository は辞書本文をログへ出さず、failpoint の例外にも候補本文を追加しません。破損ファイルの回復、バックアップ、利用者への表示は後続の管理 UI で扱います。

## 試験

Robolectric 試験は次を固定します。

- close と再 open 後の候補、世代、有効状態、優先順
- 個人辞書のマージ順、注釈、送り条件と UTF-8 書出しの codec 往復
- システム辞書更新が個人辞書と他辞書を変更しないこと
- キー単位と全件の読み取りスナップショットが世代、順、由来を固定し、旧スナップショットを後の更新から隔離すること
- 行変更後と公開直前の例外について、システム更新、新規追加、個人マージの rollback と再 open 後の旧状態
- 古い期待世代の拒否
- native SQLite の実ファイルを破損させた際に、自動削除せず同じバイト列を残し、本文を含まない一般化した例外を返すこと。実ファイルを利用できない環境では、この一件を前提不成立として区別します

集中実行後の `TEST-jp.hayase.skk.dictionary.SQLiteDictionaryRepositoryTest.xml` で12件成功、失敗0件、エラー0件、スキップ0件を確認しました。native SQLite の破損試験もスキップされず成功しています。

例外による rollback 試験は SQLite のトランザクション境界を確認しますが、プロセス強制終了や端末電源断への耐性を直接実証するものではありません。破損試験は Robolectric の native SQLite 上であり、Android 実機・エミュレーターの instrumentation では未確認です。大規模辞書の容量、時間、CursorWindow の実端末負荷も別途測定が必要です。

## Android ネイティブ試験の追記

API26・35 の各エミュレーターで、実 SQLite を使う5件がすべて成功しました。EUC-JP の厳密復号、UTF-8往復、再接続・順位・無効化・検索、実際の容量不足、注入した公開直前失敗、破損ファイル保存を検査します。容量不足と注入故障は別のケースです。

初回の容量制約は接続を開き直すと失われ、試験準備のアサーションで失敗しました。試験用の内部コンストラクターだけに接続設定を注入し、リポジトリ自身の接続で制約を設定・確認する方式へ修正しました。通常のコンストラクターは無設定です。

その後、実際の SQLITE_FULL による自動ロールバック後に `endTransaction()` が失敗し、元の容量不足例外を隠す不具合が判明しました。終了処理は必ず実行し、先行例外があれば終了失敗を suppressed に保持します。先行例外がないコミット失敗はそのまま送出し、成功として返しません。[SQLite のトランザクション仕様](https://www.sqlite.org/lang_transaction.html)の自動ロールバック規定に対応します。修正後は元の `SQLiteFullException`、旧内容・世代、再接続後の旧内容を確認しました。
