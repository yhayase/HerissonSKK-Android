# 入力UI再設計の独立レビュー

対象は[合意した入力UI](../input-ui-redesign.md)の実装です。先行する名前空間変更・編集キー修正を含む作業ツリーへ追加しています。実装担当の報告だけで合格とせず、別担当がコードと試験をレビューし、指摘もさらに別担当が再検証しています。

## 指摘と判断

| 指摘 | 独立検証と対応 |
| --- | --- |
| 一回Shiftを複数の指が同時に取得すると複数文字が大文字になる | 別担当が押下・指離しの順で再現。押下時には同時押しShiftだけを捕捉し、一回Shiftは最初に実際に送った文字で消費します。取消と押下Shiftの複数文字も回帰試験に含めます |
| 数値予測の学習が元テンプレートではなく展開済み文字列を保存する | 通常変換との比較で妥当と確認。表示・確定文字列と学習元テンプレートを分離し、両方を試験します |
| タッチ右下キーで未完ローマ字を確定するとEnterも転送される | 別担当がセッションの分岐を確認。タッチの確定と物理Enter転送を分離し、SEND欄の`n`を最初は`ん`だけ確定、次の押下で送信操作とします |
| モード選択が予測先頭を確定する | 合意文書との不一致を別担当が確認。見出し語・予測中は生の読み、通常変換中は表示ページ先頭を確定してから切り替えます |
| カタカナ表示の読みをそのまま辞書検索する | 通常変換の辞書契約との不一致を確認。検索には内部のひらがな読み、候補なしのフォールバックには表示文字種を使います |
| 使用履歴が順位に反映されない | 注入したコールバックとインターフェースの同名関数による衝突を別担当が確認。履歴の連番が順位付けに届くよう修正し、読みをまたぐ順序を検証します |
| 候補走査だけでは履歴・抑止の読込量を制限できない | 2名が独立に指摘。補助検索と文字量にも上限を設け、超過を候補なしや順位確定済みの部分結果にしません |
| 遅延実行する候補タップで表示時の同一性を失う | セッション待機列を別担当が追跡して妥当と確認。実行時にも期待する候補・予測表示の同一性を照合します |
| 予測の非同期検索が読みの即時表示を待たせる | 辞書処理のロールバックを別担当が確認。予測だけを独立した非同期処理にし、入力・辞書・セッションの版が合う結果だけを反映します |
| 古い接続のカーソル通知で新しいポップアップが移動する | 接続・監視世代、期待する選択位置・未確定範囲との照合を追加します。Android通知に接続識別子がない制約は残ります |
| 同じ選択位置の通知で待機中の外部編集を無効化しなくなった | 全体試験の失敗を別担当が再現手順とコードで検証。外部編集の版の失効と回転用スナップショットの失効を分離しました。既存の取消試験を緩めず修正しています |
| サービス破棄で物理ポップアップの終了処理が呼ばれない | 別担当が終了経路とタイマーを確認。破棄時に子窓を閉じ、予約したモード消去処理を解除します |
| タッチE2Eが学習前の候補順と予測の即時完了を仮定する | 別担当が保存済み学習と非同期検索の条件を確認。実際に表示した候補との一致、検索完了後の読み候補の表示を検査します |
| 可変幅の最後の候補ページでSpaceが登録へ進まない | 3候補・表示件数1→2で物理インライン用の送り処理に入ることを別担当が確認。画面側の末尾だけ既存の明示登録操作を使い、再帰登録・取消・右三角の無効状態も試験しました |
| 長押し注釈が同じ候補の再描画で閉じる | 実IME試験の失敗を別担当が描画世代の比較まで追跡しました。注釈表示は同じ候補・注釈参照とセッション等が続く場合に保持し、古いタップの確定防止には描画世代の照合を維持します。物理・画面の両表示で保持と失効を試験しました |
| 辞書検索の待機中に押した画面の文字が物理候補選択として処理される | 実IMEで「候補確定後の文字」が消える失敗から、別担当が待機列への格納時点を追跡しました。表示状態を確認する前に画面操作そのものを待機させ、検索・外部編集の完了後に先行入力を反映した状態で意味を判定します。候補タップの同一性照合は維持し、文字・Space・確定・モード操作の順序を試験しました |
| API 35の回転で再帰登録を失う | 同じEditTextを保持する試験で実測。構成変更後の一時的なcomposing span消失と、新しい接続による再開始を確認しました。下記の境界を独立レビューしました。API 35で同じ欄の往復回転と別欄への非持越しの2件が成功しています |
| 無害な選択通知で候補タイルを交換し押下を取り消す | 別担当が同じ入力状態でも描画世代が進むことを確認。セッション・入力状態・表示方式・表示候補が同じなら世代とタイルを保持します。押下中の通知後に指を離す試験と、ページ変更後の古いタップを拒否する試験を追加しました |

## 単体試験の終了処理

全体試験で補完サービス試験の終了が停止しました。スレッドとアニメーションの対象を調べ、未接続の試験用入力ビューで作り直したボタンの状態アニメーションが残ることを確認しました。試験の入力ビューをActivityへ接続し、終了前に外すことで、実際のdetach経路を通すよう修正しました。全体のアニメーション無効化や試験の省略は行っていません。独立レビューで対象と終了経路を確認しています。

## 同じ入力欄の接続再開始

[AndroidのonStartInput契約](https://developer.android.com/reference/android/inputmethodservice/InputMethodService#onStartInput(android.view.inputmethod.EditorInfo,%20boolean))は`restarting=true`を同じ入力欄の再開始と定義しています。ただし、アプリによる本文変更も含むため、この値だけでは保存済み状態を復元しません。

API 35では構成変更通知より先に旧接続が無効になることを実測しました。そのため、旧接続を構成変更時に読み直さず、入力が成功した時点の検証済みスナップショットを保持します。通常の自前更新への応答では保持し、外部変更では失効させます。

短時間の構成変更世代、入力先のbinding、入力・プライバシー属性のコピー、未確定文字の範囲・本文・選択位置を照合します。新しい接続で一致を確認できた場合だけ`setComposingRegion`で範囲を再設定し、本文を再挿入しません。別欄、本文変更、選択移動、取得不能、API拒否、終了・切断などでは移管しません。接続の差し替え時には古い編集処理を無効化します。

検証に使う入力先の取得範囲は16,384文字以内です。入力先が完全なスナップショットを返さない場合や、この上限を超える場合は推測で移管しません。

これはAndroidの同じ入力欄という通知を信頼する境界です。アプリとフレームワークが完全に同一の属性・本文を持つ別欄を誤って同一欄として通知した場合まで、IME側だけで識別できるとは主張しません。
