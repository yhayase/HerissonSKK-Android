# 基本設定の保存結果と学習抑止

履歴資料です。対象時点の判定を保持しています。現在の仕様・残件との区別は [レビュー履歴の案内](README.md) を参照します。

## 問題と変更

基本設定の三つのスイッチは `SharedPreferences.apply()` を使い、ディスク保存の失敗を表示できませんでした。S08 に従い、直列ワーカー上の `commit()` と保存中・成功・失敗・再試行の表示へ変更しました。状態と項目別の失敗はアプリプロセスで保持し、画面回転や別項目の保存成功で失いません。

学習をオフにすると、ディスク保存を待たず待機中の保存許可を失効します。オンにする場合は保存成功後だけ許可します。保存前に辞書管理器のポリシーを初期化し、SharedPreferences の一時的なメモリー値から誤って許可しないようにします。要求世代の古いオン完了は後のオフ要求を取り消しません。

保存失敗時は変更した項目だけを元の値・未設定状態へ戻します。学習は自動で再許可せず、表示もオフのまま保存失敗を知らせます。プロセス終了後は最後に保存できた値へ戻る可能性を明示します。ディスクへ保存できなかった選択を再起動後も保証するとは扱いません。

## 独立レビューと検証

Sol / medium が実装し、Astra / low がプライバシー境界をレビューしました。ポリシーの初期化順、許可の再開、要求世代、項目別の復元、回転、再試行について新たな具体的な脆弱性は確認されませんでした。未設定キーの試験で誤った既定値を期待していた指摘を修正し、元から値がある場合と未設定の場合を分けました。

API 26・35 の Robolectric で六つのシナリオを実行します。保存失敗、成功前の許可禁止、古い完了、未設定キー、回転と再試行、学習オフの失敗後に別設定だけが保存成功するケースを含みます。失敗は永続化アダプターで注入するため、実端末のストレージ故障そのものの証明ではありません。実 IME の設定・学習禁止・補完切替は別のエミュレーター E2E で検証します。
