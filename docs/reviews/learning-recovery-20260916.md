# 候補学習・SAF・中断復旧のレビュー

## 対象と判断

通常候補の確定後学習、SAF入出力の実IME試験、未コミット中のプロセス終了を対象にしました。実装担当と別担当が候補学習・SAFの復元境界を確認しました。主担当は学習E2Eの追加差分とdebugサービスのプロセス・ファイル境界を確認しました。

## 学習

学習要求は候補の選択時ではなく、入力先への確定が成功した後に発行します。元のセッションの学習可否を保存要求へ渡し、待機中の無効化も保存管理器で検査します。学習失敗は確定済み文字を取り消しません。遅い完了・重複完了は別の入力欄へ作用しません。送り条件は実際の検索の送りを優先して保存し、他の送り条件の候補を保持します。

独立レビューでは具体的な実装不具合はなく、保護欄と接続終了後の通知について専用試験の追加を求めました。両試験を追加し、API26/35のRobolectric実行が成功しました。

SAF E2EはAPI30で、注釈付き二番目候補の確定、個人辞書の先頭化、注釈保持、新セッションでの再変換を検査しました。通常の固定辞書E2Eは学習禁止欄で実行し、順位変更による試験間干渉を防ぎます。

## SAF復元

最初の変更より前にバックアップのバイトを取得し、UUID名の復旧情報を書きます。終了時に必ず復元し、再書出しとのバイト比較まで成功条件に含めます。復元失敗は試験失敗とし、バックアップと復旧情報を残します。独立レビューは完全一致のファイル選択、例外時の復元、結果解析、以前のIMEへの復帰を確認しました。API30の成功は他APIのSAF互換性までは保証しません。

## プロセス終了

debug専用・exported=falseのサービスでUUID名の試験DBを更新し、未コミットの行変更後で停止します。同一UID・正確なプロセス名・自分自身でないPIDを確認して子プロセスだけを終了します。再接続後の旧世代・旧候補保持をAPI26/35で検査しました。通常DBや任意SQL・任意パスを外部から指定する経路はありません。benchmark APKにサービスがないことを確認しました。release APKの検査と電源断試験は未実施です。

実行履歴・件数は[継続記録](../work-status.md)を参照します。全要件の受入完了を意味しません。
