# Emacs キーバインドの三択設定（2026-09-22）

## 変更の目的

二つのスイッチが互いに影響し、表示から編集範囲を判断できない状態を解消します。全体設定を「Emacs キーバインド」という一つの標準 ListPreference にまとめ、「無効」「IME 内のみ」「IME とアプリ」から選びます。現在値を一覧に表示し、アプリだけを有効にする組合せは提供しません。

アプリ別設定は「全体設定に従う」と同じ三択です。個別指定は IME 内を含む適用範囲全体を置き換えます。アプリ名・ID の検索、実効値の表示、保存失敗時の復旧、次の入力欄からの適用は維持します。SKK 本来の確定・取消などは、編集設定が無効でも維持します。

## 互換性

全体設定の既存 JSON はそのまま読み込み、旧「入力先」がオンなら「IME とアプリ」、旧「IME 内だけ」だけがオンなら「IME 内のみ」、両方オフなら「無効」と解釈します。保存時は三択に対応する値へ正規化します。内部の二つのフラグは既存のキー配送・保存形式との互換用です。

旧アプリ別有効指定は「IME とアプリ」へ移行します。旧無効指定は、旧全体設定の IME 内編集が有効なら「IME 内のみ」、そうでなければ「無効」へ移行します。全体設定を編集する画面では、必要な移行が保存できるまで編集を開始しません。移行に失敗した場合は再試行または閉じる操作を提供し、移行に必要な旧全体設定が先に変更されることを防ぎます。

## 分担とレビュー

全体の三択モデル・UI・下書きは Terra / medium、アプリ別設定と移行は Sol / medium、統合・エミュレーターの E2E・文書はメインで担当しました。別の Sol / medium が実装をレビューし、指摘は Astra / low が独立検証しました。後者は二つの保存先の失敗・再起動にまたがる状態の判断を含むための割当てです。

| 指摘 | 独立した判定 | 対応 |
| --- | --- | --- |
| 保存待ちの移行に別の全体値を渡すと、初回に決めた移行結果が変わる | 妥当 | 最初の旧設定値を保持し、重複した移行要求をまとめます。待機中の true→false と再読込の回帰試験を追加しました |
| 移行失敗中に全体設定だけ保存すると、再起動後に旧アプリ別設定の意味が失われる | 妥当 | 移行保存が成功するまで全体設定の編集・保存を開始しません。失敗・保存試行・再試行・再起動の回帰試験を追加しました |

修正後の再レビューでは、新しい修正対象はありませんでした。

## 検証方針

単体試験では旧形式、三択の保存・再読込、下書き・回転、全体三択とアプリ別四択の組合せ、保存中・失敗・移行の順序を検査します。エミュレーターでは設定画面から選択し、アプリ本文の C-a が全選択か行頭移動か、IME 内で `Ka C-b ta C-j` が `かた` か `たか` になるかで、実際の適用範囲を確認します。キーイベントの受信数だけで有効・無効を判定しません。

試験で触れるアプリ別設定の SharedPreferences も退避・復元対象に追加しました。実際の会話へのメッセージ送信は行いません。
