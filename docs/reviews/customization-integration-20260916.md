# 入力設定・キー・Emacs 編集の統合レビュー

履歴資料です。対象時点の判定を保持しています。現在の仕様・残件との区別は [レビュー履歴の案内](README.md) を参照します。

2026-09-16。検証件数の最新値は `docs/work-status.md` に記録します。以下は指摘を実装へ照合した結果であり、レビュー担当の報告だけで成功を宣言しません。

## 設定保存と画面

直列 I/O、世代照合、全件検証後の AtomicFile 保存を採用しました。深い JSON が JSON オブジェクト生成前にスタックを消費する問題を、深さ上限と不正入力試験で修正しました。規則選択で未適用の編集が消える問題は選択変更を止めて案内する方式にし、回転で編集中の項目も保持します。

保存・標準復旧中の回転では、要求した設定と保存前世代を保持し、直列保存後の耐久スナップショットに再照合します。成功、保存失敗、標準復旧の実際の画面再作成を試験します。保持オブジェクトのフィールドだけを見る試験は受入証拠として不足すると判断し、実処理を進める試験に置き換えました。

サービスは `onStartInput` ごとに公開設定を固定します。読込待ちの旧入力欄や終了後のサービスに、遅延完了からセッションを作りません。設定待ちの間は元のキーを渡し、未準備の標準規則で変換しません。

## 意味操作と編集

文字中に埋め込まれていた SKK コマンドを意味操作へ分け、設定済みキーから解決します。未割当文字は旧コマンドとして再解釈しません。標準割当では既存の入力列との比較試験を行い、標準の `nq` がローマ字継続に奪われる回帰を修正しました。非標準プロファイルでは有効な継続規則を優先し、AZIK の `kl`、`x[` を途中の切替で分断しません。

登録内の直接入力と全角入力、読み補完と abbrev 補完、登録内の候補一覧を別の状態として扱います。登録内一覧を外側の `candidate` だけで判定する問題があり、内側候補を参照するよう修正しました。候補ラベル `l` がモード切替になる具体例を回帰試験へ追加しました。

内部編集では、未消化ローマ字を登録本文へ確定した一打で同時に移動・削除する不一致を修正しました。本文上限で確定できない場合は未消化列を含む状態を復元します。補完提案の破棄、送り境界、目標列、親の登録本文へ越境しないことを試験します。

## 外部編集の独立検証

Astra / low の実装担当とは別の検証担当が、接続・タイムアウト・選択通知の境界を確認しました。

- EEP-01: 変更要求後の予期しない選択通知でも編集を継続できる問題を修正しました。同じセッションの不一致はポートを停止します。
- EEP-02: 取得窓末尾の CR を完全な CRLF と誤認し、途中へ HOME で移動する問題を修正しました。
- EEP-03: 外部変更の revision と、自分の期待する選択通知を区別する契約を明示し、要求後も revision を照合します。
- EEP-04: 最終照合直後のアプリ変更を完全に防ぐ追加保証は実現できません。InputConnection が比較付き原子操作を持たない制約として設計に記録し、実装欠陥と混同しません。
- EEP-05: 前の編集の選択通知が次の編集中に届くと編集機能を止める問題を修正しました。上限付きの期待通知列を維持し、古い通知で現在位置を巻き戻しません。具体的な三操作の回帰と独立再確認を行いました。

外部編集の取得窓、対応 API、期限、失敗時の停止、文書末尾を証明できない場合の拒否は `docs/emacs-editing-design.md` を正本とします。全アプリや実機の同時編集への完全な保証はありません。

## AZIK

Sol / medium の別担当による仕様照合で、通常入力 `ia`／`ii` を壊す上書き、`wl` の出力、特殊拡張と外来音の欠落を修正しました。一次仕様の動作と DDSKK の互換追加を分けて記録します。規則単体に加え、実マッパーとエンジンを組み合わせた `q`、`kl`、`x[`、`xxa`、かな切替の試験を追加しました。物理配列ごとの受入は別途必要です。

## 実エミュレーターで見つかった追加境界

API 26 の設定 E2E で、`adb exec-out` が `cat` の欠落エラーを終了コード 0 の標準出力へ返す場合を確認しました。退避実行器がこれを実在ファイルと誤認したため、退避ファイルの正確なエラー文字列と初回記録から欠落を証明し、3 API の元の設定を手動復元しました。実在した `settings.xml` は SHA-256 とバイト一致、元の欠落ファイルは終了コード・標準エラーを照合しました。結果は各初回履歴の `manual-recovery.json` に記録しています。復元未完了のまま試験を継続していません。

同じ復旧境界で反復修正となったため、実行器の担当を Terra / medium から Sol / medium へ上げました。実機で確認した `adb shell -T` の終了コードと分離された標準エラーを使い、固定パス・欠落・バイナリ転送を別々に検証します。古い実行器が記録した `restored: true` だけを復旧証拠として採用しません。

外部編集では、入力欄のカーソル移動が見えてから IME の完了通知までの間に次の操作が来ると、それを独立変更として扱い操作を捨てる問題を実 E2E で確認しました。選択通知だけの修正では解消せず、担当を Astra / low から Astra / high へ上げて競合境界を再検討しました。入力先の表示を待つだけでは非同期操作全体の完了を示さないため、試験に固定 sleep を足して隠す方針は採りません。後続操作は上限付き FIFO とし、独立変更・接続終了・失敗で取り消します。

また Meta/Super 付きキーが削除確認・保存待ちの保護より前に通過する問題を修正し、通常時の通過と保護中の消費を対で試験しました。


### 連続編集の再検証

表示側の選択更新がポートの確認完了より先行する E2E 失敗を受け、担当を demanding から architecture（Astra / high）へ上げました。原因は後続キーで進行中の版を無効化し、そのキーを捨てていたことです。待機 64 コマンドの FIFO と、旧 worker の実行権解放後の正常完了通知へ修正しました。超過キーだけを消費し、受理済みの処理順は保持します。

別の Astra / low 担当が版変更・選択通知・タイムアウト・終了・削除の一回性を再確認し、新たな具体的欠陥はありませんでした。コア 241 件、Android 単体 316 実行、ホスト 13 件が成功し、API 26・30・35 の入力設定 E2E も各 1 件成功しました。履歴は作業記録に記載します。
