# 完全辞書バックアップの独立レビュー

履歴資料です。対象時点の判定を保持しています。現在の仕様・残件との区別は [レビュー履歴の案内](README.md) を参照します。

2026-09-16。基準コミット `17a5cf0` からの実装差分を検査しました。復元設計・保存層・管理器は demanding（Astra / low）、形式処理と SAF 試験は complex（Sol / medium）、追加移行試験は standard（Terra / medium）へ割り当てました。別の Astra / low 担当が境界を読み、メインセッションが Gradle と端末試験を実行しました。

## 指摘と修正

- BACKUP-01: 保存関数の呼出時だけに epoch を取得すると、復元前から開いていた登録が復元後の初回保存で通過します。入力セッション開始時のコンテキストを要求へ渡し、受理・書込直前に照合します。復元のコミットで失効させ、入力先の表示済み本文を保持して旧確認を終了した後だけコンテキストを更新します。公開失敗時も旧許可は復活しません。
- BACKUP-02: 有効ソースだけで組み込み辞書の重複を除くと、無効な保存済み辞書が再出現します。全保存済み ID と fallback 方針を同じ snapshot に持たせます。復元済みの組み込み ID は通常の保存済み世代で削除を検証します。
- BACKUP-03: Unicode 対応の数値・16進判定が JSON で禁止される数字を受理していました。ASCII に限定し、`1١` と `\u00６1` の拒否を追加しました。
- BACKUP-04: 未知フィールドの拒否がオブジェクト全体の構築後だったため、上限内の一行でも多数の map 項目を作れました。最大 8 フィールドとフィールド名長の上限を挿入前に検査します。

修正後の独立レビューでは、上記の解消を確認し、新しい具体的な重大欠陥はありませんでした。準備済みハンドルの所有者・一回性、全件検証、revision 競合、単調な世代台帳、未知版拒否、入力 close 失敗、容量不足、保存済みだが未公開の再読込も検査しました。

## 試験の解釈

実 SQLite の復元、無効辞書・抑止・台帳・世代の保持、移行、全件巻戻しを単体と Android instrumentation で検証します。別プロセス終了試験は、宣言済みの同一 UID・正確なプロセス名・自身と異なる PID を確認して終了し、UUID 名の試験 DB だけを削除します。

コミット直前は transaction の成功設定より前に停止し、再接続後の全旧状態を比較します。コミット後は repository の終了後、検索 snapshot を公開する前に停止し、新状態の永続化を比較します。コミット途中の電源断や物理ストレージ枯渇を実証したものではありません。容量試験は SQLite の `max_page_count` による割当失敗です。

旧 v2 fixture の追加試験では、送りなしキーに送り条件を付けた不正 fixture が export で拒否されました。正しい送りありキーへ修正し、注釈・送り・抑止・順序・台帳の検証範囲は保持しました。これは旧版 APK の更新インストール試験とは区別します。

SAF E2E は実 DocumentsUI の作成・選択・明示確認・取消・不正ファイルを通します。管理器には分離した UUID DB を渡し、日常の辞書は置換しません。結果は [継続記録](../work-status.md) に記載します。実 SAF プロバイダーの close 失敗、実機と物理キーは別の検証範囲です。


SAF 試験の別担当 QA では、後始末の一箇所が失敗すると残りの cleanup が実行されない点を修正しました。各 cleanup を個別に試し、失敗を集約します。設定画面の入口は分離した Activity 試験でリンクを確認し、SAF E2E 自体は DB を注入したバックアップ画面からの実経路として扱います。runner が任意 API のエミュレーターを受け付ける点は、API を実測して履歴へ記録する仕様であり、26／35 固定を要求していないため誤検知と判定しました。
