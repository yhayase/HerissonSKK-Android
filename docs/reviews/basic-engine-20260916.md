対象は `BasicSkkEngine.kt` と `BasicSkkEngineTest.kt` です。`docs/core-design.md` の残余終端、候補取消時の復元、内部カーソル、送り境界の契約に照らして確認しました。

## 判定

BE01〜BE04 は修正済みです。併せて、変換器には定義済みだった `n'` 規則へエンジンから apostrophe を渡していなかった K01 の欠落も修正しました。対象範囲に未解消の指摘はありません。

| 項目 | 修正前 | 修正後 |
| --- | --- | --- |
| BE01 | 通常入力の未消化 `k`／`n` がある状態で絵文字や句読点を入力すると、リテラルが先に確定し、残余が次の Enter まで残りました | リテラルの直前に切替前の現在モードで残余を終端し、同じ確定結果へ入力順で連結します。ひらがな、カタカナ、半角カナを固定値で確認しました |
| BE02 | 検索時の `finish()` が読みバッファを書き換えるため、候補を取り消しても検索前の残余とカーソルを復元できませんでした | 検索前の段階、本文、カーソル、送り境界・開始子音、残余、残余の挿入先をスナップショットに保存します。C-g、先頭候補からの `x`、候補末尾の次で検索前の状態を復元します |
| BE03 | 表示用 composition の末尾へ常に残余を追加していました | 内部カーソルで本文を前後に分け、その間へ残余を表示します。表示カーソルは残余直後に置きます |
| BE04 | 本文が空でなければ、カーソルが先頭でも大文字を送り開始として扱い、送り境界0を作りました | カーソルより前に非空の語幹がある場合だけ送りを開始します |
| K01 | `n'` の apostrophe をリテラルとして処理し、`ん'` になりました | ASCII 英字と apostrophe をローマ字入力として変換器へ渡し、通常入力と見出し語の双方で `n'` を `ん` にします |

## 状態復元の確認

途中カーソルでは、`Nihon` を Home で先頭へ移動して `k` を入力した状態から検索し、取消後に本文 `にほん`、残余 `k`、カーソル0、段階 `READING` へ戻ることを状態全体の一致で確認しました。表示は `kにほん`、表示カーソルは1です。

送りでは、`NihonK` の未消化 `k` を検索で一時的に送りへ終端した後、先頭候補から `x` で戻り、本文 `にほん`、送り開始子音 `k`、空の送り、残余 `k`、カーソル3を検索前と同じ値へ戻すことを確認しました。検索取消後に残余を終端済みの `ん` として残す従来挙動は、設計の「検索前の読み・残余・編集位置へ復元」と一致しないため変更しています。
