# 設定・辞書管理・入力表示の再調整

2026-09-21の追加指摘を対象にします。アプリ名・アイコンの決定は引き続き今回の対象外です。

## 目的

アプリ別設定を名前・パッケージ名で検索でき、現在の設定を読めること、辞書の構成と操作を一覧上で理解できること、文字キーとフリック記号を識別できることを目指します。標準ローマ字の予測と未成立のローマ字列も修正します。

## 原因と対応

- アプリ別Emacs編集は常設のSearchViewから随時絞り込みます。検索語は画面回転後も保持し、有効・無効の実効状態を主表示へ移します。キー割り当ても現在値を主表示へ移し、標準値の常設表示を除きます。
- 物理キーボードの設定は「物理キーボード接続中は画面の文字キーを隠す」とし、対象を明記します。保存キーと表示条件は変えません。利用者が挙げた「画面キーボードを使用」は、配列設定リンクから開くAndroid側の併用設定でした。OS側の文言は変更せず、意味とIME独自設定との違いを利用手順に記録しました。
- 辞書は正式名、優先順位の順で並べます。RecyclerViewのハンドルで並べ替え、ゴミ箱から確認の上で削除します。追加はMaterialのFloatingActionButtonから取得元を選びます。更新には保存済みの取得元だけを使います。
- ファイルの取得元は永続読取権限とともに保存します。バックアップに含まれるURIだけでは読取を許可せず、更新時にOSが保持する同一URIの読取権限を必須とします。旧版で取得元を保存しなかった辞書や、別端末で復元して権限がない辞書は再追加が必要です。
- 主文字の基準サイズを16spから24spへ拡大し、実際のグリフ・キー寸法に応じて調整します。ピリオド・コンマは英字のベースラインを参照し、中央の点として描きません。フリック記号はキー面からさらに4dpを基準とする余白を確保します。

## 予測入力の調査

旧処理は`てn`をかなへ展開していましたが、`てに`で検索できる`てにゃ`・`てにゅ`・`てにょ`も個別に検索し、処理量と結果文字数の予算を分割していました。一つの枝が上限に達すると予測全体を未確定扱いとするため、候補が表示されなくなっていました。

インストール済みSKK-JISYO.Lの関連759行（うち`てん`で始まる711行）を使った一時的な調査では、旧10分割の6,553文字では`RESULT_LIMIT`、重複を除く7分割の9,362文字では`Ready(hasMore=true)`を確認しました。環境依存の辞書を試験資産へ同梱せず、同じ上限差を再現する生成データの回帰試験を残しました。

検索範囲が短い前方一致に包含される枝を除き、`てな/てに/てぬ/てね/ての/てん`と英字を含む`てn`を検索します。`てk`もかなへの展開と英字のままの検索を含みます。全体の処理量・結果文字数の上限、最近使った候補の順位付けは維持します。AZIKなど標準以外のローマ字規則に応じた整備は将来の拡張としてロードマップへ記録しました。

DDSKKの`skk-kana-input`を参照し、不成立のローマ字列は以前の未確定接頭部を捨て、今回のキーを根から処理し直します。`zc`は`z`を確定せず`c`を保留します。

## 独立レビュー

- 保存されたcontent URIについて、実装担当とは別の担当が権限照合・非公開Activity・容量制限・更新先の分離を確認しました。バックアップ内のURIによってアプリの権限を流用する経路は確認されませんでした。
- ドラッグだけでは物理キー・読み上げ操作から並べ替えられない指摘は別担当が妥当と判定し、ハンドルを選択した際の移動メニューを追加しました。
- 不成立の複数文字接頭部で`kyt`が`k`を確定してしまう指摘も別担当が妥当と判定し、単一文字だけでなく以前の接頭部全体を破棄するよう修正しました。
- 文字キーの描画と試験は実装担当以外が確認し、実グリフの非重複・余白・ベースラインと、狭幅・縦横・拡大文字の条件を確認しました。

設定の再表示・再試行について複数回の修正が必要になったため、当該部分をSol/mediumからAstra/lowへ引き上げました。保存済み一覧を再確認し、未確認の間は完了を無効にします。失敗時の再試行は一覧確認から行い、初期S導入の遅い応答が明示選択済みのLを上書きしないことを検証します。別担当のレビューと、さらに別の担当の指摘検証を行いました。

初回のS自動準備が既に始まってからLを選ぶと、Sを一時的に取得した後でLへ置き換える場合があります。最終構成にはLだけが残ります。追加レビューでこの点は、承認済みのS自動準備と両立する任意の取得量最適化であり、最終構成の重複不具合ではないと判定しました。

ファイル取得元のcontent URIを含む完全バックアップは、HTTPS取得元だけを受理していた旧開発版では復元できません。復元先もこの版以降へ更新します。URI自体を復元しても、OSのファイル権限は復元されません。

通常のPreferenceの末尾にある現在値が省略される懸念は、別担当がテーマの`singleLineTitle=false`と拡大文字の実画像を照合し、誤検知と判定しました。長いコマンド名と現在値は折り返されます。不要な描画変更は行いませんでした。
