# カスタマイズ・編集計画の基盤検証

履歴資料です。対象時点の判定を保持しています。現在の仕様・残件との区別は [レビュー履歴の案内](README.md) を参照します。

2026-09-16。[カスタマイズ設計](../customization-design.md)と[Emacs編集設計](../emacs-editing-design.md)のうち、純粋コアの基盤を実装しました。設定画面、設定保存、キー変更、AZIK、入力先編集はこの時点では未接続です。

ローマ字規則は不変な索引を一度だけ構築し、状態復元でも同じ規則を使います。件数・文字数・Unicode・重複・残余循環を検査し、4,096段でも再帰スタックに依存しない検証にしました。通常補完の終端判定も固定のn判定から規則へ移しました。

句読点はかなの通常入力・読み・登録本文に適用し、直接入力・abbrev・半角カナへ混入させません。初期値は句点「。」、読点「、」、丸括弧全角です。旧コアの句点リテラル期待値二件は、この採用仕様に合わせて変更しました。全句読点の組合せと適用範囲を別の試験で検査しています。

候補はラベルと一ページの件数を設定でき、候補選択開始時に件数を固定します。幅変更中のラベルずれを避け、登録からの復帰も同じ対応を使います。初期の自動計算は文字倍率を反映した96 dpの最小枠を使い、1〜ラベル数へ制限します。

別担当のレビューで、汎用規則集合が受け入れた大文字キーをSKKの大文字開始文法では実行できないことを確認しました。SKKエンジン開始時に拒否し、設定層も保存前に拒否する契約にしました。無効な設定を黙って使いません。

編集計画は完全な文字列と向き付き選択から、移動先または削除範囲を計算するだけの純粋処理です。論理行、CRLF、Unicode書記素、列保持、単語境界、範囲選択と削除後の再分割を別担当がレビューしました。InputConnectionの取得・適用能力を証明する部品ではありません。

検証はコア205件、Android単体178実行がすべて成功し、失敗・エラー・スキップは0件でした。新しい設定による実IME操作と外部編集のE2Eは後続です。完成済みの補完の実IME結果と混同しません。
