# ストレージ主体の辞書検索への変更と独立レビュー

## 目的

大きな辞書でも起動時と学習時の処理量が全候補数に比例しないようにします。SQLiteを正本とし、通常経路から全件スナップショットの構築を外します。[設計契約](../dictionary-storage-cache-design.md) に上限・非同期入力・互換性を記載します。

## 採用した方法

起動時と保存後は辞書一覧・世代などの管理情報だけを公開します。見出し検索と前方一致検索は索引を使って必要な範囲だけを読み、直近の結果を有限LRUに保持します。保存後は世代を更新して旧キャッシュを失効させます。保存中の順位反映、由来と削除の世代検証、復元前の書き込み禁止を維持します。

入力スレッドからの未取得検索は読み込み要求として扱い、エンジンの状態を巻き戻します。ワーカーの読み込み後、同じ入力先・操作が有効な場合だけ再実行します。再実行前には候補を確定したり学習したりしません。待機中の物理キーは到着順に保持し、結果が届いた状態で改めて解釈します。

通常検索の全件読み出しは廃止しましたが、明示的な入出力・完全バックアップと、旧故障注入試験用のスナップショットAPIは残します。これらを通常起動・学習へ流用しません。

## 独立レビューで修正した点

- 補完では、表示可能な見出しが一つ見つかった後に残りの全候補を走査しないようにしました。多数の候補を持つ見出しの後ろにも補完候補があるケースを実SQLiteの回帰試験にしました。
- 再実行したキーが入力先への素通しになっても、後続の待機キーを消さないようにしました。
- 入力待機キューが64件を超えた場合に受理済みキーを捨てる実装は採用しませんでした。辞書キャッシュの上限と入力待機を分離し、100件の入力を順序どおり反映する試験を追加しました。
- 一見出しがキャッシュ上限を超えても変換不能にせず、一操作だけの作業領域で扱います。大きな数値テンプレートと `#4` の参照先を交互に読み直して進まなくなるケースも、操作中の結果保持で防ぎます。
- 終了済みリポジトリーへ遅延した検索が届いてもSQLite接続を開き直さないようにしました。
- 全単体試験で見つかった、候補削除の重複完了通知による不要な再描画を修正しました。

レビューでは、古い公開世代で新しいDBの未キャッシュ候補を読まないこと、空の個人見出しでも削除用の世代を保持すること、無効辞書が組み込み辞書を隠す条件、復元時の組み込み辞書無効化、数値変換の世代混在防止も確認しました。

## 検証の根拠と限界

通常初期化で候補・補完・全件の読み込み回数が0であること、キャッシュの件数・レコード数・文字数による追い出し、追い出し後の保存先からの再取得を検証します。学習ではSQLiteトリガーを使い、無関係な見出しへのINSERT・UPDATE・DELETEが起きないことも確認します。

同じAPI 26エミュレーターで旧配布APKと新実装を測定します。初回検索はアプリのキャッシュが空である条件であり、ストレージのOSキャッシュは温まっています。PSSには試験用の合成辞書も含まれるため、キャッシュのメモリー量と同一視しません。最終APKの測定・E2E結果は [作業記録](../work-status.md) と [性能測定](../dictionary-performance.md) に記録します。Xiaomi Pad 8での起動・入力速度は未測定です。
