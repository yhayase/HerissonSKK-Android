# 実機受入で挙がった入力UI以外の修正

対象日: 2026-09-20

## 変更範囲

- C-jは確定のみ、Enterは既定で通常入力の確定後に入力欄の改行・アクションを一度実行します。未確定中のEnterを確定だけにする設定は既定オフです。登録・削除確認のEnterは入力先へ渡しません。
- Emacs編集が有効な入力先で、Ctrl+/はUndo、Ctrl+yはPasteです。入力先アプリが対応する操作へ渡します。
- Ctrl+kは、取得した本文の末尾を確認できた場合に最終行も削除します。削除範囲は先にAndroidのクリップボードへ保存し、保存失敗・セッション失効時には削除しません。
- 基底パッケージとアプリIDをse.haya.skkへ変更しました。旧試用版とは別アプリです。[移行手順](../package-migration.md)に辞書バックアップ・復元の手順と設定の再設定を記録しました。

キーボード配列・カーソル近傍の表示・候補メニュー・再帰登録表示の再設計は、この修正に含めません。先行修正後に設計を議論します。

## 独立レビューと指摘検証

実装をSol / mediumへ委任し、入力先編集の境界をAstra / low、パッケージ移行・文書と試験をTerra / mediumが確認しました。指摘は別担当が現行コードで検証しました。

- クリップボード保存中に入力セッションが失効した場合の削除継続を防ぎ、保存後にも有効状態と期限を確認します。回帰試験を追加し、別担当が修正済みと確認しました。
- 候補のcommitTextが拒否されても「キーを消費した」という戻り値はtrueでした。この値だけでEnterの入力先アクションを続ける問題を、別担当が妥当と判定しました。物理・タッチの両経路で確定後のactive/failedを確認し、拒否時はアクションを送らない回帰試験を追加しました。独立レビューで修正済みと確認しました。
- カーソル移動E2Eの初回失敗は、変更前からある試験が別プロセスの選択通知完了を待たない問題でした。現行修正による回帰の証拠にはならないと別担当が判定しました。入力位置0と旧composing spanの解除を観測してから次の文字を送り、期待値「あ日本」は維持します。常時スナップショット取得などの製品コード変更は行っていません。

- Undoの初回E2Eは、Ctrl+kで削除した直後にCtrl+yで元へ戻した操作を、Ctrl+/が貼り付けだけ取り消すと仮定して失敗しました。実測では同じ列のCtrl+zも同じ結果となり、貼り付け単独では両方が元へ戻りました。入力先のUndo単位に従う仕様として別担当が検証し、最終行の削除・貼り付けと、独立した入力欄での貼り付け・Undoに分けました。製品側のUndo経路は変更していません。

## 残る制約

入力先がUndo/Pasteを実装していなければ実行できません。Ctrl+kは、本文末尾や編集範囲を確認できない入力先では推測で削除しません。クリップボード保存と削除は原子的ではないため、削除拒否時にもコピーした文字が残る場合があります。

旧アプリの辞書はバックアップで移します。入力設定・キー割当・アプリ別Emacs設定・AndroidのIME選択は移らないため、新版で設定し直します。本番署名・公開・利用者端末への新版導入は実施していません。
