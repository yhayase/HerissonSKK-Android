# 設定画面とフリック表示の修正・検証

2026-09-21の実機指摘を対象とします。アプリ名とアイコンの決定はロードマップへ追加するだけとし、この変更では実施しません。

## 変更の目的と範囲

- 設定をAndroidX Preferenceの目的別階層へ変更します。ページ名・戻る操作と保存操作を固定し、本文だけをスクロールします。幅は最大720dp、下部操作は最大360dpに制限します。
- 編集は下書きで保持し、保存成功で上位画面へ戻ります。未保存で戻る場合は保存・破棄・キャンセルを選びます。標準化はページ内に限定します。辞書管理には共通の標準値がないため保存だけを置きます。アプリ別設定とバックアップは個々の明示操作で保存する画面です。
- ローマ字は標準・AZIK・カスタムを選び、カスタム規則を一覧・検索・行単位の編集で扱います。辞書は現在の有効状態と優先順位を先に示し、対象の行から更新・移動・削除を選びます。
- 初期設定を分離し、Sを自動導入します。承認済みカタログはS・L・人名・地名・郵便番号の5種類です。郵便番号の配布元更新は2022年5月と表示します。
- フリック記号は矢印を除き、キー内の右上・右下へ配置します。通常の英字大文字化は表示を省略します。
- アプリ側のEmacs編集が無効でも、IME内の編集を有効にできる独立設定を追加します。旧設定は追加項目オフとして移行します。

## 独立レビューと指摘の検証

実装担当とは別の担当がレビューし、指摘はさらに別の担当が現行コードと再現条件を照合しました。

| 指摘 | 独立判定と対応 |
| --- | --- |
| 一般設定の保存で、変更していない学習設定まで失敗・停止扱いになる | 妥当。ページの変更分だけを保存し、ストアでも未変更値を除外します。成功・失敗の両方で学習方針を維持する試験を追加しました |
| 一般設定の回転で復元Fragmentが未初期化の下書きを参照する／保存完了を失う | 妥当。復元前に下書きを用意し、進行中の保存状態を画面から独立して保持します |
| 初期設定の保存後の公開失敗を導入完了扱いする | 妥当。利用可能な公開状態まで確認し、再試行は保存済み内容を再公開します |
| 初期設定のプロセス再生成で選択済み追加辞書が再開しない | 妥当。完了対象を保存し、状態購読の前に導入要求を再開します |
| 初期設定の遅いコールバックが再試行を上書きする | 直列実行経路では指摘の競合を再現できず、誤検知として修正対象から除外しました |
| カスタマイズ保存の世代競合から復帰できない | 妥当。最新値と下書きを三方向で比較し、同じ項目の競合は利用者が残す値を選択します。再度保存するまで書き込みません |
| 辞書の文字コード選択が回転で失われる | 妥当。ファイル選択要求だけでなく現在の選択も復元します |
| 辞書の利用可否が実際の設定行に表示されない | 妥当。実際のPreference行へ利用状態を結び付けます |
| 辞書の詳細操作で内部ファイル名へ戻る | 妥当。表示名を統一し、保存する識別名とは分離します |
| 英字の上フリックに大文字の補助表示がない | 大文字化は省略する承認済み要件のため誤検知です |
| フリックの主文字と補助表示の境界判定 | 描画と測定を一致させ、文字の実境界で重複を検査します。修正の繰り返しを受けTerra/mediumからSol/mediumへ担当を引き上げ、別担当が再レビューしました |

内部Emacs編集の試験では、IME内カーソル移動に必要な`InputConnection.setSelection`を外部編集と誤認した検査を修正しました。外部編集ワーカーへの要求が増えないことと、IME内の実際のカーソル移動を別々に検証します。

完全バックアップ画面も共通の設定階層へ移行し、別担当が画面再作成・確認待ちの復元データ・遅延コールバック・処理中の戻る操作を確認しました。保存形式や復元の明示確認は変更していません。

UI試験のレビューでは、短いページが動いていないだけでも固定表示の検査を通過する点が見つかりました。独立検証後、長いキー割り当てページで本文の移動を必須にし、見出しと下部操作の座標不変、本文幅の720dp上限と中央配置、本文表示領域内への収まりを確認する試験に改めました。文字そのものの見切れは画像でも確認します。

## Android 8の初回Ctrl+kで見つかった問題

設定E2Eで、Android 8だけ初回のCtrl+kが本文を変更しない状態を同じ条件で2回再現しました。原因はクリップボードへの初回アクセスを編集ワーカーで行っていたことです。[Android 8のClipboardManager](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-8.0.0_r1/core/java/android/content/ClipboardManager.java)は初期化時に呼出し元のLooperを使うHandlerを作成します。Looperのないワーカーでは初期化が失敗し、コピー失敗時に削除しない保護が働いていました。

実装経路と一次資料を別担当が照合し、さらに修正後のライフサイクルと入力本文の扱いをレビューしました。ClipboardManagerだけをIMEのonCreateで取得し、ワーカーは取得済みインスタンスを使います。コピー成功前に削除しない保護は維持します。個人データの追加保持は行いません。

SAFの古い試験には、候補確定にEnterを使いながら改行なしを期待する箇所が残っていました。承認済みのEnter契約に従い、確定だけを意図した9箇所はC-jへ変更しました。再帰登録の完了操作はEnterのままです。画面外にある設定項目は、アプリのPreference一覧だけをスクロールして探します。

## Paste直後のUndoが失われる競合

最終E2Eで、貼り付けた文字が入力欄へ見えていても、その直後のUndoが消えるケースが見つかりました。詳細調査をSol/mediumからAstra/lowへ引き上げ、別のSol担当が因果関係を独立検証しました。貼り付けによる選択通知を外部操作と誤認し、先に受理したUndoを待機列から破棄していました。

発行中のコンテキスト操作に限って通知を保留し、操作後の取得位置と照合する修正を採用しました。永久に通知を自分の操作とみなす方式は採用しません。不一致・取得不能なら待機列を破棄し、後からの外部選択変更も引き続き検知します。操作を再送することはありません。早い通知、遅い通知、無変化、取得不能、不一致、後続の外部選択を含む決定的な回帰試験を加え、接続・セッションの重点178件が成功しました。実装担当とは別の担当のレビューで未解決の指摘はありません。

WebViewの試験準備は、入力欄側の接続生成だけでなく、新しい接続がSKKの座標監視要求を受けたことまで待ちます。試験アプリのInputConnectionを委譲ラッパーで観測し、接続番号を照合します。古い接続の遅延通知は成立条件になりません。入力結果の検査を弱めたり、固定時間を待って通過させる方法は採用していません。別担当のレビューも完了しました。Android 13以降ではフレームワークが二引数の`requestCursorUpdates`を呼ぶため、両オーバーロードを同じ方法で観測します。元の入力接続への委譲は維持します。試験アプリが参照しないAndroidX注釈を追加する必要はなく、プラットフォームの`TargetApi`を使用します。
