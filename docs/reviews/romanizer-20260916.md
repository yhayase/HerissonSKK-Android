# ローマ字変換・文字種変換レビュー

履歴資料です。対象時点の判定を保持しています。現在の仕様・残件との区別は [レビュー履歴の案内](README.md) を参照します。

実施日: 2026-09-16

対象は `Romanizer.kt`、`KanaTransforms.kt` と、それぞれの JVM 単体試験です。Android 接続、基本変換エンジン、辞書処理はこのレビューの対象外です。

## 判定

ROM001〜ROM005 の修正を再確認し、対象範囲に追加の欠陥は確認しませんでした。特に、接頭辞が重なる規則の終端処理は、短い完全一致の出力を失わず、その規則が生成した残余も続けて解決します。

| 項目 | 確認内容 | 結果 |
| --- | --- | --- |
| ROM001 | `a → A`、`ab → B` で `a` を終端すると `A` を返す | 合格 |
| ROM001 | `a → A + c`、`ab → B`、`c → C` で `a` を終端すると `AC` を返す | 合格 |
| ROM002 | 終端専用の `n` は通常入力中に確定せず、終端時だけ `ん` を返す | 合格 |
| ROM003 | 終端出力と通常出力、または終端出力と残余を同じ規則に設定すると拒否する | 合格 |
| ROM003 | 明白な残余循環を初期化時に拒否し、非循環の残余列は規則数に基づく上限内で完了する | 合格 |
| ROM004 | 半角カナ変換でカナ以外の `é` と `각` を正規化せず保存し、ひらがなの反復記号を `ヽ`／`ヾ` に変換する | 合格 |
| ROM005 | `wi`、`we`、`ye` をそれぞれ `うぃ`、`うぇ`、`いぇ` に変換する | 合格 |

## 実装確認

`finish()` は通常解決を先に実行し、未消化文字が残る間、完全一致の終端出力、通常出力と残余、未解決文字列の順に処理します。通常出力を追加した後に残余を `resolve()` へ渡すため、接頭辞が重なる短い規則でも出力と残余の両方が保持されます。

残余循環は規則表の構築時に検査されます。実行時にも、完全一致と既完了接頭辞の両方の書き換え経路で `rules.size + 1` 回を上限としていることを確認しました。現行試験は明白な循環の拒否と有限な三段の残余列を直接検査しています。防御用の実行時上限だけを強制的に発火させる試験はありませんが、構築時検査を通る通常規則の受入動作には影響しません。

`KanaTransforms.toHalfwidthKana()` はカタカナ範囲の文字だけを NFD へ分解するため、非カナ文字の正規化形を変更しません。変換表で全分解要素を扱える場合だけ半角へ変換し、扱えないカナは元の文字を保持します。
