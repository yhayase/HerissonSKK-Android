# リリース前の未解決試験の調査

## 対象と判定

`d28fd95` を基準に、入力文字数不一致（#2）、予測候補の待機失敗（#3）、回転後の再帰登録表示（#4）を調査しました。利用者による操作感の受入は維持し、Google Play の準備には着手していません。

### 入力文字数（#2）

合成キーの投入に `KeyCharacterMap.getEvents()` の時刻をそのまま使っていました。Android の `Instrumentation.sendStringSync()` は、後続イベントが古くなって破棄されることを避けるため、各イベントを投入する直前に時刻を更新します。この標準 API へ置き換え、登録本文の完全一致検査は維持しました。

API 26 の一時診断では、生成後12秒待った同じキーをそのまま送ると本文は変わらず、時刻を更新して送ると「あ」が1文字追加されました。Android のログにも `Dropped event because it is stale.` が押下・解放それぞれに残りました。一時診断は通常試験から除去しました。過去の失敗実行には受信ログがなく、当時の1文字欠落をこの原因と断定はできませんが、元の投入方法に存在した欠落経路と修正の効果を実測しました。

診断記録: `test-editor/build/reports/customization-e2e/emulator-5586/20260923T023534566867Z`。ログ: `build/reports/release-test-investigation-20260923/skk-stale-input-dispatcher.log`。

### 予測候補（#3）

製品の API 26 固有障害ではなく、辞書状態に依存した試験でした。API 26 には SKK-JISYO.S の6,764候補が残っており、API 35 には個人辞書だけがありました。「に」の検索だけでも前者には75行・59種類の候補本文があり、使用履歴の「二本」と読み順で先に来る候補により「日本」が表示幅の外へ出ます。予測候補にはページ送りがないため、「日本」が必ず表示されるという試験の前提が成立しませんでした。

同じ APK のまま辞書条件だけを固定すると、API 26 のタッチ試験は失敗2件を含む9件すべて成功しました。実行器は停止中の辞書 DB と journal/WAL/SHM を退避し、組込み試験辞書で実行した後、元のバイト列と補助ファイルの有無を復元します。既存の設定・IME 復元も維持します。元の辞書がない場合に試験で作られた補助ファイルが残らないこともホスト試験で確認します。

変更前の API 26 は7/9件、API 35 は9/9件成功。辞書を固定した API 26 は9/9件成功し、復元も成功しました。固定条件の記録: `test-editor/build/reports/customization-e2e/emulator-5586/20260923T023144411748Z`。

### 回転後の表示（#4）

過去の失敗箇所は、横画面へ回転した後の再帰登録ポップアップ待機です。表示窓の欠落と登録状態の消失をその記録だけでは区別できません。

独立調査と別担当の検証で、API 33 以降では回転直後のトークン未準備・窓追加失敗の後、窓の準備通知で物理ポップアップの接続を再試行しない経路を確認しました。`onWindowShown()` で表示条件を再評価して再接続します。非表示にする利用者操作や入力終了で表示許可を取り消す条件は維持します。

回帰試験は実際のサービスの窓準備通知を呼び、トークンなし、接続失敗、次の通知での成功を検査します。ただし、過去の失敗がこの経路だった証拠はなく、構成変更の1秒の保持期限も別の可能性として残ります。#4 は過去事象の原因まで解決した扱いにはしません。

## レビュー

入力・予測・回転を別担当が調査しました。回転の指摘は別担当が検証した後に修正し、さらに別担当が差分をレビューしました。補助関数だけを検査する当初のテストは不十分と判定し、サービスの実コールバックを検査するテストへ変更しました。辞書退避・復元の差分も別担当がレビューしています。

## 検証上の留意点

対象クラスの単体試験で、既存の API 35 テストが本文実行前の Robolectric フォント資源初期化で `FileSystemAlreadyExistsException` となりました。新規回帰テストの失敗とは区別し、初回記録を `build/reports/release-test-investigation-20260923/skk-visibility-first-failure.xml` に保存しています。後述の SDK 別実行で再検証しました。


対象クラスから新規テストを除いても、JDK 17 に変更しても初期化エラーが再現しました。全ゲート `build/reports/local-verification/20260923T023931850565Z` では Android 単体1,035件中39件が失敗し、後続の lint・成果物検査は完了していません。これは成功したゲートとして扱いません。

スタックは [Robolectric #10116](https://github.com/robolectric/robolectric/issues/10116) と一致し、[上流修正 #11496](https://github.com/robolectric/robolectric/pull/11496) は異なる SDK の環境が JVM 共通の ZIP ファイルシステムを重複して開く問題を説明しています。API 35 だけの同じクラスは成功しました。依存ライブラリや描画方式は変更せず、`verify-local.py` で API 26・30・35 を別々のテスト JVM で実行し、各 XML を保存して合計します。直接 `:app:testDebugUnitTest` を SDK 指定なしで実行する場合は、上流の問題が残ります。単独実行には `-Probolectric.enabledSdks=26`（または30・35）を指定できます。
