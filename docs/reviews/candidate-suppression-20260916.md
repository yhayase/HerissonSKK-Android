# 候補削除の保存層・抑止検索の独立レビュー

履歴資料です。対象時点の判定を保持しています。現在の仕様・残件との区別は [レビュー履歴の案内](README.md) を参照します。

個人候補の削除、由来ごとのシステム候補抑止、一件ずつの復元を単一トランザクションで扱います。個人辞書世代と全保存由来の世代・種別・候補同一性を検査し、方針禁止や競合では変更しません。システム原本と世代は削除操作で変更しません。

DB v2は抑止表と辞書IDごとの最大世代を保持します。同じIDを取り外して再追加しても世代を再利用せず、古い確認を新しい辞書へ適用しません。v1移行は既存の候補・順序・有効状態・世代を保持します。抑止は標準SKKテキスト書出しの対象外です。

別担当が原子性、故障点でのロールバック、世代台帳の移行、組み込みID承認と保存辞書へのなりすまし拒否、完全一致の抑止、個人候補を復活させない復元を確認しました。Managerが抑止一覧を落とす接続漏れを指摘し、snapshot経由で取り込み辞書と組み込み辞書の両方へ適用するよう修正しました。両方の検索と復元を管理器の試験で確認しました。

コア・Android単体試験に加え、旧スキーマを直接作成する移行試験と、抑止後の再接続・復元・同一ID辞書更新をAPI26・35の実SQLiteで検証しました。ネイティブ各8件が成功しています。

この段階では入力中の削除確認、数値候補の全由来の引渡し、復元管理画面は未接続です。K11全体の完了とは判定しません。
