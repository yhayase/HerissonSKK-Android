# 実機報告に基づく表示・辞書取り込みの修正

## 報告と原因

2026-09-17、候補画面が入力先を覆うこと、C-b が編集として動かないこと、skk-dev の L 辞書の取り込みが失敗することが報告されました。Emacs 編集設定はオフだったことをユーザーが確認しました。

- 候補は Android の candidates frame に置いていました。この領域は入力先のアプリをリサイズしないため、高さの上限だけでは入力欄の遮蔽を防げませんでした。
- C-b は Emacs 編集がオフなら入力先へ渡す仕様です。未確定の読みは引き渡し前に確定します。初期値やキー配送は変更せず、有効化と次の入力欄からの反映を設定画面に明記しました。
- 公式 L 辞書の 714 行目 `ゆるb /弛;[文語]/緩;[文語]/` に含まれる正規の注釈をパーサーが拒否していました。括弧付き注釈、引用符付き注釈、スラッシュや英字一文字の見出しにも対応不足がありました。

## 修正と独立レビュー

文字キーを持たない候補・状態表示を input frame に移し、Android が入力先へ必要な高さを通知する構成にしました。通常表示をコンパクトにし、長文の全文表示は引き続き有界にします。保護欄と状態表示オフの待機状態では表示要求を拒否します。

注釈はデータとして解析し、候補中の任意式は引き続き拒否します。辞書の読取・形式・保存の失敗はダイアログと保持される状態文で示します。解析中に画面が再作成された場合は、黙って完了扱いにせず再選択を案内します。

表示担当以外のレビューで、試験アプリ自身の IME 余白が遮蔽の検出を弱める可能性を指摘しました。API 26／30 は通常のリサイズ、API 35 は edge-to-edge のインセット処理を検証します。入力欄・表示領域の可視性とキャレット行の位置を検査します。辞書の信頼境界は別担当がレビューし、式を実行しないことと全体の厳密な解析を確認しました。画面再作成時の状態保持も別担当が確認しました。

## 検証の証拠と範囲

- 新しい表示 E2E を旧配布 APK `f025b9d` に対して実行すると、API 26 で「候補表示が画面下端の入力欄またはアプリ領域を覆っています」と失敗しました。同じ試験を修正版に対して実行すると 2 件成功しました。修正版の履歴は `test-editor/build/reports/display-e2e/emulator-5582/20260917T012316314764Z` です。
- 公式 [skk-dev/dict の L 辞書](https://github.com/skk-dev/dict/blob/master/SKK-JISYO.L) は 4,489,815 バイト、SHA-256 `c791f578d1b4040fce282db29bc22b2cc7ea46f83e269fab2e0fa779e2967e40` です。175,789 見出しを解析し、UTF-8 書き出し・再解析後の見出し別候補リストが一致しました。辞書全体はリポジトリや APK に同梱しません。
- API 35 の実 SQLite に全件を取り込み、DB を閉じて開き直した後の注釈とスラッシュ見出しの検索を確認しました。`app/build/reports/large-dictionary/20260917T012320Z` に APK・辞書のハッシュと 1 件成功の結果があります。試験用 DB と配置した辞書は削除しました。
- 取り込み失敗の状態保持・画面再作成試験は API 26／35 の Robolectric です。解析中断は状態マーカーを用いた試験で、実プロバイダーをブロックして回転させた試験ではありません。

最終の製品コードは `7398c40` です。ローカルゲート `20260917T012947172046Z` はコア 252 件、Android 単体 401 実行、ホスト 22 件、lint と配布物検査に成功しました。配布 APK の SHA-256 は `d24e37ed3bf509510aa738d8b39b5e1fe44951c6b86e2bade8c6cc097d384503` です。入力先終了時には表示を同期的に消去し、パスワード欄への移動でも表示が残らないことを確認しました。

最終 APK の入力 E2E は API 26／35 で各 13 件成功しました。履歴は `connection/emulator-5582/20260917T013037535385Z` と `connection/emulator-5584/20260917T013040119100Z` です。表示は API 26 `20260917T013038004179Z`、API 30 `20260917T013034174430Z` で各 2 件成功し、Emacs 編集を含む設定試験は API 35 `20260917T013040228799Z` で 1 件成功しました。いずれも `test-editor/build/reports/` 以下にあります。API 35 の表示試験も最終の終了処理追加前に成功しています。

API 30 の SAF 試験では、同じフォーカス中の入力欄を `setText("")` で消去した直後の打鍵と、遅延した選択通知の競合を検出しました。別担当の検証を経て、新しい ActivityScenario で各変換を試す手順へ変更しました。製品コードと配布 APK は変更していません。

変更後の SAF 試験は API 30 で 1 件成功し、開始時の個人辞書・設定・IME を復元しました。履歴は `test-editor/build/reports/saf-dictionary-e2e/emulator-5580/20260917T013359007185Z` です。修正版試験 APK のビルドと `:test-editor:lintDebug` も成功しています。

Xiaomi Pad 8 と報告元アプリでの修正版の確認は残ります。入力先が Android のリサイズや IME インセットに対応しない場合まで、非遮蔽を保証するものではありません。
