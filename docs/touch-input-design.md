# QWERTY画面キーボードとIME切り替えの設計

更新日: 2026-09-20。本書は初回リリースの画面キーボード、タッチ候補操作、物理キーボード接続時の表示、IME切り替えの実装契約を記録します。実機での操作感と表示の受入結果は本書だけでは確定しません。

再設計で合意した新しい操作・表示は[入力UI再設計の合意事項](input-ui-redesign.md)に記録します。以下は再設計前の実装契約です。

## 入力領域

入力ビューは、上から候補・状態領域、QWERTY文字領域の順に配置します。候補・状態領域は既存の高さ上限を保ち、一覧、注釈、登録、全文表示を縦にスクロールできます。文字領域は英字3段と操作2段で構成し、横画面ではキーを低くします。文字倍率はAndroidの`sp`倍率を反映しつつ、倍率1.5以上では基準文字サイズを下げ、入力欄を覆う高さの増加を抑えます。

英字面はQWERTY配列です。記号面は2ページあり、1ページ目の「記号 2/2」と2ページ目の「記号 1/2」で切り替えます。どちらのページからも「英字」で英字面へ戻れます。数字とすべてのASCII印字可能記号を入力でき、`¥`も1ページ目に残します。記号ページは文字入力後も変わらず、入力欄の切替時は英字面へ戻ります。Shiftは一回だけ有効です。次の英字を大文字の論理文字としてコアへ渡して解除します。この大文字がSKKの読み開始または送り開始になります。タッチ文字を物理キーイベントに変換せず、`BasicSkkAction.Text`として`EditorSession`へ渡します。

操作段は次を提供します。

| 表示 | 論理操作 |
| --- | --- |
| 空白/変換 | 次候補または変換開始 |
| 前候補 | 前候補 |
| 取消 | 現在の内側状態から一段取り消す |
| Backspace | コアが所有する未確定文字を削除する |
| 左・右 | 登録本文または読みのカーソルを移動する |
| 補完 | 次の補完候補を表示する |
| 登録 | 現在の読み・候補から明示登録を開始する |
| Enter | 内側の未確定状態、登録保存、通常確定の順で処理する |
| かな/英数 | 現在のモードに応じてかなと直接入力を切り替える |
| 記号/英字 | 文字面を切り替える |
| IME切替 | Androidの入力方法選択画面を開く。文字領域を隠している間も表示する |

再帰登録中も同じ文字領域を使います。Shiftで子の読みを開始し、変換または登録を操作できます。候補・状態領域には外側から内側までの登録階層を表示し、現在操作する最内層をかぎ括弧で示し、「操作対象」として層番号も表示します。登録本文、子の読み、子候補は入力先へ流しません。

## 候補のタッチ確定

候補タイルは候補一覧内の絶対位置を保持し、タップすると`BasicSkkAction.SelectCandidate`でその候補を確定します。描画時に次の値を固定します。

- 入力セッション世代
- 候補表示の版
- 候補の絶対位置
- 候補オブジェクトの参照
- 登録の深さ

タップ時に現在のセッション、候補表示の版、表示ページ、候補参照、登録の深さをすべて照合します。一つでも変わっていれば操作を破棄します。サービスの構成版と入力セッション世代は分離し、構成変更後に新しく描画した候補まで古い操作として拒否しません。これにより、非同期辞書読込、入力欄切替、取消、再帰登録の開始・終了、ページ移動の後に古いタイルが別の文字を確定しません。照合後の操作と、コアが処理しなかった編集操作は、どちらも`EditorSession`に固定された`InputConnection`だけへ適用します。

## 物理キーボードとの切替

既定では、仮想デバイスではない英字キーボードが接続されている間、QWERTY文字領域を隠します。候補・状態領域は残すため、物理キーだけで入力しながら候補、注釈、登録状態を確認できます。設定`hide_touch_keyboard_with_hardware`を無効にすると、物理キーボード接続中も文字領域を表示します。

接続、切断、デバイス情報変更、画面構成変更、入力セッション開始の各時点で表示を再評価します。物理キーの文字は従来どおりAndroidの`KeyEvent.getUnicodeChar`を使い、OSレイアウトの対応を保持します。画面QWERTYの固定配列を物理キーボードのJIS・US判定へ流用しません。

## 保護入力と接続制約

パスワード欄と`TYPE_NULL`ではSKKコアを起動せず、候補、登録、学習を行いません。タッチ操作は、セッション開始時に固定して捕捉した`InputConnection`だけへ適用し、接続がない、終了した、または失敗したセッションへ再送しません。通常文字と空白は直接`commitText`し、BackspaceとDeleteはコードポイント単位で削除します。カーソル移動は入力先の選択位置を推測して書き換えず、ネイティブのDPAD操作へ委ねます。Enterは`IME_FLAG_NO_ENTER_ACTION`を尊重して、入力先の通常の入力接続契約に従います。物理キーは既存の安全な配送契約に従います。

入力先の非同期編集が保留中でも、タッチ操作はこのセッション内の外部編集待機列で到着順に再生します。上限は64件です。辞書読込待ちの操作列は別の待機列で管理し、上限は1024件です。物理キーボードから来た通常の独立入力は、既存の安全契約に従って遅延した外部編集を無効化します。これは古い編集を別の状態へ適用しないための扱いです。

保護入力での変換、登録、候補操作は無効です。入力モード変更、補完、登録など、通常の文字入力・訂正・移動・完了に当たらない操作は直接発行しません。

## IME切り替え

タッチでは`IME`キー、物理キーボードでは修飾なしのCtrl+SpaceでAndroidの入力方法選択画面を開きます。Ctrl+Spaceはアプリへ渡すショートカットと衝突しますが、初回はIME切り替えを両方の入力手段から必ず利用できることを優先し、サービスの明示コマンドとして予約します。

引用入力が待機中の場合は引用を先に判定し、Ctrl+SpaceをIMEコマンドとして消費しません。パスワード欄と`TYPE_NULL`でもSKK状態へ入らず、IME選択だけを実行できます。キーリピート、Shift・Alt・Metaを伴う操作はIME切り替えとして扱いません。

## 検証範囲

JVM試験では、Shiftの一回性、記号面切替、候補絶対位置の確定、無効な候補位置、候補タップの参照同一性、保護入力のコードポイント編集・DPAD移動・Enter契約、外部編集待機列と辞書読込待ち操作列の到着順・上限を確認します。実機受入ではPixel 7とXiaomi Pad 8の縦横、文字倍率、QWERTYの全キー、登録と再帰登録、候補タップ、物理キーボード接続・切断、設定の両値、タッチとCtrl+SpaceのIME選択、保護入力、`TYPE_NULL`を確認します。

キー寸法、狭幅での収まり、大きな文字での読みやすさ、入力欄を隠さないこと、再帰登録階層の視認性は実端末で未確認です。自動試験の合格だけで視覚的な受入完了とはしません。
