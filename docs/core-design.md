# Kotlinコアの状態所有と接続契約

本書はコアと Android 接続層の状態・副作用の契約を定めます。[要件](requirements.md)、[互換性](compatibility.md)、[外部実装との比較](reference/browser-extension.md)を前提に、U01 と半角カナの標準操作を以下で具体化します。

## 境界と API

コアは独立した Kotlin/JVM モジュールとし、Android、画面、DB、コルーチンのスケジューラーに依存しません。入力欄の文字や `▽` の位置から状態を復元せず、読み・送り・残余・カーソル・候補・登録の親子を自身で所有します。Android は正規化した入力と辞書応答を渡し、返された表示と効果を実行します。

実装の入口は `BasicSkkEngine.dispatch(BasicSkkAction)` と `BasicSkkResult` です。キー処理はセッション内で直列に行い、入力先への確定と保存の効果を一度だけ適用します。表示はコアの状態から導出し、入力先用compositionとIME内の候補・登録表示を分けます。

| 所有者 | 責務 |
| --- | --- |
| コア | 入力モード、読み・送り・残余・カーソル、候補・登録状態、設定、保存・確定要求 |
| 辞書アダプター | 検索、由来・世代、保存、有限キャッシュ、読込要求 |
| Android接続層 | キー配送、入力接続、辞書ワーカーと待機操作、セッション失効、表示・外部編集 |

未キャッシュ検索では `DeferredDictionaryReadException` を使い、コアは操作前の状態へ戻します。`EditorSession` はワーカーで読込み、セッションと辞書操作のrevisionが有効な場合だけ同じ操作を再実行します。効果を適用する前の再実行であり、確定・保存済みの効果を再送しません。取消・入力欄変更等で古い読込と待機操作を失効させます。詳細は [ストレージとキャッシュ](dictionary-storage-cache-design.md) を参照します。

Android は各効果を元のセッションにだけ一度適用します。`commitText` と `finishComposingText` を別々の確定イベントとして扱いません。適用失敗や対象不明時は新しい入力欄へ再送せず、そのセッションを終了して通知します。入力先に既に表示した composition の終了方法は既存の接続仕様に従います。Android API の成功を越えた配送保証は主張しません。

通常候補の学習は `CommitText` の成功応答に結び付けます。確定要求に一意な番号を付け、対応する成功応答を一度受理した後にだけ保存要求を出します。確定拒否・古い応答・重複応答では学習しません。登録の明示的な保存は別の操作であり、保存成功後に入力先への反映が失敗しても辞書保存を取り消したとは表示しません。保存要求にも一意な番号を付け、失敗後の再試行による二重保存を防ぎます。

## 状態と内部編集

入力モードと、読み・abbrev・候補選択などの入力段階を分離します。登録スタック、削除確認、補完状態もコアが所有します。`Reading` は語幹、任意の送り開始子音と送り本文、ローマ字残余、編集位置、開始モードを持ちます。辞書の読みはかな表示モードに関係なくひらがなへ正規化し、abbrev の大小文字は保持します。

内部文字列は UTF-16 でも、カーソルを拡張書記素クラスタ境界に限定します。境界計算は純 JVM で試験できる部品へ分離し、結合濁点、サロゲート、ZWJ 絵文字を受入条件にします。ICUとUnicodeの採用版・コーパスは [coreの案内](../core/README.md) に記録します。単純な `Char` 削除やコードポイント単位だけでは N08 の合格としません。

U01 の編集操作は Left/Right、Home/End、BS/Delete とし、Emacs 編集オフでも利用できます。Home/End は内部の論理行の先頭／末尾です。見出し語は単一行です。移動時に残余があれば、現在位置で終端処理して内部文字列へ挿入してから移動します。入力先への確定はしません。BS は残余を一文字ずつ削除し、残余がなければカーソル直前のクラスタを削除します。Delete は残余を終端処理してから次のクラスタを削除します。

語幹と送りの境界は文字位置と別の属性です。左右移動は境界を越えられます。境界直前は語幹側、直後は送り側として識別し、挿入先を曖昧にしません。送りをすべて削除した場合は送り属性も解除します。語幹が空なら検索せず編集を継続します。送り内編集後も開始子音は保持し、別の送り開始子音に直すときは送り全体を削除して入力し直します。候補から取消した際は検索前の読み・残余・編集位置・送り境界へ復元します。

登録は `RegistrationFrame(returnState, readingKey, body, innerState)` のスタックとします。内側の確定出力は最上位フレームの `body` へ挿入し、最上位登録完了だけを入力先の `CommitText` にします。保存と確定は別の効果で、保存失敗を保存成功と表示しません。空 Enter、内側 Enter、C-g の段階的取消、保存済み子の保持は互換性 K09/K10/K18 に従います。登録の保存・取消・戻り先は [登録契約](registration-design.md) に従います。

## U01: Q・q・半角カナ・終端

C-q の標準操作は **次のキーの引用** です。半角カナ操作は残し、初期割当を空にします。利用する場合は設定から競合しないキーを割り当てます。引用は Android 接続層で現在表示中の本文を保持して未確定状態を終了し、次の修飾キー以外の物理キーを入力先へ渡します。コアの半角カナ操作とは分離します。

以下の表の「半角カナ操作」は、利用者が割り当てたキーで呼び出す意味操作です。DDSKK の固定コミット `e8bf68b27021c29781dbfa6a8ef7b770565bdb5b` のモード切替を参考にしていますが、C-q の初期割当は本製品の引用契約に従います。

DDSKK のカーソル位置までの領域変換をそのまま移さず、内部カーソル位置にかかわらず見出し語全体を文字種変換します。これは入力先の既存文字を取り込まない Android の採用仕様です。

| 状態 | q | Q | 半角カナ操作 |
| --- | --- | --- | --- |
| 通常かな | ひらがな↔カタカナ。半角カナからはひらがな | 空の見出し語を開始 | ひらがな／カタカナ→半角カナ、半角カナ→ひらがな |
| 見出し語 | 全体をひらがな↔カタカナに変換して確定。元が半角なら全角カタカナへ | 現在の読み全体を確定し、空の見出し語を開始 | 全体を半角カナに変換して確定 |
| 候補 | 候補を一度確定し、通常状態の q を実行 | 候補を一度確定し、空の見出し語を開始 | 候補を一度確定し、通常状態の半角カナ操作を実行 |
| abbrev | 文字 q を挿入 | 文字 Q を挿入 | 英数字の幅を切り替えて読み全体を確定 |
| 直接入力・全角英数 | そのモードの通常文字 | そのモードの通常文字 | 未割当として渡す |

見出し語の文字種確定後は開始モードへ戻ります。送りがある場合は語幹と送りを一度ずつ変換し、開始子音・マーカーは出力しません。登録中は同じ操作を内側状態に適用し、確定先は登録本文です。

終端処理は **切替前のモード** で行います。標準規則の残余 n はひらがなで `ん`、カタカナで `ン`、半角カナで `ﾝ`、終端出力のない k/ky はそのままです。Enter はその出力だけを確定しモードを維持し、C-j はその後ひらがなへ戻ります。q／半角カナ操作は残余を終端処理してから切替または全体の文字種変換を行います。Q は通常時の残余を終端確定してから空の見出し語を開始します。これらの残余処理も Android の明示的な選択です。

見出し語中の英数切替キー `l`／`L` は、終端できる保留 `n` などを確定し、未完成の保留を破棄して、読みを確定した後に半角／全角英数へ移ります。明示的に再割当されたキーと、途中の `zl`／`zL` の規則継続を優先します。標準規則の `xtu`／`xtsu` は `っ` を入力できます。保留中の重子音から得た `っ` は送り境界より前の語幹へ入れ、送りの読みを別に保ちます。候補の取消は検索前の読み・ローマ字残余・カーソル・送り境界へ戻します。

## 設定と入力先境界

パスワード欄と `TYPE_NULL` では通常の SKK コアを起動せず、候補・登録・学習を行いません。タッチ文字と空白はセッション開始時に固定した `InputConnection` へ直接確定し、削除はコードポイント単位、カーソル移動は入力先のネイティブ DPAD に委ねます。古い操作を新しい入力欄へ再送しません。物理キーも保護入力の配送規則に従います。保護欄でも IME の切替操作だけは利用できます。

辞書・外部編集の待機中は、後続の受理した入力を元のセッション内で順序どおり処理します。表示更新の通知だけを非同期編集の完了とみなさず、独立した入力・接続終了・操作失敗では旧編集を失効させます。辞書待機と外部編集の上限・失敗境界はそれぞれ[有限キャッシュ](dictionary-storage-cache-design.md)と[Emacs 編集](emacs-editing-design.md)を参照します。

ローマ字規則（出力・残余・終端出力）、キー割り当て、記号、候補表示方針を 入力セッション用の不変設定として注入します。Android の `onStartInput` で版を固定し、同じ入力セッションの候補巡回・再帰登録・未確定入力が空へ戻った後も変更しません。固定した入力接続へ途中から別の設定世代を混ぜないためです。候補のラベル、ページ幅、ラベルと候補 index の対応は候補集合の選択中ずっと固定し、幅変更は選択終了後の新しい候補一覧から反映します。標準値は単独2件・3候補目から一覧・最大7件・`asdfjkl` です。一覧中の Space は次ページ、x は前ページへ移動します。ページ件数は画面幅に加え画面高と文字サイズの上限を満たす値で固定します。設定の保存・移行は [カスタマイズ設計](customization-design.md) に従います。

設定適用前に状態ごとのキー競合を検証します。候補中の q/Q などの SKK コマンドと選択ラベルが重なる設定は、対象状態と両操作を表示して適用を拒否します。コマンドを別キーに割り当てて競合を解消することは可能です。ラベルが黙ってコマンドを置き換える規則にはしません。重複ラベルと選択キー不足も検証し、最後に正常適用した設定を保持します。

パスワード／TYPE_NULL は Android 側で通常コアを迂回します。学習禁止だけの通常欄では変換を継続し、コアと保存アダプターの両方で保存を禁止します。禁止への変更は進行中の設定版にかかわらず即時反映し、保存の公開直前にも現在のセッション方針を確認します。

内部編集は入力先の周辺文字に触れません。未確定のない入力先 Emacs 編集は別の外部編集要求とし、接続層が範囲を確認して実行します。詳細キーと単語境界は [編集設計](emacs-editing-design.md) に定義します。

## 契約を示す入力例

以下は状態と効果の期待値です。実行結果の報告ではありません。

| 操作・条件 | 観測する結果 |
| --- | --- |
| q、n、Enter | `ン` を一度確定、カタカナ維持、改行なし |
| 半角カナ操作、n、C-j | `ﾝ` を一度確定、ひらがなへ復帰 |
| k、Q | `k` を確定し空の見出し語開始、既存入力先を取り込まない |
| Nihon、Left、q | カーソルによらず `ニホン` 全体を確定、ひらがなへ復帰 |
| Nihon、Left、Left、a、Delete、SPC | `にあん` で検索。入力先の確定済み文字は変えない |
| KaKu、C-g、q | 読みへ戻り `カク` を一度確定。送り子音 k は出力しない |
| カスタム出力 `か゚`、内部 BS | 一クラスタを削除し、結合記号を残さない |
| 登録本文の `😀`／ZWJ 絵文字、内部 BS | 一クラスタ全体を削除。子の確定は入力先へ出さない |
| 検索後に取消または入力欄変更、遅延応答 | 表示・確定・保存の効果なし |
| 候補確定直前に学習禁止 | 確定は可能、辞書保存はなし |

## 非同期保存待ちの学習順位

辞書管理器は保存要求を受理した時点で、元の入力コンテキストと保存許可証に結び付く順位変更を保持します。同じ管理器の次の検索から適用するため、二本を確定してすぐ「にほん」を検索しても DB 保存完了を待たず二本を先頭にできます。対象は既存候補の並べ替えだけで、新しい辞書由来や削除用世代を作りません。数値変換は表示文字列でなく学習先テンプレートと読み・送り条件を照合します。

保存成功時は辞書の管理情報・キャッシュ世代の更新と待機項目の解除を同じ管理器ロック内で行います。保存失敗、元の許可証の失効、入力コンテキストの失効では待機中の順位を取り消します。復元後は再公開が失敗しても旧入力を失効させ、待機順位を破棄します。

## 表示記号と標準規則の継続

`▽`／`▼` はコアの本文へ含めず、既定オフの設定に応じて Android 接続層が表示へ付けます。本文読戻し未対応なら付けません。通常の確定はコアが返す本文だけを使い、外部カーソル移動・終了時は以前の表示全文が元の位置に一致するときだけ表示記号を削除し、現在の選択位置を補正します。一致を確認できないときはユーザー本文を推測で削除せず、表示記号が残る場合がある旨を通知します。

標準の z 系記号も、有効なローマ字継続をコマンド・送り開始より先に処理します。`zj → ↓`、`zk → ↑`、`zL → ⇒`、`z<SPACE> → 全角空白` を含みます。大文字規則の例外は標準と同一の `zL → ⇒` だけです。規則の途中だけに現れる記号は単独入力の開始文字とは扱わず、句読点設定を維持します。`fa/fi/fe/fo` も標準規則で扱います。
