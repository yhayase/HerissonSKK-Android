# Kotlin コアの状態所有とフェーズ 2 の設計

作成日: 2026-09-16。実装前の採用設計です。実装完了・DDSKK 実行との一致を示す文書ではありません。[要件](requirements.md)、[互換性](compatibility.md)、[ロードマップ](roadmap.md)、[ブラウザ版評価](reviews/browser-extension-20260916.md)を前提に、U01 と半角カナの標準操作を以下で具体化します。

## 境界と API

コアは独立した Kotlin/JVM モジュールとし、Android、画面、DB、コルーチンのスケジューラーに依存しません。入力欄の文字や `▽` の位置から状態を復元せず、読み・送り・残余・カーソル・候補・登録の親子を自身で所有します。Android は正規化した入力と辞書応答を渡し、返された表示と効果を実行します。

以下は契約の略記です。補助型・実装方法を固定する完成コードではありません。

```kotlin
interface SkkEngine {
    fun dispatch(action: Action): Transition
    val state: EngineState
}
data class Transition(
    val disposition: Disposition,
    val view: ViewState,
    val effects: List<Effect>,
)
// Action: KeyInput / LookupCompleted / LookupFailed / PolicyChanged / EndSession
// Effect: CommitText / Lookup / Persist / RequestEditorEdit / Notice
// Disposition: Consumed / PassThrough
```

`dispatch` はセッション内で直列に実行します。状態変更と返却効果を一組として確定し、効果を再実行するために同じキーを再投入しません。`ViewState` は状態から導出する完全なスナップショットで、入力先用 composition と IME 内の候補・登録表示を分けます。マーカーと注釈を `CommitText` に含めません。

| 所有者 | 所有するデータ・責務 |
| --- | --- |
| コア | 入力モード、現在の入力段階、内部バッファ、登録スタック、候補位置、設定版、検索要求番号 |
| 辞書アダプター | 検索・保存・世代公開、文字コード、永続化失敗。候補本文と注釈、送り条件、由来を構造として返します |
| Android 接続層 | `KeyEvent` の文字生成、AltGr、キー上下配送、入力欄識別、`InputConnection`、選択変更、UI、外部編集の可否 |

検索は `Lookup(sessionId, requestId, readingRevision, dictionaryGeneration, query)` とし、対応する応答だけ受理します。取消、編集、入力欄変更後の応答は状態・表示・保存を変更しません。検索中の通常キーは接続層の順序付きキューで待ち、取消・セッション終了は検索と待機キーを無効化できます。キューには上限を設け、超過時は読みを保持して検索待ちを終了し、追加キーを無言で失わずエラーを通知します。上限と待機終了後の再入力案内は非同期接続実装時に試験で固定します。失敗なら読みを保持して通知し、候補ゼロと検索失敗を区別します。

Android は各効果を元のセッションにだけ一度適用します。`commitText` と `finishComposingText` を別々の確定イベントとして扱いません。適用失敗や対象不明時は新しい入力欄へ再送せず、そのセッションを終了して通知します。入力先に既に表示した composition の終了方法は既存の接続仕様に従います。Android API の成功を越えた配送保証は主張しません。

通常候補の学習は `CommitText` の成功応答に結び付けます。確定要求に一意な番号を付け、対応する成功応答を一度受理した後にだけ保存要求を出します。確定拒否・古い応答・重複応答では学習しません。登録の明示的な保存は別の操作であり、保存成功後に入力先への反映が失敗しても辞書保存を取り消したとは表示しません。保存要求にも一意な番号を付け、失敗後の再試行による二重保存を防ぎます。

## 状態・編集・将来拡張

入力モードは `Hiragana / Katakana / HalfwidthKana / Direct / FullwidthLatin`、入力段階は `Idle / Reading / Abbrev / LookingUp / Selecting` として分離します。将来の登録・削除確認も段階に追加できるようにします。`Reading` は語幹、任意の送り開始子音と送り本文、ローマ字残余、編集位置、開始モードを持ちます。辞書の読みはかな表示モードに関係なくひらがなへ正規化し、abbrev の大小文字は保持します。

内部文字列は UTF-16 でも、カーソルを拡張書記素クラスタ境界に限定します。境界計算は純 JVM で試験できる部品へ分離し、結合濁点、サロゲート、ZWJ 絵文字を受入条件にします。実装ライブラリと Unicode 版は採用時に記録します。単純な `Char` 削除やコードポイント単位だけでは N08 の合格としません。

U01 の編集操作は Left/Right、Home/End、BS/Delete とし、Emacs 編集オフでも利用できます。Home/End は内部の論理行の先頭／末尾です。見出し語は単一行です。移動時に残余があれば、現在位置で終端処理して内部文字列へ挿入してから移動します。入力先への確定はしません。BS は残余を一文字ずつ削除し、残余がなければカーソル直前のクラスタを削除します。Delete は残余を終端処理してから次のクラスタを削除します。

語幹と送りの境界は文字位置と別の属性です。左右移動は境界を越えられます。境界直前は語幹側、直後は送り側として識別し、挿入先を曖昧にしません。送りをすべて削除した場合は送り属性も解除します。語幹が空なら検索せず編集を継続します。送り内編集後も開始子音は保持し、別の送り開始子音に直すときは送り全体を削除して入力し直します。候補から取消した際は検索前の読み・残余・編集位置へ復元します。

登録は `RegistrationFrame(returnState, readingKey, body, innerState)` のスタックとします。内側の確定出力は最上位フレームの `body` へ挿入し、最上位登録完了だけを入力先の `CommitText` にします。保存と確定は別の効果で、保存失敗を保存成功と表示しません。空 Enter、内側 Enter、C-g の段階的取消、保存済み子の保持は互換性 K09/K10/K18 に従います。フェーズ 2 では未登録時に読みを保持して通知し、登録機能が利用可能とは表示しません。

## U01: Q・q・半角カナ・終端

標準半角カナキーを **C-q** とします。DDSKK の固定コミット `e8bf68b27021c29781dbfa6a8ef7b770565bdb5b` を `git show` で読み、`skk.el` の `skk-setup-j-mode-map-options` と `skk-toggle-characters`、`skk-jisx0201.el` の `skk-toggle-katakana`、`skk-vars.el` の q/Q 規則を確認しました。DDSKK は半角機能を既定で無効にしていますが、本製品では F01 の必須モードとして有効にします。ソース・テーブルは複製していません。

DDSKK のカーソル位置までの領域変換をそのまま移さず、内部カーソル位置にかかわらず見出し語全体を文字種変換します。これは入力先の既存文字を取り込まない Android の採用仕様です。

| 状態 | q | Q | C-q |
| --- | --- | --- | --- |
| 通常かな | ひらがな↔カタカナ。半角カナからはひらがな | 空の見出し語を開始 | ひらがな／カタカナ→半角カナ、半角カナ→ひらがな |
| 見出し語 | 全体をひらがな↔カタカナに変換して確定。元が半角なら全角カタカナへ | 現在の読み全体を確定し、空の見出し語を開始 | 全体を半角カナに変換して確定 |
| 候補 | 候補を一度確定し、通常状態の q を実行 | 候補を一度確定し、空の見出し語を開始 | 候補を一度確定し、通常状態の C-q を実行 |
| abbrev | 文字 q を挿入 | 文字 Q を挿入 | 英数字の幅を切り替えて読み全体を確定 |
| 直接入力・全角英数 | そのモードの通常文字 | そのモードの通常文字 | 未割当として渡す |

見出し語の文字種確定後は開始モードへ戻ります。送りがある場合は語幹と送りを一度ずつ変換し、開始子音・マーカーは出力しません。登録中は同じ操作を内側状態に適用し、確定先は登録本文です。

終端処理は **切替前のモード** で行います。標準規則の残余 n はひらがなで `ん`、カタカナで `ン`、半角カナで `ﾝ`、終端出力のない k/ky はそのままです。Enter はその出力だけを確定しモードを維持し、C-j はその後ひらがなへ戻ります。q/C-q は残余を終端処理してから切替または全体の文字種変換を行います。Q は通常時の残余を終端確定してから空の見出し語を開始します。これらの残余処理も Android の明示的な選択です。

## 設定と入力先境界

ローマ字規則（出力・残余・終端出力）、キー割り当て、記号、候補表示方針を `ConfigSnapshot` として注入します。Android の `onStartInput` で版を固定し、同じ入力セッションの候補巡回・再帰登録・未確定入力が空へ戻った後も変更しません。固定した入力接続へ途中から別の設定世代を混ぜないためです。候補のラベル、ページ幅、ラベルと候補 index の対応は候補集合の選択中ずっと固定し、幅変更は選択終了後の新しい候補一覧から反映します。標準値は単独3件・一覧7件・`asdfjkl` です。設定 UI や AZIK を先に実装する必要はありません。

設定適用前に状態ごとのキー競合を検証します。候補中の q/Q などの SKK コマンドと選択ラベルが重なる設定は、対象状態と両操作を表示して適用を拒否します。コマンドを別キーに割り当てて競合を解消することは可能です。ラベルが黙ってコマンドを置き換える規則にはしません。重複ラベルと選択キー不足も検証し、最後に正常適用した設定を保持します。

パスワード／TYPE_NULL は Android 側で通常コアを迂回します。学習禁止だけの通常欄では変換を継続し、コアと保存アダプターの両方で保存を禁止します。禁止への変更は進行中の設定版にかかわらず即時反映し、保存の公開直前にも現在のセッション方針を確認します。

内部編集は入力先の周辺文字に触れません。未確定のない入力先 Emacs 編集は別の `RequestEditorEdit` とし、接続層が範囲を確認して実行します。この機能の詳細キーや単語境界は U02 の後続仕様であり、フェーズ 2 の前提にしません。

## 実装の受入例

以下は追加するテストの期待値です。実行済みの結果ではありません。

| 操作・条件 | 観測する結果 |
| --- | --- |
| q、n、Enter | `ン` を一度確定、カタカナ維持、改行なし |
| C-q、n、C-j | `ﾝ` を一度確定、ひらがなへ復帰 |
| k、Q | `k` を確定し空の見出し語開始、既存入力先を取り込まない |
| Nihon、Left、q | カーソルによらず `ニホン` 全体を確定、ひらがなへ復帰 |
| Nihon、Left、Left、a、Delete、SPC | `にあん` で検索。入力先の確定済み文字は変えない |
| KaKu、C-g、q | 読みへ戻り `カク` を一度確定。送り子音 k は出力しない |
| カスタム出力 `か゚`、内部 BS | 一クラスタを削除し、結合記号を残さない |
| 登録本文の `😀`／ZWJ 絵文字、内部 BS | 一クラスタ全体を削除。子の確定は入力先へ出さない |
| 検索後に取消または入力欄変更、遅延応答 | 表示・確定・保存の効果なし |
| 候補確定直前に学習禁止 | 確定は可能、辞書保存はなし |

最小実装は、(1) 純 JVM モジュール・データ契約・内部バッファ、(2) 独立記述の最小ローマ字規則とモード／終端、(3) テスト辞書による読み・送り・候補・取消、(4) Android 接続と候補表示、の順です。途中編集の部品・状態を (1) で作り、登録・設定 UI・永続辞書は各フェーズへ分けます。完全な標準テーブルや辞書を取り込む前には出典とライセンスを確認し、最小テーブルの合格を K01〜K08 全体の完成と表示しません。
